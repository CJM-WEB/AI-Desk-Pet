# 工作台最终修复报告：统一分隔器键盘方向

## 复审核验与 RED

右侧属性栏控制的是 `rightWidth`，分隔线向右移动应让该值减小。旧实现只让指针使用反向系数，键盘仍固定把 `ArrowRight` 映射为数值增加。

新增独立 DOM 回归后，16 项中仅该用例失败：`ArrowRight` 预期 `rightWidth=292`，实际为 308；其余 15 项通过。保存失败重挂载用例在实现修改前即通过，证明复审 M1 是规格文字与既有安全行为不一致，而不是需要新增失败标记或修改 SettingsStore。

## 最小实现

- 将仅描述指针的 `pointerDirection` 收敛为统一的 `valueDirection`，指针与键盘共用“空间移动方向 → 受控尺寸增减”的映射。
- 右侧栏 `valueDirection=-1`：`ArrowRight` 减 8、`ArrowLeft` 增 8，Shift 步长为 32；指针向右拖动仍减少右栏宽度。
- 修正过预算右栏回归中固化旧错误方向的键位。
- 不修改 SettingsStore。规格正式更正为：保存失败保留当前窗口布局；下次启动恢复上一次成功持久化值，没有成功值时使用默认值。

- 布局、preload、工作台组件联合定向测试：76/76 通过。
- Desktop typecheck：退出 0。

- 目标真实 Electron E2E：1/1 通过；验证右侧 `ArrowRight` 与 Shift 32px 的尺寸和几何方向，并保留鼠标拖动、重开恢复与窄屏最小尺寸覆盖。
- 未运行完整 `verify:characters`，符合本轮范围受限验证要求。

## E2E 校准记录

首次 E2E 扩展已确认 `ArrowRight` 正确将右栏约 324px 降至 316px，但测试随后要求在过预算布局中原位反向恢复。释放的共享预算已被左栏占用，使右栏当时的 `max` 等于当前值，该前提不成立。最终由 DOM 在未超预算环境覆盖双向键盘，E2E 保留最能捕获本缺陷的向右和 Shift 几何断言。第二次失败是后续鼠标断言仍引用键盘操作前的左栏基准；改为交互前即时几何基准后通过，业务值符合预期。

## 人工边界

不同 Windows DPI、长期反复键盘与鼠标交替操作的主观手感仍待用户人工确认；自动化只证明数值、方向、持久化与响应式契约。
