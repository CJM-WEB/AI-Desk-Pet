## 3. 文件真实状态和事务时序证据

自动 E2E 用真实临时文件观察源路径，并用隔离适配器目录的 `.attempt-*` 记录 Main 端写入尝试：

| 时点 | 自动观察结果 |
| --- | --- |
| 确认卡出现、尚未确认 | 源文件存在；确认卡只显示相对文件名，并说明“将移入 Windows 回收站，可从回收站恢复；执行前还会再次检查”。 |
| 点击确认、搬运动作已 `started`、尚未到提交帧 | 源文件仍存在；隔离适配器没有 `.attempt-*`，即没有回收站写入尝试。 |
| 注入伪造令牌、错误动作 ID 和错误帧 ID | Main 全部拒绝；源文件仍存在；写入尝试仍为 0。 |
| 匹配的精确提交帧到达后 | 源文件离开原路径；隔离适配器恰有 `.attempt-1`；Agent 显示成功总结；角色进入成功表现。 |
| 已成功后重复上报同一里程碑 | `.attempt-*` 仍只有一个，没有重复执行。 |

该证据证明“确认前无副作用、提交帧前无副作用、提交后最多执行一次”。它没有证明文件已进入真实 Windows 回收站，也没有证明可从资源管理器恢复；后两项必须人工验收。

## 4. 成功、失败和中断场景

| 场景 | 自动证据与结果 |
| --- | --- |
| 成功 | 文件工具对普通文件和目录分别调用可注入回收站端口一次，目标离开原路径；真实 Electron E2E 的成功文件只在匹配提交帧后离开原路径。 |
| 回收站拒绝或失败 | 文件工具先把端口异常收敛为脱敏的 `RECYCLE_BIN_FAILED`，Agent 对外事件再统一为 `FILE_TASK_EXECUTION_FAILED`；原文件内容保持不变；同一动作再次执行得到 `ACTION_EXPIRED`。E2E 强制适配器失败后，文件保留且角色进入失败表现。 |
| 目标变化 | 预览后把原实体移走并在同路径创建新文件，执行返回 `ENTRY_CHANGED`，端口调用为 0，新文件内容保持不变。目标消失返回 `ENTRY_NOT_FOUND`，动作同时被消费。 |
| 动画失败、中断或超时 | 协调器在提交前收到 `completed`、`interrupted`、`failed`、`cancelled` 或启动/提交超时，均取消事务且执行次数为 0。真实 E2E 的拖拽中断保留源文件。 |
| 角色切换 | Main 撤销旧搬运授权；旧角色的真实令牌随后提交仍被拒绝，源文件保持不变，写入尝试数不增加。 |
| 提交后动画中断 | 不伪造回滚；已开始的系统执行继续以其真实成功或失败结果收敛。 |

## 5. 提交帧、降级和幂等

- 精确提交帧：官方默认角色的搬运表现使用稳定帧 ID；协调器要求播放令牌、动作 ID 和提交帧 ID 三者匹配，精确提交只执行一次。
- 无标记降级：V1 转换只映射 `carry` 语义，不伪造提交帧；V2 搬运表现没有标记时，Main 授权明确返回 `commitFrameId: null`。此时只有匹配的 `started` 可作为合成提交点，提交仍最多一次。该路径是受控兼容降级，不具备精确帧时序。
- 重复和旧令牌：重复 `started`、重复提交帧、伪造令牌、错误动作、错误帧、上一事务令牌及角色切换后的旧令牌均被拒绝；活动事务也拒绝并发 `begin`。
- Renderer 终态：播放器首次进入提交帧只上报一次；新令牌中断旧令牌，旧 revision 和重复事件不会恢复旧播放。

## 6. 权限与日志脱敏

- 回收站系统调用只位于 Main 注入的端口；文件工具只持有平台无关端口，Renderer、Agent 和角色包不能直接调用 Windows 回收站。
- 文件工具公开动作只包含相对路径，不包含授权根绝对路径；私有动作是一次性的，成功、失败和伪造副本都不能重放。
- 自动安全测试验证拒绝授权根本身、上级目录、Windows 绝对路径、UNC、符号链接和 Junction。
- E2E 捕获边界验证日志会清除 API Key、`Authorization` Header 和授权根绝对路径，包括跨输出块拆分的敏感值；回收站闭环还验证成功、角色切换、拖拽中断和失败四条唯一正文哨兵均未进入捕获日志。
- 结构化审计测试验证不记录正文和绝对路径；失败结果只暴露稳定错误码或脱敏事实，不透传底层错误中的完整路径或文件内容。
