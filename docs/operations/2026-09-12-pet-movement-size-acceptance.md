# 桌宠单屏移动尺寸回归验收

日期：2026-09-12。环境：Windows、Electron 43.5.0、Node.js 24.18.0，当前单屏 150% DPI；使用隔离窗口与临时用户数据。依据[修复计划](../superpowers/plans/2026-09-12-pet-movement-size-fix.md)、[固定尺寸规格](../superpowers/specs/2026-09-01-pet-startup-motion-regression-design.md)及用户最新“当前只考虑单屏”的范围限定。

后续用户录屏确认仍有位置回跳，诊断与修复见[移动回跳验收](2026-09-12-pet-motion-jitter-acceptance.md)。本记录仅证明该轮尺寸问题修复，不证明当时的位置合成已连续。

## 根因与最小改动

Electron 43.5.0 的 `setPosition` 内部使用 `GetSize()` 后调用 `SetBounds()`，高 DPI 换算后的尺寸被当作下一次输入，导致不可调整大小的桌宠窗口仍随移动递增。其实现见[固定版本源码](https://github.com/electron/electron/blob/v43.5.0/shell/browser/native_window.cc#L257)。动作循环时的几何布局提交 180×220，又将已经膨胀的窗口缩回，形成周期性抽动。

`window-manager.ts` 新增唯一 `setPetWindowPosition`，一次原子提交目标坐标及配置中的 180×220，不读取系统实际宽高。Main 自动运动和旧位置恢复接入此入口，拖拽与几何布局复用它并删除重复写法。一次移动只有一次原生提交，没有先扩大再缩小的第二次操作，没有新增监听修复或重试。

Renderer、Pixi、帧间锚点、素材和三档语义未改。审查确认 Renderer 的运动帧只做平移，Pixi 换帧不直接重算缩放；这两处不是此次尺寸扩大源头，未顺带重构。几何事务的预登记和失败撤销仍保留。未新增依赖或 IPC，未执行 Git 写操作。

## RED 与 GREEN

- 隐藏空白窗口使用正式桌宠窗口参数，单屏连续 `setPosition` 80 次，尺寸从约 181×221 增长到 260×294；去掉 min/max 约束仍然增长。无模型、角色动画及素材也能复现，证明错误在窗口移动边界。
- 修复前正式三档运动 E2E 新增 resize 与每个绘制帧尺寸采样，准确失败：客户区出现 58 种尺寸，包含 184×238、194×236 等。停止后恢复正常不能通过此断言。
- 使用正式新定位函数在当前单屏连续移动 240 次，实际客户区每次均为 180×220。原生 `resize` 事件仍可能发出，`getBounds` 仍有 180/181 DIP 的取整差异；这些结果不再被回灌为新尺寸。
- 修复后正式三档运动 E2E **1/1 通过**。审查补强 Canvas 必须存在且宽高为正，并将检查扩展到静止与间歇阶段后，最后一次独立运行再次 **1/1 通过**（约 1.1 分钟）：从第一次实际移动起共 **10038** 个采样，客户区只有 **180×220**，Canvas 只有 **156×192**。原有实际位移、到达接续、静止零位移、间歇等待及无播放令牌报错断言保持。
- 中间一次 E2E 与全量测试并行时在 `connect_over_cdp` 阶段超时，未进入行为验证；未修改超时或断言。全量检查结束后独立重跑得到上述通过结果。
- 五个定向文件 **130/130 通过**，覆盖窗口定位、拖拽、几何 FIFO 与运动连续性。桌面类型检查、生产构建及 preload/生产边界检查通过。

## 全量门禁与边界

`pnpm.cmd verify:desktop` 实际运行到单元门禁失败：全仓类型检查通过、Core **108 通过/1 跳过**，随后单元 **3015 通过/40 失败**。与已有失败记录逐项比较，38 项名称一致；额外两项为角色包和 Store 的 5 秒超时，单独重跑 **2/2 通过**（837ms、425ms）。没有更改这两项测试上限，也未将定向结果当作全量通过。

随后 `pnpm.cmd verify:characters` 的 Runtime **237/237**、Assets **109/109** 与桌面类型检查通过，桌面单元 **2512 通过/38 失败**，失败均为上述旧基线项；因此两条全量门禁均不能标记通过。另行执行 `pnpm.cmd test:security` **16/16**、`pnpm.cmd test:integration` **72/72**，均通过。独立审查确认无遗漏桌宠定位入口，`git diff --check` 通过。

跨屏行为不在本次范围；真实用户桌面上的最终观感待用户人工确认。源码重建不等于既有桌宠进程已经加载新实现，重新启动后使用此次修复。没有将自动化尺寸证据扩大为所有动画观感均已人工通过。

原始观察、原生对照与门禁输出保存在工作树忽略目录 `.superpowers/` 的 `motion-size-*`、`movement-size-*` 文件中。旧的[行为连续性验收](2026-09-12-character-behavior-continuity-acceptance.md)只证明当时的位移和动作接续；本次新增全程尺寸断言后才证明本轮尺寸修复。
