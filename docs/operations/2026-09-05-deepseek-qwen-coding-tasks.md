## 真实模型的早期组件证据

内置 Qwen 与已配置 DeepSeek 都曾通过原 Core 的单文件自然读取探针：模型事先不知道的随机标记由真实 read 返回，并进入最终正文；各自为一次 read 调用。Qwen 该次约 1,367 毫秒，DeepSeek 约 1,896 毫秒，仅是单次观察。

此证据尚不覆盖正式授权卡、界面显示、编程闭环或稳定成功率。早期 DeepSeek 探针的 `thinking` 普通请求覆盖被原 transport 拒绝，成功读取使用未指定该字段的默认策略；不能记为已验证关闭思考。正式协议扩展完成后必须重新运行真实 DeepSeek 验收。

## 正式桌面入口的自动化结果

Task 3B 将正式 Main 接到 `ConversationCoordinator → CapabilityTaskAdapter → CodingTaskService → createCodingSession`。当前正式构建只有新任务执行链；旧专属源码仍等待替换验收后按用户要求批准删除。普通聊天与角色保留自己的链路。

正式组合的真实 HTTP／Core 测试从自然读取请求开始：范围确认前没有 Core 请求，确认及时返回，原 read 读取随机正文并回注模型，最终消息含实际内容，关闭完成后发布终态。具体许可、取消／reset清理屏障、有限历史接纳、Renderer卡片消费者和pet只接收phase均有定向验证；这不是实际窗口观察。

## 正式链的真实模型运行与修复

Task 4A 迁移了共用验收驱动。两款模型都从正式 Conversation 入口开始，经真实范围确认进入原 Core；最终正文必须包含仅存在隔离文件中的随机答案。修复场景检查实际测试退出码先为 1、后为 0，另外验证修复函数和测试文件未被替换；取消场景等待实际 PID／心跳，再从正式入口取消并检查进程退出及心跳停止。单场景选择只能输出 `partial`，不能标为整套通过。

真实运行暴露并修复了三个问题：可选表现字段格式错误连带丢弃合法任务建议；聊天提示未正确覆盖本地文件内容问答；Windows helper 正常退出先于独立管道结算时被误报为清理失败。分别有先失败后通过的回归。任务建议仍独立通过严格 Schema 和 Main 授权；helper 仍需正常退出和零存活进程两项证据，不降低清理屏障。

2026-09-06 另行只读对照了固定上游的正式 V1 DeepSeek 请求、消息关联和拒绝链，没有发现新增的确定协议或结果回注缺陷。V1 裸拒绝默认停止，带反馈拒绝或相应配置则可继续；本产品只拒绝对应操作并允许独立授权工作继续，属于已确认的适配。V1 的 `packages/opencode/src/session/processor.ts` 在连续三次工具名和输入完全相同时请求 `doom_loop` 许可，当前 V2 没有该检测。已有脱敏记录不足以确认各次重复是否完全相同；这项成熟参考不能被写成已实现，也不能证明能阻止换工具或命令实现相同被拒效果。此差异保留在后续审查中，不为参数表面一致而修改已通过的 DeepSeek 协议。

实际命令：`node apps/desktop/scripts/run-local-model-acceptance.mjs --model deepseek --profile <现有配置标识> --user-data <开发数据目录>`；Qwen 使用 `node apps/desktop/scripts/run-local-model-acceptance.mjs --backend vulkan`。后续拒绝单项在对应命令追加 `--scenario reject`。DeepSeek 在私有设置副本中使用原凭据回调，源设置散列前后相同；Qwen 中文聊天、中止恢复、零云调用及私有路由恢复通过。

修复后的 Windows Job 测试在 Electron 下 20 项通过；Desktop 定向测试合计 138 项通过，各次运行范围与失败修正分别保留。Core 与 Desktop 类型检查、最新桌面构建通过，既有构建警告未掩盖。完整标准安全／集成／UI 门禁仍属于后续步骤。

2026-09-06 的独立审查发现验收脚本仅给模型函数的定义阶段设置 VM timeout，宿主随后调用额外输入可能死循环并阻止清理。有界子进程先复现“原输入通过、额外输入卡住、清理未执行”；第 1 轮修复将同步形状检查、属性读取和调用放入同一次有期限的 VM，只返回布尔结果。额外输入和 getter 的同步死循环均报告超时并触发原验收生命周期关闭；该轮验收脚本 21 项测试、Desktop 类型检查通过。复审随后复现返回正确值后排入无限微任务仍会绕过期限。第 2 轮使用 VM 原生 `afterEvaluate` 选项把微任务纳入同一 1000ms 期限，三种循环均超时且完成原生命周期关闭；验收脚本 21 项和 Desktop 类型检查通过，独立复审确认原重要发现关闭、无新增阻断。组合测试增加第三次超时及真实 bundle 冷启动后，测试子进程的防挂期限由 5 秒改为 8 秒，生产 VM 期限未扩大。两轮均未重新调用真实模型。

曾有一次真实 DeepSeek 连续拒绝后 `close` 失败，原因没有取得，不能归因于已复现的 helper 顺序问题；当次 `cleanup=false` 保留。其临时配置和项目副本现已核对精确路径、无链接且无关联进程后清理。两次早期递归清理和一次私有诊断复合清理曾被自动审批拒绝；后续缩小为经核对的叶子文件及空目录操作完成清理，未关闭或绕过审批。未在报告保存 API Key、文件正文或进程输出。

## 桌宠与网站隔离

`apps/website`、`apps/cloudbase-api`、`apps/package-scanner` 的业务、配置与运行入口未修改。共享锁文件曾因依赖重算带动既有网站链记录变化，已恢复，并单独核对六个相关 importer 及其 317 个 package／snapshot，与 Git 基线一致。后续依赖操作仍须重查该图，不能仅以网站源码无改动认定隔离完成。
