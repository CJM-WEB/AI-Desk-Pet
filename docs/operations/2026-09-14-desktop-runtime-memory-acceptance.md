日期：2026-09-14。环境：Windows、现有 worktree，基准提交 `8fb39684224042d347bdff1277462b365f94343f`。用户批准在全部既有效果和核心功能不变的前提下优化资源。本次没有执行 Git 写操作。

后续真实硬件 GPU、开发版及打开过设置／工作室后的内存测量见[日常使用验收](2026-09-14-desktop-steady-memory-acceptance.md)。本记录仅保留启动优化阶段及软件栅格化基准，不作为后续 500 MB 目标的完成证明。

## 实际改动

- 启动只创建宠物、聊天、气泡三个必要窗口；设置与角色工作室首次使用时创建，之后保持原隐藏、重开、未提交内容和工作室保存握手。
- 五个视图按需加载 JavaScript。入口继续按聊天、工作室、全局 CSS 的原顺序静态加载全部样式，没有更改 CSS 属性、动画、图集、分辨率或帧率。
- 复用既有加载事务，并发首次打开只创建一个候选；失败可重试，已销毁候选不能迟到发布。显示前等待自有页面的首个视图 DOM 提交，10 秒未就绪按加载失败处理。
- 模型调用、流式正文、会话保存、授权判定、文件执行、角色行为代码和模型启停策略均未修改。官网、CloudBase、扫描器与共享协议没有改动，没有新增依赖。

适用[规格](../superpowers/specs/2026-09-14-desktop-runtime-memory-design.md)与[计划](../superpowers/plans/2026-09-14-desktop-runtime-memory.md)。

## 内存对照方法

在修改生产代码前运行固定构建，随后使用相同 `tests/fixtures/electron-app.ts#createElectronAppFixture`、固定角色、独立临时用户目录及采样脚本复测。关闭本地模型，不连接真实 Provider，不读取真实密钥或聊天正文。启动后等待 5 秒，采集三次，每次相隔 5 秒；进程取样包括该夹具的 Main 及后代。

指标为 `Win32_PerfFormattedData_PerfProc_Process.WorkingSetPrivate`，按进程汇总私有工作集；不相加页面共享的 JavaScript 堆读数。测试启动含 `--disable-gpu --no-sandbox`，启用软件栅格化，因此本结果不等同于用户 `pnpm dev` 或正式硬件 GPU 环境。单次三点采样也不构成长时间泄漏测试。

原始记录与脚本位于本机忽略目录 `.superpowers/sdd/2026-09-14-desktop-runtime-memory/`，分别为 `baseline-idle.json`、`after-final-idle.json` 和 `desktop-runtime-memory-probe.ts`。复测命令：

```powershell
node_modules/.bin/tsx.cmd .superpowers/sdd/2026-09-14-desktop-runtime-memory/desktop-runtime-memory-probe.ts --label=after-final
```

最终版本三次采样如下，单位 MiB：

| 版本／样本 | Main | GPU | Renderer 合计 | 其他 | 总私有工作集 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 优化前 1 | 225.742 | 96.680 | 416.301 | 7.629 | 746.352 |
| 优化前 2 | 232.926 | 89.152 | 293.148 | 7.633 | 622.859 |
| 优化前 3 | 243.398 | 88.281 | 298.304 | 7.633 | 637.616 |
| 最终版本 1 | 141.836 | 73.352 | 156.953 | 7.387 | 379.528 |
| 最终版本 2 | 142.957 | 73.586 | 162.071 | 7.387 | 386.001 |
| 最终版本 3 | 148.277 | 73.543 | 168.055 | 7.387 | 397.262 |

总私有工作集中位数 **637.616 → 386.001 MiB**，降低 **251.615 MiB（39.46%）**。所有优化前样本包含五个页面，最终版本均为三个必要页面。优化前首个样本明显高于后两次，因此保留全部原始值并使用中位数，不以最高值计算收益。这组结果不能用于宣称用户约 800 MiB 的开发环境必然降到 386 MiB。

## 未通过和未覆盖

`pnpm.cmd verify:desktop` 在全量单元阶段停止：初次 3344 项通过、42 项失败。随后按失败原因复核：

- 本次新增测试的工作目录路径和 E2E 入口清单已修正，并在最终 116 项定向测试中通过。
- 35 项角色几何、位置、运动 IPC、动作编辑测试可独立复现：测试使用 V2 或旧动作协议，生产已采用 V3 或现行字段。另两项角色导入测试期待播放投影包含顶层名称，与当前播放投影契约不符。相关源码、测试和直接依赖相对基准提交无改动，定向测试也不经过本轮 Main 启动与 App 懒加载。没有擅自改角色功能或放宽协议来让旧测试通过。
- 构建依赖过滤和两个角色包转换测试在全量运行中超时，独立复测通过；没有据此修改超时门槛或声称完整单元门禁通过。
- 完整 E2E 使用 `pnpm.cmd exec playwright test --config tests/playwright.config.ts --max-failures=3` 有界执行：三个 `character-event-bindings.spec.ts` 场景分别在 85/80/80 秒超时，达到上限停止，94 项未运行。没有固定旧构建对照证明这三个超时的原因，因此保留为未通过，不归因为已经证明的旧问题。独立安全、集成与上表目标界面验证不代表整个桌面门禁通过。

硬件 GPU 的真实开发版内存、长时间运行、手动托盘点击、全部显示器/DPI 组合和安装卸载属于待用户人工确认。关闭已使用的设置或工作室仍保留其状态和相应内存，这是保持原交互的有意边界。本轮不使用强制 GC 或工作集裁剪，也不承诺每个环境固定下降同样的 MiB。
