# 内容审核与应急处置手册

本手册供唯一管理员处理 AI Pet 共享资源包、反馈和建议。普通投稿完全匿名；管理员邮箱、审核证据、状态令牌和存储地址不得公开。

## 1. 审核原则

- 只允许与 AI Pet 产品直接相关的内容。
- 政治内容、脏话、色情、暴力、违法、广告、隐私泄露、恶意文件、侵权和非 AI Pet 内容不得公开。
- 所有投稿先系统审核，再管理员审核。系统通过不等于自动发布。
- 文本、图片、JSON、ZIP 或外部审核任一必要检查失败时均保持隐藏，不得按通过降级。
- `manual_review_pending` 与 `auto_rejected` 的共享包在批准前都必须具有当前有效的技术扫描通过证据；反馈与建议不依赖角色包 Scanner。
- 当前有效证据必须同时表明 `package_scan`、`isolated-scanner`、`Pass`，并与当前投稿 ID、包对象键、实际包大小、状态版本和 `CHARACTER_PACKAGE_SCAN_PASSED` 结果码精确绑定。
- 缺少、陈旧或字段不完整的证据，以及 Scanner 不可用、超时或失败时，批准必须保持禁用；不得通过“转人工”改变该门禁。

### 1.1 本地关键词相关性信号

- 强产品词包括 AI Pet、AI桌宠、桌宠、桌面宠物和 desktop pet，命中后给出相关性通过建议。
- 资源对象、产品功能、问题与建议采用跨组组合判断；单个弱词不能自动通过。
- 零命中、弱命中或组合不足统一转人工，不代表内容已经违规；规则异常记录稳定错误码 `KEYWORD_RELEVANCE_RULE_ERROR`、触发告警并进入人工队列。
- 关键词审核记录提供方为 `local-keyword`，规则版本为 `keyword-relevance-2026-08-01`。
- 关键词层绝不自动驳回，管理员仍需结合原文、TMS/IMS、OCR 和文件扫描结果作出最终决定。

## 2. 每日队列检查

1. 登录 `/admin`，确认使用已预注册的唯一管理员邮箱 OTP。
2. 依次查看“待我审核”“自动驳回”“已发布”“隔离区”和“审计记录”。
3. 先处理高风险和投诉举报记录，再处理普通队列；隔离区到期清理由定时任务执行并通过告警跟踪。
4. 每次操作前刷新详情；界面使用状态版本号与幂等键，出现 409 时重新加载，不重复提交旧操作。

## 3. 系统通过后的人工审核

对 `manual_review_pending` 记录逐项核对：

- 标题、正文、封面 OCR、JSON 可展示字段与 AI Pet 的直接相关性；
- TMS/IMS 与自定义规则的标签、分数和有限证据；
- 共享包文件清单、MIME/签名/路径/大小、ClamAV、图片解码与内容安全结果，以及与当前投稿和状态版本精确绑定的技术扫描通过证据；
- 版权、第三方权利、广告、联系方式和隐私泄露风险。

共享包只有在上述当前有效证据完整时才能填写理由并执行“批准发布”；普通反馈与建议沿用既有人工审核条件。存在违规、权利风险或无法接受的不确定性时填写理由并“驳回”。管理员理由不得包含密钥、内部 URL、管理员身份或不必要的敏感原文。

## 4. 自动驳回与转人工

`auto_rejected` 表示系统发现明确违规。管理员应检查命中规则与证据：

- 判断正确：维持自动驳回，等待三天隔离清理；
- 疑似误判且需要继续判断：填写理由后执行“转人工”，进入 `manual_review_pending`；
- 共享包只有当前有效技术扫描通过且内容复核确认无违规时，才能纠正机器误判并批准；
- Scanner 不可用、技术扫描失败、未完成、超时、恶意文件命中、证据陈旧或字段缺失时，批准必须保持禁用。

转人工只改变队列归属，不补全技术证据、不放宽共享包批准规则，也不会直接公开。

## 5. 管理员驳回

人工审核不通过时选择“驳回”，理由应对应具体规则，例如“与 AI Pet 无关”“包含政治内容”“存在版权授权疑点”或“含联系方式广告”。驳回后正文和文件立即保持私有并进入三天隔离期；不要在审计理由中复制完整违规文本。

## 6. 已发布内容删除

收到有效投诉、发现漏审或出现紧急风险时：

1. 打开“已发布”，确认目标 ID 与公开页面一致；
2. 填写原因并执行“删除”；
3. 立即检查公开社区或反馈列表中已消失，下载接口不再签发地址；
4. 到“隔离区”确认状态为 `deleted_quarantined`，保留原状态以便三天内恢复；
5. 在审计记录中确认操作、前后状态、理由和时间存在。

## 7. 三天内恢复

仅在确认误删、投诉撤回且内容重新满足规则时恢复。恢复前重新检查最新系统证据与文件状态，填写恢复理由并执行“恢复”。恢复应回到删除前状态：原为已发布则重新公开；原为未发布则不得因恢复直接公开。恢复后再次验证公开可见性或队列归属。

## 8. 三天后清理

`ai-pet-cleanup` 定时处理到期记录。清理后状态为 `purged`，封面、ZIP、正文及可识别内容永久删除，只保留投稿 ID、内容类型、状态时间、规则编号、风险类别和管理员操作摘要等最小审计信息。永久清理不可由管理员页面恢复。每天检查清理失败告警，不得通过延长公开可见性解决失败。

## 9. 审计记录

每个管理员写操作必须具有：管理员会话与白名单校验、目标投稿、操作前后状态、理由、幂等键、版本号和时间。HTTP 响应中的请求 ID 用于排查当次请求，但当前不写入管理员审计记录。审计记录不可在普通管理员页面修改；不得保存完整已清理违规正文、私有文件、状态令牌、签名地址或云服务原始响应。

## 10. 失败关闭

以下任一情况发生时停止批准，保持内容隐藏：TMS/IMS/CAPTCHA，Scanner 不可用、超时或无病毒库，当前技术证据缺失或陈旧，数据库/存储异常，审核 worker 持续失败，管理员权限校验异常。记录稳定错误码并告警，不把第三方原始错误暴露给用户。恢复后先用安全夹具冒烟，再恢复审核；共享包仍须重新取得当前有效技术证据。

## 11. 投诉举报处理

投诉入口为首页“反馈与建议”。识别以“【投诉举报】”开头的投稿后：

1. 记录被投诉公开 ID、类型、理由和必要证据，不要求投诉者公开身份；
2. 涉及明显违法、恶意文件或隐私泄露时立即紧急下架；
3. 涉及版权或事实争议时先下架隔离，再核对投稿内容与证据；
4. 通过状态查询结果给出有限处理说明，不公开管理员或举报人信息；
5. 误判时按恢复流程处理，超过三天且已清理则不能恢复原文件。

## 12. 紧急下架与安全事件

发现恶意文件传播、批量违规、权限绕过或令牌泄露时，立即关闭匿名投稿写路径，删除相关公开内容并使下载失效；轮换受影响的服务端密钥；检查管理员会话、审计记录、对象访问与网关日志；评估受影响范围后按适用要求处置。恢复前必须验证非管理员 API 仍返回 401/403、私有对象不能直读、危险包不能批准、日志不含明文令牌。

## 13. 误判复盘

复盘只记录最小必要的规则编号、风险类别、状态变化和修正措施。若需要调整关键词分组或组合规则，先增加对应回归用例，再在开发环境用安全/危险/边界夹具回归并修改源码；不得为减少人工量而取消政治内容、脏话、非 AI Pet 内容或技术扫描的强制检查。

## 14. 数据库迁移冻结

当前唯一迁移入口为 `pnpm.cmd plan:cloudbase-migrations`。该命令仅在本地读取仓库 migration 并输出 checksum plan；不读取凭据、不加载管理 SDK，也不连接或写入数据库。阶段 2 的事务型 runner、自动化和开发环境 PostgreSQL smoke 通过前，不得执行 migration 或通过控制台复制 SQL 绕过冻结；已提交数据库变更只能新增前向 migration。阶段 2 runner 仅可直接消费 inventory item 的 `version`、`fileName`、`sha256` 与 `bytes`，并须在 SQL 写入前对 checksum 漂移、重复版本、非法文件名和空 migration 失败关闭。该要求不构成阶段 2 runner 的实现、部署或数据库写入授权。
