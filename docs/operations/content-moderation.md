# 内容审核与应急处置手册

本手册供唯一管理员处理 AI Pet 共享资源包、反馈和建议。普通投稿完全匿名；管理员邮箱、审核证据、状态令牌和存储地址不得公开。

> 2026-09-01 状态：阶段 2C 的 Task 1、Task 2 与适用的 Task 4 已完成本地收窄和验证，远端前置门为 `blocked`。阶段四本地 Production/Memory 合同为 30/30，CloudBase API 分段门为 329/329，临时 PostgreSQL 17.11 已顺序执行 13 个 migration 并通过 103 项行为验证；同一次完整 `verify:web-chain` 已通过真实 Scanner 候选与 website E2E 21/21 并退出 0。这些本地证据不证明真实对象存储、TMS/IMS、cleanup、网关、远端 migration、部署、告警或人工处置流程已经执行。线上仍是旧测试版；共享包投稿继续关闭，本分支的管理员强制发布能力尚未上线。完整阻断事实见[网站阶段 2C 上海阻断验收记录](website-stage-2c-shanghai-acceptance.md)。

## 1. 审核原则

- 只允许与 AI Pet 产品直接相关的内容。
- 政治内容、脏话、色情、暴力、违法、广告、隐私泄露、恶意文件、侵权和非 AI Pet 内容不得公开。
- 所有投稿先进入系统审核状态并保留真实扫描事实，再由管理员作出发布裁决。系统通过不等于自动发布；`system_reviewing` 或 `auto_rejected` 也可由管理员填写理由后转入人工队列。
- 文本、图片、JSON、ZIP 或外部审核任一必要检查失败时均保持隐藏，不得按通过降级。
- 共享包上传完成只进入 `system_reviewing`；成功扫描后进入 `manual_review_pending`，危险或无效包进入 `auto_rejected`，依赖失败继续保持私有并重试。
- `manual_review_pending` 的共享包执行普通批准前必须具有当前有效的技术扫描通过证据；缺少证据时普通批准保持禁用，但唯一管理员可在完成独立风险确认后执行“强制发布”。`auto_rejected` 不能一步发布，反馈与建议不依赖角色包 Scanner。
- 当前有效证据必须同时表明 `package_scan`、`isolated-scanner`、`Pass`，并与当前投稿 ID、不可覆盖包对象键、实际包大小、完整 ZIP 大小和 SHA-256、协议版本、规则版本、扫描完成时间、最终状态版本和 `CHARACTER_PACKAGE_SCAN_PASSED` 结果码精确绑定。
- 技术证据从扫描完成时起精确有效 24 小时，只有 `expiresAt > now` 才有效；恰好到期即失效。
- 缺少、陈旧或字段不完整的证据，以及 Scanner 不可用、超时或失败时，普通批准必须保持禁用；“转人工”不改变技术事实，也不会自动触发强制发布。
- 系统未通过、缺少有效通过证据或 Scanner 失败的共享包，可先经 `move_to_manual` 进入 `manual_review_pending`，再由唯一管理员完成独立风险确认并执行 `force_publish`；该两步流程不得改写或删除原扫描事实。

### 1.1 本地关键词相关性信号

- 强产品词包括 AI Pet、AI桌宠、桌宠、桌面宠物和 desktop pet，命中后给出相关性通过建议。
- 资源对象、产品功能、问题与建议采用跨组组合判断；单个弱词不能自动通过。
- 零命中、弱命中或组合不足统一转人工，不代表内容已经违规；规则异常记录稳定错误码 `KEYWORD_RELEVANCE_RULE_ERROR`、触发告警并进入人工队列。
- 关键词审核记录提供方为 `local-keyword`，规则版本为 `keyword-relevance-2026-08-01`。
- 关键词层绝不自动驳回，管理员仍需结合原文、TMS/IMS、OCR 和文件扫描结果作出最终决定。

### 1.2 公开下载计数口径

- 公开字段 `downloadCount` 只表示“成功签发次数”：服务先确认投稿仍公开、发布依据有效且只有一个固定包资产，再成功生成短期签名地址，并在幂等计数事务成功后才向浏览器返回地址。
- 同一设备以同一 `operationId` 重试时可以重新签名，但只回放首次计数快照，不重复增加成功签发次数；计数事务失败时不得返回已经生成的地址。
- 成功签发不证明浏览器实际传输了文件字节，也不等于下载完成、安装完成或使用成功。历史计数不按新口径猜测回写或校正。

### 1.3 发布结构不变量

- 普通批准与强制发布经过同一结构断言；管理员最终裁决权不能绕过结构完整性。
- 共享包必须具有非空标题和正文、恰好一个 cover 与一个 package、固定投稿根内 cover/package 对象键、匹配的图片/ZIP MIME，以及大于零的实际大小；derived 资产可多值。
- 反馈和建议只要求合法 kind 与非空标题/正文，不要求角色包资产或 Scanner 证据。
- 本地 PostgreSQL 和 Memory Adapter 已覆盖这些规则；远端 migration 未执行，因此不得宣称任何 CloudBase 环境已由数据库约束保护。

## 2. 每日队列检查

1. 登录 `/admin`，确认使用已预注册的唯一管理员邮箱 OTP。
2. 依次查看“待我审核”“自动驳回”“已发布”“隔离区”和“审计记录”。
3. 先处理高风险和投诉举报记录，再处理普通队列；隔离区到期清理由定时任务执行并通过告警跟踪。
4. 每次操作前刷新详情；界面使用状态版本号与幂等键，出现 409 时重新加载，不重复提交旧操作。

## 3. 系统通过后的人工审核

对 `manual_review_pending` 记录逐项核对：

- 标题、正文、封面 OCR、JSON 可展示字段与 AI Pet 的直接相关性；
- TMS/IMS 与自定义规则的标签、分数和有限证据；
- 共享包文件清单、MIME/签名/路径/大小、ClamAV、图片解码与内容安全结果，以及与当前投稿和状态版本精确绑定的技术扫描通过证据；
- 版权、第三方权利、广告、联系方式和隐私泄露风险。

共享包只有在上述当前有效证据完整时才能填写理由并执行普通“批准发布”，发布依据记录为 `standard`；普通反馈与建议沿用既有人工审核条件。存在违规、权利风险或无法接受的不确定性时填写理由并“驳回”。管理员理由不得包含密钥、内部 URL、管理员身份或不必要的敏感原文。

## 4. 自动驳回与转人工

`auto_rejected` 表示系统发现明确违规。管理员应检查命中规则与证据：

- 判断正确：维持自动驳回，等待三天隔离清理；
- 疑似误判且需要继续判断：填写理由后执行“转人工”，投稿进入 `manual_review_pending`；该动作不改写原技术扫描结论；
- 共享包具有当前有效通过证据且内容复核确认无违规时，执行普通批准；
- Scanner 不可用、技术扫描失败、未完成、超时、恶意文件命中、证据陈旧或字段缺失时，普通批准必须保持禁用。
- 上述系统未通过或无有效证据情形不会自动公开；唯一管理员若决定承担风险，必须先完成“转人工”，再按第 4.1 节执行独立强制发布。

转人工不会重绑定旧证据、不放宽普通批准规则，也不会直接公开。对象键、实际大小、完整 ZIP 大小或 SHA-256 任一归档身份字段变化时都必须重新扫描。

### 4.1 共享包强制发布

仅当共享包处于 `manual_review_pending` 且缺少当前有效技术通过证据时，唯一管理员才可使用独立“强制发布”动作；“缺少有效证据”包括系统未通过、危险结论、未完成、超时、证据陈旧或字段缺失，但原结论必须完整保留：

1. 填写具体审核理由，第一次点击“强制发布”只展开风险确认区；
2. 完整阅读“该文件未通过安全扫描，发布后用户可能下载危险文件”；
3. 只有明确确认后才提交 `ADMIN_OVERRIDE_ACCEPTED`，发布依据记录为 `admin_override`；
4. 公开卡片、详情和下载入口必须显示“管理员人工放行，未通过系统安全验证”。

存在当前有效通过证据时应使用普通批准，不得错误标记为人工覆盖。强制发布不生成扫描通过证据、不改变原扫描记录，也不能从 `system_reviewing`、`auto_rejected` 或隔离状态一步发布。

## 5. 管理员驳回

人工审核不通过时选择“驳回”，理由应对应具体规则，例如“与 AI Pet 无关”“包含政治内容”“存在版权授权疑点”或“含联系方式广告”。驳回后正文和文件立即保持私有并进入三天隔离期；不要在审计理由中复制完整违规文本。

## 6. 已发布内容删除

收到有效投诉、发现漏审或出现紧急风险时：

1. 打开“已发布”，确认目标 ID 与公开页面一致；
2. 填写原因并执行“删除”；
3. 立即检查公开社区或反馈列表中已消失，下载接口不再签发地址；
4. 到“隔离区”确认状态为 `deleted_quarantined`，保留原状态以便三天内恢复；
5. 在审计记录中确认操作、前后状态、理由和时间存在。

## 7. 三天内恢复

仅在确认误删、投诉撤回且内容重新满足规则时恢复。恢复前重新检查文件状态，填写恢复理由并执行“恢复”。反馈与建议按删除前状态恢复；共享包无论删除前状态为何都先回到 `system_reviewing`，不重绑定旧版本证据，重新扫描成功后进入 `manual_review_pending`，并由管理员重新批准。恢复动作本身不得让共享包重新公开。

## 8. 三天后清理

`ai-pet-cleanup` 设计为定时处理到期隔离记录与过期互动幂等账本。清理后状态为 `purged`，封面、ZIP、正文及可识别内容永久删除，只保留投稿 ID、内容类型、状态时间、规则编号、风险类别和管理员操作摘要等最小审计信息。永久清理不可由管理员页面恢复。当前真实 cleanup 调度尚未配置，不能把本地函数和测试写成远端清理已生效；部署后每天检查清理失败告警，不得通过延长公开可见性解决失败。

## 9. 审计记录

每个管理员写操作必须具有：管理员会话与白名单校验、目标投稿、操作前后状态、理由、幂等键、版本号和时间。强制发布还必须保存精确风险确认、动作时可见的最新扫描摘要和首次结果快照；同键同输入只回放首次快照，同键异参必须冲突失败。HTTP 响应中的请求 ID 用于排查当次请求，但当前不写入管理员审计记录。审计记录不可在普通管理员页面修改；不得保存完整已清理违规正文、私有文件、状态令牌、签名地址或云服务原始响应。

## 10. 失败关闭

以下任一情况发生时停止普通批准，保持内容隐藏：TMS/IMS/CAPTCHA，Scanner 不可用、超时或无病毒库，当前技术证据缺失或陈旧，数据库/存储异常，审核 worker 持续失败，管理员权限校验异常。记录稳定错误码并告警，不把第三方原始错误暴露给用户。数据库、存储或管理员权限异常时强制发布同样失败关闭；只有服务恢复且管理员完成第 4.1 节的独立风险确认后，才能执行该高风险动作。

## 11. 投诉举报处理

投诉入口为首页“反馈与建议”。识别以“【投诉举报】”开头的投稿后：

1. 记录被投诉公开 ID、类型、理由和必要证据，不要求投诉者公开身份；
2. 涉及明显违法、恶意文件或隐私泄露时立即紧急下架；
3. 涉及版权或事实争议时先下架隔离，再核对投稿内容与证据；
4. 通过状态查询结果给出有限处理说明，不公开管理员或举报人信息；
5. 误判时按恢复流程处理，超过三天且已清理则不能恢复原文件。

## 12. 紧急下架与安全事件

发现恶意文件传播、批量违规、权限绕过或令牌泄露时，立即关闭匿名投稿写路径，删除相关公开内容并使下载失效；轮换受影响的服务端密钥；检查管理员会话、审计记录、对象访问与网关日志；评估受影响范围后按适用要求处置。恢复前必须验证非管理员 API 仍返回 401/403、私有对象不能直读、危险包不能批准、日志不含明文令牌。

审核 worker 在管理员强制发布后送达的技术结果只更新真实扫描记录和风险摘要，不得静默改写 `published`、`admin_override`、状态版本或管理员审计。若后到结果为危险，管理界面必须持续显示高风险信息；系统不自动隔离，管理员应立即核对目标 ID，按第 6 节执行“删除并隔离”，并确认公开列表和下载接口已失效。

## 13. 误判复盘

复盘只记录最小必要的规则编号、风险类别、状态变化和修正措施。若需要调整关键词分组或组合规则，先增加对应回归用例，再在开发环境用安全/危险/边界夹具回归并修改源码；不得为减少人工量而取消政治内容、脏话、非 AI Pet 内容或技术扫描的强制检查。

## 14. 数据库迁移冻结

`pnpm.cmd plan:cloudbase-migrations` 仍是默认只读迁移入口，只在本地输出 checksum plan，不读取凭据、不连接数据库。2026-09-01 已用 `node tools/test-cloudbase-migrations.mjs --postgres-runtime <本地 PostgreSQL 目录>` 在临时 PostgreSQL 17.11 中顺序执行 13 个 migration 并通过 103 项行为验证；该工具只用于一次性本地行为门，在随机本机端口验证函数、约束、批准/强制发布拒绝、幂等互动与事务回滚后停止并删除临时实例，不得传入远端地址，也不构成 CloudBase 部署或生产写入授权。同日完整 `verify:web-chain` 已通过真实 `scanner-candidate` 与 website E2E 21/21 并退出 0；已提交数据库变更仍只能新增前向 migration，真实开发环境和生产 migration 均未执行，并继续受阶段 2C 独立授权门冻结。
