# 描述用途匹配与真实事件表现修复

日期：2026-09-12。范围依据：用户本轮明确要求恢复三档运动、聊天前思考、任务期间工作、失败沮丧、成功或夸赞开心、久未互动无聊，并处理保持、中断与结束。延续[持续行为规格](2026-09-12-character-behavior-continuity-design.md)的模型解释描述、程序保持调度、单一 Engine 和单屏运动边界。

## 目标与证据

真实 Coordinator → Projection → Director → Service → Engine 组合已经复现：初次请求挂起时没有思考候选；授权卡遗漏等待事实；局部工作计划覆盖旧思考或移动候选；终态事实正确但结果反应等待另一次推理。真实 Runtime + Scheduler 复现启动活动匹配把首次五分钟自主评估推迟至十五分钟，以及失败后本生命周期不再恢复。旧脚本化模型 E2E 只证明正确候选可以播放，不证明模型用途匹配稳定。

不修改文件执行器、Qwen 文件任务判别、权限、角色素材、已验收的移动尺寸和位移数学。不引入外部依赖、名称关键词表、第二套状态机或持久化个人上下文。

## 用途匹配

角色和模型就绪时，独立无工具请求只根据公开作者名称与描述选择各用途的合法 `stateId/actionId`，无合适素材可以返回空。用途包括正在处理聊天、真实工作、等待确认、移动、成功、失败、被夸赞、长期未陪伴和休息。模型不决定真实事件是否发生，也不生成权限或工具结果。

用途表仅在 Main 当前角色与模型生命周期内保存，换角色、修改描述、模型配置变化、reset 或关闭后撤销。跨用途允许同一作者动作，但提交现有 Engine 时按当前用途生成一个合法候选，避免重复 ID 或将多个用途误写成 AND 条件。逐轮普通表现不能擦掉已经接纳的用途表。

启动失败采用有界、间隔恢复；不与空闲评估共享下一次评估时间。第一次输入恰逢准备未完成时，采用有界准备后再响应；不能把尚未匹配或未收到 Renderer 首帧说成已播放。用途缺失或模型不可用不阻塞基础聊天或已授权任务。

后台用途准备与自主重评分别每小时最多四次，失败和取消不返还已消费额度；后台预检重试至少间隔一分钟。用户主动输入时如仍缺用途，当前轮可以进行一次十二秒有界准备；这次明确交互不占后台预算，也不在本轮自动循环重试。用途表属于当前角色实例，模式切换或纯运动重试不清除已经验证的作者用途。Renderer 尚未显示当前角色时可以预热用途，但自动运动必须等待当前 Engine 接纳首个合法 `started`；随后每次运动仍使用原有 1.5 秒首帧门槛。旧实例反馈不能放行新实例，不延长超时、不修改窗口尺寸和位移算法。

## 事件、保持与退出

| 可信来源 | 表现与结束 |
| --- | --- |
| 接收本轮聊天输入 | 准备思考，主请求仍在处理时保持；主回复、失败、取消或授权等待结束该聊天占用 |
| 授权卡 | 单独等待事实；未授权不产生 taskRunning；取消、拒绝、失效或提交后退出 |
| Core 真实执行 | 保持工作，许可等待可选等待表现；准备首帧不伪造执行事实 |
| Core 成功／失败 | 立即用已验证结果用途提交有界反应；只认 Core，普通聊天 success 不能冒充任务成功 |
| 夸赞等普通聊天 | 无工具请求只选择本轮反应或明确目标；反应在正文处理结束后接续，不永久绑定 chatting |
| 未互动五分钟 | 开启自主时按未陪伴用途选择可持续背景；保留后续十五分钟重评与小时预算；只依赖桌宠互动和运行时情境 |
| 三档运动 | 0 禁止自主位移，1 连续，2 间歇；聊天、任务、拖拽及明确播放期间遵守已有阻塞与首帧边界 |

明确状态／动作仍遵守用户优先与原有有限播放契约。临时反应结束恢复有效长期背景，不能每轮插入待机。任务终态、新输入、取消与配置切换使旧异步结果失效；新思考或工作不能被上一轮迟到反应覆盖。所有调用保留时间上限与取消清理。

真实事件反应只保留一个作者定义的有限状态片段，片段可以包含多个动画循环，不能在十秒冷却后再次出现。片段占用期间暂停自动运动；已经明确提交的用户位移保留自身令牌，不被晚到的普通聊天反应改写。拖拽中断真实位移并保留档位，松手后按当前聊天、任务、反应与运动首帧事实重新调度。

## 请求简化与并行

用途匹配把固定事件语义移出每轮完整计划推理。逐轮无工具表现仅选择反应、明确状态／动作、长期背景或移动控制，分数、活动条件与有限生命周期由 Main 转为既有协议。远程主请求与表现继续并行；Qwen 单槽不并发争用，有了预先用途即可先显示思考并运行正文，之后进行必要的本轮表现选择，动画与正文／任务并行。移除被替代的每次任务终态再推理与仅 moving 的启动匹配路径。

逐轮请求只有 `kind / choice / mode / target / distance` 五字段，模型不生成活动条件、分数或持续时间。Qwen 实测可能同时选 `background` 和运动档位；仅当配对准确等于当前已验证的 moving 用途时，将该一致的位移意图转成运动。移动用途不能作为静止的长期背景原地循环；作者明确原地表演仍通过有界 state/action。DeepSeek 实测将获得认可与索求关注混淆，因此夸赞用途明确为获得认可后的开心，不通过默认 ID 映射纠正模型。

旧的嵌套模型选择 Schema 和转换器退役，仅保留 Engine 仍消费的内部决策类型；Provider 通用结构化输出、原主聊天申请协议与 Core 执行链不变。

## 验证与交付

### 2026-09-13 休息与自动运动互斥补充

用户明确要求“休息期间不要移动”，本补充将这一要求收敛到现有 Director：已接纳的长期背景对应当前模型匹配的 `rest` 状态时，暂停连续与间歇自动运动，包括尚未开始的首帧准备和已经开始的自动位移。复用 Engine 的背景生命周期与现有停止入口，不增加固定名称表、另一套状态机或持久配置。

休息不修改用户保存的三档运动模式；聊天、任务、结果反应和拖拽结束后，仍有效的休息继续阻止自动运动。新的有效背景替换休息后解除暂停；用户明确请求位移或非零运动档位时结束休息背景。静止命令保留休息。明确的一次性动作仍遵守原有有限播放，不自动改为长期状态。无聊等其他背景不一律禁止移动。

只修正 Main 调度，不改模型协议、素材、窗口几何、文件权限和 Renderer。新增自定义状态动作的支持情况按用户要求只读核查；本缺陷用默认角色契约的 Service／Director／Scheduler 定向回归验证，不启动桌宠或真实模型。非法、迟到和无匹配选择继续沿用原有拒绝策略。实际结果单独记录。

真实 Qwen／Provider 实验单独记录合法性、语义命中与耗时；网络替身不得冒充真实模型。必要 Engine／桌面测试、类型检查、安全与集成、构建及隔离 Electron 验证分别记录。人工视觉验收由用户完成，保留全量门禁既有失败的准确记录。

本修复替代旧持续规格中“Qwen 每轮先完成完整表现再请求正文”“每次任务终态另发模型请求”和仅移动启动匹配的实施选择；其余已批准契约继续有效。实施步骤和实际证据分别记录，本文不作为完成证明。
