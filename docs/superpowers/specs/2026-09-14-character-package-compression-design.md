# 完整角色包无损导出压缩

## 授权、目标与边界

用户已确认保留 PNG 格式、完整原始素材、运行图集、草稿和配置，导入操作不变，并于 2026-09-14 明确要求提交此前内存优化后开始实施。本规格固化该已批准方案，无需重复批准。此前内存优化已独立提交 `9faef2a1`。

目标是在普通角色包导出时缩小完整包体，不改变像素、透明度、尺寸、裁片坐标、动作、播放速度、皮肤、锚点及行为。只修改导出副本；本地素材、草稿与已发布版本保持。没有降画质、删帧、删源文件、草稿替代已发布版本或自动上传。

本次不修改官网上传上限、CloudBase、扫描器及共享解压预算，不处理内置模型，不改变界面或核心功能。恢复导出承担原始故障证据归档，继续逐字节保留文件。后续网站上限调整仍需独立实施；不承诺任意丰富角色都能小于 100 MiB。

## 现状与方案

现有 `character-package-service.ts` 使用 yazl 导出 ZIP，yauzl 导入时已经解压、校验并安装。PNG 本身已经压缩，外层 ZIP 单独提高压缩级别收益有限。默认包包含九张源图和九张图集，没有重复 SHA；草稿可包含未发布修改，不能删除源目录或重新编译来替代发布图集。

采用内置 `node:zlib` 对 PNG 的 IDAT 压缩流做无损重压，保留原始过滤行字节，不进行图像解码、滤镜、调色板转换或像素重采样。比较 level 9 下 memLevel 8/9 的结果，只保留更小候选。合并连续 IDAT，其他允许保留的 PNG 块逐字节保留；无法可靠处理、未知结构、动画、无收益或超过优化工作预算时直接保留原文件。WebP 等其他资源保持原字节。JSON 保留全部字段并继续由 ZIP 压缩。

PNG 优化是可选表示优化，不成为新的导入格式或严格性边界。调用入口为 `optimizePngForExport(input: Buffer): Promise<Buffer>`，异常或不适用返回原数据；输入文件的身份、字节数和 SHA 检查仍由现有导出服务负责，不能吞掉源文件变化错误。

## 导出数据流与内存

保留原文件句柄及实际字节 SHA 检查。归档输出连接到现有可信临时 FileHandle 后，逐个读取并验证资源，优化一张后立即通过 yazl 流写入；等待该资源消费完成再处理下一张，不缓存全包或同时展开所有图片。压缩使用异步 zlib，不在 Main 同步执行大块压缩。单张解压工作数据预算为 128 MiB，解析最多保留 8192 个块，超出仅跳过优化，既有角色包大小边界保持。块预算在创建下一个块对象之前检查，避免大量空 IDAT 放大 Main 堆内存。

源素材保留 assetId、文件名和 MIME，更新导出 catalog 的 byteLength/sha256；运行图集保留 assetId/fileName，更新资源 byteLength/sha256，并按原契约更新各表现引用资源 SHA 去重排序后的 geometry.resourceRevision。所有其他几何数据保持。最后写入完整草稿和更新后的两个 JSON 文档，仍按既有预算检查最终包内字节。

原有安全临时文件、排他目标写入、目标竞态检查与失败清理继续使用。归档写入失败必须终止资源准备及输出，不留下伪成功包。导入端不新增手工解压或图片还原步骤，也不修改包版本。

## 兼容、失败与验证

- 严格验证被优化 PNG 的签名、块边界、CRC、必要结构；不能保持全部相关信息时回退原文件，绝不静默删除未知数据。
- 重新压缩会改变文件字节和 SHA，但 PNG 解压后的过滤流必须完全一致，因此像素及所有解码语义保持。
- 保留原导出只包含目录清单内文件、禁止链接替换和原文件变化、目标不覆盖的规则。恢复导出及导入事务保持。

- 集成 TDD：真实角色导出，源图和图集均缩小、全部文件仍存在、原项目逐字节未改；新目录导入后草稿、已发布配置和资源摘要一致，再次导出及重新读取源素材通过。继续运行导出竞态、错误和清理测试。

## 替代与参考

本规格只替代普通导出把素材字节直接写入 ZIP 的资源准备方式，保留唯一导入/导出协议。此前角色工作室、发布播放、本地大尺寸源图规格与其包预算继续适用。没有用户数据迁移，没有新增依赖或复制外部源码。

复用现有 yazl/yauzl 及 Node zlib；方案参考 [Node zlib](https://nodejs.org/api/zlib.html)、[PNG 规范](https://www.w3.org/TR/png-3/)。已比较 pngjs、sharp 方案，本次无需引入额外编码库。
