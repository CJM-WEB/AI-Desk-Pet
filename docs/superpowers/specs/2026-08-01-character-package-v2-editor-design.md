# 角色包 V2 与角色工作室编辑闭环设计

## 1. 文档目的

本文定义 AI 桌宠阶段 1 的角色包 V2、开发期 V1 自动转换、角色工作室编辑闭环和现有播放器兼容边界。

本阶段直接把 V2 作为新建、编辑、编译、导入和导出的唯一正式角色结构。项目尚未正式发布，因此不向用户暴露“升级角色”流程；现有本地 V1 数据和导入的 V1 角色包由程序自动保留并转换。

本阶段只建立稳定的数据和编辑契约，不接入自主行为引擎。桌宠仍按当前状态仲裁和动作选择方式运行，为紧随其后的“本地事件—状态推断—动作调度”阶段提供可靠基础。

## 2. 已确认原则

- 继续使用现有 Electron、TypeScript、PixiJS、Zod、Zustand 和角色存储体系，不替换项目骨架。
- 采用“一个角色身份、一个默认皮肤、多个增量覆盖皮肤”。
- 采用“一个主状态、多个修饰状态”，不允许多个主状态同时控制角色身体。
- 采用“系统标准语义、用户自定义语义标签”双层语义。
- 用户定义表现约束，系统保留最终中断和安全裁决权。
- 不再强制八个固定核心状态，只要求一个默认回退状态可播放。
- 角色人设使用结构化字段，不允许角色包携带任意系统提示词。
- 采用现有三栏角色工作室的渐进扩展方案。
- 现有 V1 数据自动转换，不显示升级按钮，不长期维护两套编辑逻辑。
- 采用最小修改、TDD、原子存储和严格角色包安全边界。

## 3. 范围

### 3.1 本阶段包含

- 角色包 V2 草稿与发布清单契约。
- 角色身份、人设、皮肤、状态、动作、表现覆盖和回退关系。
- V1 本地数据与 V1 导入包的自动转换。
- V2 草稿、编译清单、角色索引和角色包导入导出。
- 角色工作室中的人设、皮肤、状态语义和动作约束编辑。
- V2 到现有播放器输入的只读投影。
- 转换、保存、编译、导入导出和预览回退的测试与恢复路径。

### 3.2 本阶段不包含

- Agent 参与状态判断或动作选择。
- 新的自主行为调度器和主动性运行时。
- 真实文件删除、回收站适配、文件搬运动画提交点。
- 资源管理器目录观察、目录藏身和动态窗口层级。
- 长期记忆、自由聊天改造、语音和桌面自动化。
- 角色包中的脚本、Shell、任意 Prompt、系统权限或未知执行器。

## 4. 总体架构

阶段 1 形成以下单向数据链：

```text
V1 本地数据 / V1 导入包
          │
          ▼
   V1 开发期转换器 ──失败──► 保留 V1 与恢复记录
          │
          ▼
     V2 草稿与素材目录
          │
   角色工作室编辑与自动保存
          │
          ▼
      V2 编译与发布清单
          │
          ├────────► V2 角色包导出
          │
          ▼
 LegacyRuntimeView 只读投影
          │
          ▼
       现有播放器
```

V2 是唯一正式角色结构。`LegacyRuntimeView` 是 Main 在加载 V2 后生成的派生运行 DTO，只服务当前播放器，不回写角色数据，也不作为导出格式。

## 5. 角色包 V2 契约

### 5.1 顶层结构

V2 草稿和发布清单使用明确的 `version: 2`。顶层逻辑字段包括：

- `id`、`name` 和缩略图引用。
- `identity`：结构化角色人设。
- `defaultSkinId`：默认皮肤标识。
- `defaultStateId`：默认回退状态标识。
- `skins`：皮肤与表现覆盖。
- `states`：状态语义、类别和动作关联。
- `actions`：动作语义和调度约束。
- `resources`：发布清单中的素材元数据。
- 编译版本和必要的完整性元数据。

草稿允许未完成的表现帧；发布清单要求默认回退链能够得到至少一个可播放动作。所有对象标识必须在所属角色内稳定且唯一。

### 5.2 结构化人设

`identity` 包含有界的纯数据字段：

- 角色简介和背景设定。
- 性格特征标签。
- 语言风格和常用称呼。
- 喜好、厌恶和行为倾向。
- 角色边界。
- 可选示例台词。

所有文本和数组必须设置长度与数量上限，防止角色包制造无界上下文。示例台词只表示语言风格；运行时以后通过应用内受控模板转换为 Agent 上下文，不能覆盖系统安全策略、工具权限、隐私规则或系统提示。

### 5.3 皮肤

每个角色至少有一个皮肤，且 `defaultSkinId` 必须引用现有皮肤。

皮肤只描述表现：

- 稳定 ID、显示名称和说明。
- 按动作 ID 保存的表现覆盖。
- 按标准语义族保存的通用表现回退映射。

动作表现包含帧、FPS、锚点和交互区域等与素材相关的数据。角色身份、状态语义、动作权限、行为偏好和关系记忆不属于皮肤。

非默认皮肤采用增量覆盖，不复制默认皮肤的完整数据。解析指定动作表现时采用固定顺序：

1. 当前皮肤的精确动作表现。
2. 当前皮肤为该标准语义族声明的通用动作表现。
3. 默认皮肤的精确动作表现。
4. 默认回退状态在默认皮肤中的首个可播放动作表现。

通用回退必须引用相同标准语义族的动作，不能跨语义伪装。回退关系必须无环。

### 5.4 状态

状态名称不再由程序固定。每个状态包含：

- 稳定 ID 和显示名称。
- `primary` 或 `modifier` 类别。
- 一个标准语义族或明确的自定义语义。
- 用户自定义语义标签。
- 有界强度和建议持续时间。
- 允许共存与明确禁止的状态引用。
- 结构化进入和退出提示。
- 是否允许 Agent 在未来推断该状态。
- 该状态可使用的动作 ID。

同一时刻只有一个主状态，修饰状态可以并存。角色包只声明共存与禁止规则；最终冲突处理属于下一阶段的系统调度器。

状态条件不得包含代码或任意表达式。本阶段只允许引用应用注册的可信行为信号、标准语义和本角色状态 ID。条件组合只允许有界的“全部满足”或“任一满足”，不允许递归嵌套和用户自定义运算符。第一批可信行为信号覆盖闲置、用户交互、对话开始、倾听、思考、任务开始、任务成功、任务失败、移动开始、移动停止、携带开始和携带停止。

### 5.5 动作

动作定义与皮肤表现分离。动作定义包含：

- 稳定 ID 和显示名称。
- 标准语义族与用户自定义语义标签。
- 行为偏好值。
- 建议持续时间、冷却和重复抑制窗口。
- 循环策略。
- 普通中断策略和被中断后的回退动作。
- 适用与禁止的主状态、修饰状态和方向。
- 失败回退动作。
- 未来可选的受控能力引用。

动作回退引用必须存在且无环。任务动作以后只能引用应用注册的受控能力，不能声明命令、路径、权限或脚本。

用户声明的“不可中断”只约束普通动作切换。以下系统事件始终具有强制中断权：

- 用户拖拽或明确取消。
- 安全确认、错误和真实任务结果。
- 角色切换、窗口关闭和素材失效。
- 文件操作真实结果与动画阶段不一致。

### 5.6 语义命名空间

系统标准语义族提供稳定调度词汇，第一批包含待机、倾听、思考、移动、说话、携带、庆祝和失败。用户可以创建任意显示名称和自定义语义标签，但不能占用系统命名空间。

未知自定义语义不根据名称猜测系统含义。未来调度无法精确匹配时，先使用角色声明的标准语义族，再进入默认回退状态。

## 6. V1 自动转换

### 6.1 用户体验

- 不显示“升级为 V2”按钮、弹窗或版本选择。
- 启动加载现有 V1、本地编辑 V1 或导入 V1 包时自动转换。
- 新建、复制、保存、编译、导入和导出全部直接产生 V2。
- 转换成功后角色在工作室中直接显示 V2 能力。

### 6.2 字段映射

- 保留角色 ID、名称、缩略图、素材 ID、文件名、哈希和长度。
- 创建 `default` 默认皮肤。
- V1 帧、FPS、锚点和交互区域进入默认皮肤的动作表现。
- V1 内置状态 ID 保留并映射到对应标准语义。
- `idle` 映射为默认回退状态。
- V1 自定义状态 ID、显示内容和触发器保留；未知名称不推断标准语义。
- V1 动作权重映射为 V2 行为偏好。
- 循环、方向和现有动作属性映射到对应 V2 字段。
- V1 缺少的新约束采用保守默认值：无冷却、允许普通中断、无受控能力引用。
- 素材文件不复制，只重组引用关系。

V1 如果存在跨状态重复动作 ID或重复状态 ID，转换器必须保留全部内容并生成确定性的唯一 ID，同时记录旧 ID 到新 ID 的内部转换映射。相同输入必须得到相同结果。不能静默覆盖后出现的对象。

### 6.3 事务步骤

1. 完整读取并验证 V1 元数据与素材引用。
2. 在内存生成 V2 并执行全量 V2 校验。
3. 写入固定事务临时文件并重新读取验证。
4. 将原 V1 元数据移动为内部恢复备份。
5. 原子替换 V2 数据并更新角色索引。
6. 提交完成后保留一个最近恢复点并清理临时事务文件。

任一步骤失败都必须恢复索引和原角色。不能留下半个 V2、空角色、孤立素材或错误的活动角色指针。启动时发现中断事务时，根据已持久化阶段继续提交或恢复旧数据。

转换失败的角色保留在角色列表中并显示稳定错误状态；用户可以查看恢复提示、重新尝试或导出原始数据，不得自动删除。

## 7. 存储、编译和角色包

### 7.1 正式数据边界

- 草稿和发布清单只保存 V2。
- 角色索引记录角色版本和必要的转换状态。
- 编译资源继续使用内部安全文件名与哈希校验。
- Main 加载 V2 后生成 `LegacyRuntimeView`，磁盘不维护第二份正式 V1 清单。
- 导出只生成 V2 角色包。

### 7.2 导入

导入继续在隔离目录中执行：

1. 校验归档条目、大小、类型、路径和资源结构。
2. 识别 V1 或 V2。
3. V1 在隔离目录中完成转换；V2 直接严格解析。
4. 校验资源引用、哈希、默认皮肤和默认回退链。
5. 通过现有角色创建与回滚事务进入正式存储。

失败不能创建部分角色或污染源素材目录。V2 未知字段严格拒绝，防止拼写错误和恶意声明被静默接受。

### 7.3 编译与运行投影

编译器验证完整 V2 和所有引用。发布成功后，当前播放器只消费 Main 生成的只读投影视图：

- 使用默认皮肤解析动作表现。
- 将 V2 标准语义映射到现有播放器能够识别的运行状态。
- 无法映射的自定义语义通过默认回退状态提供可播放动作。
- 投影不修改 V2、不写回权重、不删除未知状态或皮肤。

本阶段不改变当前动作选择算法。默认皮肤改变并重新发布后，运行角色可以显示新默认皮肤，但选择动作的触发和权重逻辑仍与现状一致。

## 8. 角色工作室 V2

### 8.1 布局

保留现有三栏结构，不建立新的顶部工作区导航。

左栏上半部分由“角色”扩展为“角色与皮肤”；下半部分继续使用“状态与动作”。中央继续使用实时预览、播放控制和时间轴。右栏根据当前选择显示角色人设、皮肤、状态或动作属性。

### 8.2 角色与人设

选择角色后，右栏编辑结构化人设字段。界面不提供任意 JSON、系统 Prompt 或脚本输入。所有数组字段使用可增删的结构化行，并显示数量和长度限制。

### 8.3 皮肤编辑

- 皮肤区域标题提供加号。
- 每个非默认皮肤行提供减号。
- 默认皮肤不可直接删除，必须先设置其他皮肤为默认。
- 删除空皮肤可直接完成；包含表现覆盖时需要确认。
- 皮肤选择只改变草稿编辑上下文和中央预览。
- 修改默认皮肤并重新发布后，现有播放器显示新的默认皮肤。

### 8.4 状态与动作编辑

- 继续使用现有状态行加号、动作行减号和状态删除确认模式。
- 状态行标记主状态或修饰状态。
- 状态属性使用结构化选择器编辑语义、强度、持续时间、共存、禁止、条件和 Agent 可推断标记。
- 动作属性编辑语义、偏好、冷却、中断、适用/禁止状态、方向、循环和回退。
- 引用选择器只列出当前角色中的合法对象，不能手输不存在的 ID。

删除被引用的状态、动作或皮肤时，界面列出引用来源。能够确定地安全移除的引用可在确认后同步清理；可能改变语义或回退结果的引用必须先由用户重新选择，系统不得猜测。

### 8.5 实时预览

- 切换角色、皮肤、状态或动作时先提交当前编辑，再加载目标对象。
- 皮肤切换立即重建候选播放器并释放旧播放器。
- 缺少精确表现时，预览显示当前使用的回退来源。
- 整条回退链不可播放时显示明确错误，不保留上一角色或上一皮肤的旧画面。
- 时间轴继续编辑当前解析出的动作表现，不跨皮肤写入。

### 8.6 草稿持久化

复用现有自动保存、修订号、角色切换屏障和关闭前 `flushDraft`。V2 的嵌套编辑操作必须生成不可变的新草稿值，不能原地修改导致修订检测失效。

保存状态必须区分“正在保存、已保存、保存失败”。失败时保留内存编辑值并明确提示，不能显示“草稿已保存”。

## 9. 错误处理

| 故障 | 处理方式 |
| --- | --- |
| V1 转换失败 | 保留原数据和恢复记录，角色标记转换失败 |
| V2 临时文件验证失败 | 不替换当前数据，清理临时文件 |
| 索引提交失败 | 回滚角色数据与索引，重启继续恢复 |
| 草稿保存失败 | 保留内存修改，显示失败并允许重试 |
| 皮肤表现缺失 | 按固定链回退并显示来源 |
| 整条表现链不可播放 | 阻止发布，指出皮肤、状态和动作 |
| 删除对象仍被引用 | 列出引用；安全引用确认清理，其余阻止删除 |
| 回退关系成环 | 稳定拒绝并指出循环节点 |
| 未知字段或非法语义 | 严格拒绝，不进行名称猜测 |
| 导入失败 | 删除隔离事务，不污染正式角色存储 |

所有公开错误继续使用稳定错误码，Renderer 不显示绝对内部路径。恢复记录只保存事务所需元数据，不复制无关用户数据。

## 10. 性能和安全

- V2 校验与运行投影只发生在加载、保存、编译或角色切换时，不进入逐帧渲染。
- 皮肤共享角色素材目录，不复制相同资源文件。
- 预览只加载当前皮肤与当前动作所需资源，切换时释放旧播放器。
- 本阶段不增加模型调用、后台高频轮询、截图或桌面感知。
- 角色包不能携带任意代码、命令、路径授权、系统权限、Prompt 覆盖或 MCP 配置。
- 受控能力引用必须属于应用内注册白名单；本阶段只定义字段和校验边界，不执行能力。
- MCP 继续保持 Main、Agent 和 Renderer 禁用状态。

## 11. 测试策略

### 11.1 Schema 与转换

- 合法草稿和发布清单。
- 未知字段、重复 ID、非法语义和越界文本。
- 默认皮肤、默认回退状态和可播放链。
- 主状态、修饰状态、共存和禁止规则。
- 动作与皮肤回退循环。
- V1 每类字段无损映射。
- 重复 V1 ID 的确定性重命名与内容保留。
- 素材引用重组但文件不复制。
- 权重转换为偏好，未知自定义状态不猜测语义。

### 11.2 存储事务

- 临时写入、重新读取、备份、替换和索引提交的故障注入。
- 转换失败和重启恢复。
- 并发自动保存与角色切换。
- 保存失败后内存修改保留。
- 活动角色指针在回滚后保持正确。

### 11.3 角色工作室

- 人设字段编辑和限制。
- 皮肤新增、重命名、复制、设为默认和删除。
- 状态与动作新增、复制、删除和引用处理。
- 角色、皮肤、状态和动作切换不丢数据。
- 右栏结构化条件与回退选择。
- 保存、关闭重开、编译和发布后字段完整。

### 11.4 预览与角色包

- 皮肤切换即时刷新并释放旧播放器。

## 12. 完成标准

- 所有新建、保存、编译和导出数据均为 V2。
- 现有本地 V1 和 V1 导入包自动保留并转换。
- 用户可以在现有三栏工作室中编辑结构化人设、多皮肤、自由状态语义和动作约束。
- 默认皮肤、增量覆盖和表现回退可预览、可解释且可持久化。
- 保存、重启、发布和导出再导入不丢字段或素材。
- 转换、保存和导入失败不会产生空角色、半写数据或孤立素材。
- 当前播放器通过只读投影继续稳定运行，动作选择行为不改变。
- MCP、安全文件边界、拖拽和现有 Provider 功能保持不变。
- 本阶段形成下一阶段自主行为引擎可以直接消费的稳定角色契约。
