# AI Pet 角色工作室可靠性改进设计

> 状态：待用户审阅
> 日期：2026-07-30
> 目标分支：`AgentCoreExtension`

## 1. 背景

本设计处理角色工作室中的三类问题：

1. 切换角色、状态或动作后，实时预览仍可能保留上一个角色的画面。
2. 状态与动作区域只能新增动作，缺少符合层级关系的新增与删除入口。
3. 草稿和源素材虽然已经写入应用数据目录，但完全退出并重新启动后，工作室没有完整恢复素材目录，用户被迫重新导入、设置和编译。

本轮只改进角色工作室可靠性。MCP、桌面边缘拖拽、模型目录、自由对话和隐私记忆分别进入后续独立设计。

## 2. 已确认的产品规则

### 2.1 实时预览

- 切换角色、状态或动作时，立即清除旧角色画面，再加载新选择。
- 新选择存在有效帧时，从第 1 帧开始显示和播放。
- 新选择没有动作、没有帧、帧区域无效或素材加载失败时，只显示透明棋盘与明确提示，不保留旧图像。
- 修改帧、素材、帧率、循环、朝向或锚点后，预览立即更新，不要求先保存或编译。
- 快速连续切换时，只有最后一次选择的异步结果可以显示。

### 2.2 状态与动作

- 核心状态固定且不可删除。
- 每个状态都可以新增动作。
- 用户新增的扩展状态可以删除。
- 每个动作都可以删除。
- 空动作直接删除；包含帧的动作需要确认。
- 空扩展状态直接删除；包含动作的扩展状态需要确认。
- 删除动作或扩展状态只删除草稿配置，不删除其引用过的源素材。

### 2.3 保存与恢复

- 编辑后 500ms 自动保存。
- 导入素材成功后立即持久化。
- 切换角色、关闭工作室和退出应用前等待保存完成。
- 保留顶部“保存草稿”按钮，允许用户立即保存。
- 完全退出并重新启动后，自动恢复草稿、右侧属性和完整素材目录。
- 恢复已有草稿不要求重新导入、重新设置或重新编译。

## 3. 现状与根因

### 3.1 旧预览没有及时清除

角色、状态和动作选择已经能够更新到预览组件，预览资源键也包含角色身份。问题出在 Pixi 场景切换边界：

- 空目标路径会请求加载空资源，但没有显式的同步场景清空操作。
- 加载新图片期间，旧精灵仍可能停留在 Canvas。
- 场景释放旧动画后若没有立即渲染，Canvas 仍会显示上一次绘制的像素。

因此界面提示已经切换到“当前动作没有可预览帧”时，旧角色图像仍可能可见。

### 3.2 素材目录没有在启动时恢复

角色草稿、源素材文件和 `source/catalog.json` 已经持久化在 `userData/characters/<角色ID>/`。Main 层的 `CharacterAssetService` 也已经提供安全的 `listSources()` 能力。

Renderer 的 `loadSelectedDraft()` 目前只调用 `getCharacterDraft()`，没有重新枚举素材目录。`availableSources` 只在当前会话导入素材后赋值，并且会被“本次导入结果”覆盖。因此：

- 重启后素材文件仍在磁盘，但工作室显示为没有素材。
- 同一会话多次导入时，旧素材也可能从当前列表中消失。
- 用户会误以为数据丢失并重复导入。

### 3.3 缺少删除领域操作

角色工作室 Store 目前只有 `addAction()` 和 `addExtensionState()`，没有删除动作或删除扩展状态的领域操作。`StateList` 也只负责选择状态和动作，无法表达新增、删除和确认规则。

## 4. 方案选择

采用定向修复现有链路，不重建工作室架构，也不修改角色数据格式。

未采用的方案：

- 通过 React `key` 在每次切换时销毁并重建整个预览：实现简单，但会重复初始化 WebGL、产生闪烁，且不能解决素材恢复。
- 新建统一角色工作区快照协议：一致性更强，但会扩大 IPC 和数据结构变更，不符合本轮最小修改原则。

## 5. 架构与数据流

### 5.1 Main

- 继续以 `userData/characters/<角色ID>/` 为唯一角色数据源。
- 复用 `CharacterAssetService.listSources(characterId)`。
- 通过角色 IPC 服务暴露只读的素材目录查询。
- 不新增数据迁移，不修改草稿、素材目录或编译清单格式。

### 5.2 Preload 与共享协议

新增白名单方法：

```ts
listCharacterSources(characterId: string): Promise<ImportedWorkshopSource[]>
```

输入继续使用现有角色 ID 校验。输出只包含工作室需要的公开元数据：

```ts
interface ImportedWorkshopSource {
  assetId: string;
  displayName: string;
  mimeType: 'image/png' | 'image/webp';
}
```

不得通过该接口暴露绝对文件路径。

### 5.3 Renderer Store

`loadSelectedDraft(characterId, requestRevision)` 同时读取：

- `getCharacterDraft(characterId)`
- `listCharacterSources(characterId)`

两项都成功且请求修订仍然有效后，一次性更新：

- `selectedCharacterId`
- `draft`
- `selectedStateId`
- `selectedActionId`
- `availableSources`

旧请求晚返回时不得覆盖新选择。加载失败时显示错误，不使用空草稿或空素材目录覆盖当前稳定工作区。

素材导入成功后不再直接使用本次导入数组覆盖 `availableSources`，而是重新查询该角色的完整素材目录。

## 6. 预览生命周期

### 6.1 场景接口

为 `PixiCharacterScene` 增加显式清空能力。清空操作必须：

1. 停止 ticker。
2. 移除当前精灵和帧纹理。
3. 清除当前动作引用。
4. 立即渲染空场景。
5. 通知依赖当前帧的消费者。

清空不销毁 Pixi Application，也不销毁仍由资源加载流程管理的缓存对象。

### 6.2 切换过程

角色、状态或动作身份发生变化时：

1. 增加加载修订。
2. 取消旧加载。
3. 同步清空场景和当前预览状态。
4. 若目标无有效动作，保持空场景并显示原因。
5. 若目标有效，异步加载素材。
6. 只有仍匹配当前加载修订的结果可以显示。
7. 过期结果必须释放资源。

帧率、循环、朝向、锚点等同一动作内的修改继续复用现有场景，不触发无意义的 WebGL 重建。

## 7. 状态与动作界面

### 7.1 工具栏

移除顶部工具栏中的：

- “添加动作”
- “扩展状态”

保留新建角色、导入角色包、导入素材、保存草稿、导出角色包、编译并发布和启用角色。

### 7.2 左侧列表

- “状态与动作”标题行末尾显示加号，用于打开扩展状态创建对话框。
- 每个状态行末尾显示加号，用于向该状态新增动作。
- 扩展状态行显示减号，用于删除该扩展状态。
- 核心状态行不显示状态减号。
- 每个动作行末尾显示减号，用于删除该动作。
- 所有图标按钮提供中文 `aria-label` 和悬停说明。
- 工作室处于忙碌状态时，相关按钮禁用。

### 7.3 删除与回退

动作删除：

- 无帧动作直接删除。
- 有帧动作使用现有 `<dialog>` 风格确认。
- 确认内容显示动作名称和帧数。
- 删除当前动作后，优先选择同状态中的下一个动作，其次选择前一个动作。
- 状态没有剩余动作时，选中动作设为 `null`，预览进入空状态。

扩展状态删除：

- 没有动作时直接删除。
- 包含动作时使用现有 `<dialog>` 风格确认。
- 确认内容显示状态名称和动作数量。
- 删除当前扩展状态后，回退到第一个核心状态及其首个动作。

删除完成后：

- 草稿修订增加。
- 草稿状态变为 `dirty`。
- 进入现有 500ms 自动保存链路。
- `availableSources` 保持不变。

## 8. 持久化与退出

- 所有动作属性、帧、锚点和状态结构修改继续使用现有自动保存。
- 手动保存立即刷新当前草稿修订。
- 切换角色前必须保存脏草稿；保存失败时保留当前角色。
- 关闭工作室和退出应用继续复用现有 Main/Renderer 刷新握手。
- 编译发布必须使用最后一次成功保存的稳定修订。
- 已保存草稿的恢复不依赖编译结果。
- 已发布运行版本不因草稿编辑而自动变化。

## 9. 错误处理

- 草稿读取失败：保留当前稳定工作区并显示草稿读取错误。
- 素材目录读取失败：不把素材列表改为空，显示素材目录恢复错误。
- 单个动作引用的素材缺失：保留动作和帧配置，预览显示“预览素材读取失败”或更具体的素材缺失提示。
- 快速切换产生的过期请求：静默释放，不显示错误。
- 自动保存失败：沿用现有错误状态和提示队列，手动保存仍可重试。
- 删除确认取消：不改变草稿、选择、预览和素材目录。

## 10. 测试设计

### 10.1 Pixi 单元测试

- 清空场景会停止 ticker。
- 清空场景会移除精灵和帧纹理。
- 清空场景会立即渲染。
- 清空后当前帧和命中快照为空。

### 10.2 预览组件测试

- 切换角色时旧场景立即清空。
- 切换到无动作或无帧目标时不保留旧画面。
- 加载失败后保持空场景。
- 快速连续切换只显示最后一次结果。
- 同一动作属性修改继续即时刷新且不重复读取相同素材。

### 10.3 Store 测试

- 启动和切换角色时同时恢复草稿与完整素材目录。
- 乱序草稿或素材响应不能覆盖较新选择。
- 多次导入后重新读取完整素材目录。
- 删除动作和扩展状态遵守权限、确认与回退规则。
- 删除配置不改变素材目录。
- 删除操作进入自动保存链路。

### 10.4 UI 测试

- 顶部不再显示“添加动作”和“扩展状态”。
- 标题、状态和动作行显示正确的加减号。
- 核心状态没有删除入口。
- 图标按钮具有中文无障碍标签。
- 非空删除使用确认对话框。

### 10.5 IPC 与 E2E

- 素材枚举 IPC 拒绝非法角色 ID。
- Preload 只暴露白名单方法。
- Electron E2E 创建角色、导入素材、配置动作、等待保存、完全退出并重新启动。
- 重启后验证草稿、素材、预览和右侧属性全部恢复。
- 最终执行桌面端类型检查、单元测试、安全测试和角色相关 E2E。

## 11. 范围边界

本轮不处理：

- 素材删除、垃圾回收或未引用素材清理。
- 角色包格式、运行时清单格式和用户数据迁移。
- MCP 模块禁用。
- 桌宠屏幕边缘拖拽。
- 模型目录更新。
- 自由对话策略。
- 长期记忆、本地长期记忆和主动性选择。

这些事项按照已确认的项目拆分顺序分别设计和实施。

## 12. 验收标准

- 切换角色、状态或动作后不再显示旧角色残影。
- 无帧或加载失败时 Canvas 保持清空并显示明确提示。
- 顶部旧新增按钮移除，左侧加减号符合已确认层级。
- 核心状态不可删除，扩展状态和动作按内容决定是否确认。
- 删除配置不删除源素材。
- 完全退出并重新启动后，草稿、动作属性、帧、锚点和素材目录自动恢复。
- 用户无需重新导入、重新设置或重新编译即可继续编辑。
- 快速切换、保存失败和素材缺失均不会用空数据覆盖已有磁盘数据。
