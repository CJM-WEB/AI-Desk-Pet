# AI 桌宠参考架构吸收与自主陪伴体系演进设计

> 文档状态：已确认设计
> 基准日期：2026-08-01
> 目标分支：`AgentCoreExtension`
> 设计路线：自有体系优先、参考成熟项目、小步纵向交付

## 1. 文档目的

本文定义 AI 桌宠下一阶段的架构演进方向。项目继续以既有 Electron、React、TypeScript、Pixi、Agent Core、角色运行时和安全文件工具为唯一产品与技术主线；外部开源项目仅作为问题案例库、架构参考和兼容接口参考，不作为新的项目骨架。

本文覆盖以下已确认目标：

1. 用户能够高自由度定义角色、皮肤、状态和动作。
2. 桌宠通过本地状态引擎与 Agent 语义判断，自主决定当前状态与动作。
3. 桌宠能够以角色化动画表现真实文件操作，包括将文件“搬运”到系统回收站。
4. 桌宠不永久置顶；准确前台 Explorer 可建立动态相邻层级，其他应用前台时自然覆盖桌宠。
5. 桌宠能够自由聊天，不被限制为文件助手。
6. 优先建立本地长期记忆、角色关系记忆和可选择的主动性。
7. 模型目录不再依赖应用内写死列表，采用服务商发现、可更新目录和手动模型 ID。
8. 语音与未来桌面自动化通过可选适配器接入。
9. MCP 当前继续禁用但保留代码，未来恢复必须另行完成安全设计。

## 2. 基本原则

### 2.1 自有体系优先

- 不整体迁入其他项目的框架、运行时或 AgentOS。
- 不因参考项目采用 Python、Unity 或独立后端而替换当前主技术栈。
- 先复用现有模块，再以最小改动补充契约和适配层。
- 外部项目的概念必须重新映射到本项目的安全、隐私和产品边界。

### 2.2 角色定义能力，桌宠自主决策

用户负责定义角色“能做什么”和动作所表达的语义；桌宠负责结合环境、对话、记忆、性格和当前任务决定“现在应该做什么”。旧权重机制保留为偏好与离线回退，不再直接决定行为。

### 2.3 默认安全而非默认全能

- 文件操作只作用于用户授权范围。
- 删除默认进入系统回收站，第一阶段不开放永久删除能力。
- 角色包不能携带任意脚本或提升系统权限。
- Agent 不能绕过动作调度、文件授权或操作确认。
- 截图、麦克风、桌面控制与主动行为均由用户单独授权。

### 2.4 可选能力必须能够降级

模型、记忆、语音、资源管理器观察或未来自动化执行器失效时，基础桌宠、基础角色动作和普通文字交互仍应工作。

参考方式分为三级：

1. 设计吸收：重新实现状态、事件、记忆、权限和调度思想。

3. 局部代码复用：仅在许可证兼容、技术栈匹配、边界清晰且明显优于现有实现时采用，并记录来源与修改情况。

AGPL、专有许可、许可不明和来源不明的角色、模型、动作、声音及图片素材不得进入仓库。

## 4. 总体架构

现有 Electron 主进程继续负责系统能力与安全边界，preload 继续提供最小化、强类型 IPC，React Renderer 继续负责桌宠、聊天、设置和角色工作室，Pixi 继续负责当前序列帧角色表现。

在现有模块上补充四个逻辑层次；这些是职责边界，不要求一开始拆成四个新包。

### 4.1 角色定义层

声明角色身份、人设、皮肤、状态、动作、语义、表现约束、文件交互表现与可选能力。

### 4.2 自主行为层

接收本地事件、对话语义和陪伴认知状态，完成状态推断、候选动作生成、硬约束过滤、偏好排序、动作调度和结果反馈。

### 4.3 陪伴认知层

负责自由聊天、共享用户档案、角色关系记忆、情节记忆、行为偏好和主动性调度。

### 4.4 外部能力层

封装安全文件工具、模型服务、未来语音服务、Windows UIA、浏览器接口和视觉执行器。任一能力都必须独立授权、可禁用、可降级。

核心依赖约束：

- Agent 只能提出结构化状态和动作意图，不能直接指定素材路径或绕过调度器。
- 角色包只能定义表现与能力需求，不能获得系统权限。
- 外部执行器不能直接修改角色存储、记忆或隐私设置。
- UI、角色、Agent 和工具仅通过明确的数据契约通信。

## 5. 角色包 V2

### 5.1 角色结构

角色包 V2 逻辑上包含：

- 角色身份、人设与语言风格。
- 一个或多个皮肤。
- 可扩展状态定义。
- 可扩展动作定义。
- 动作语义、行为偏好和回退关系。
- 文件交互动作映射。
- 可选音色、口型和未来渲染能力声明。

角色工作室仍是主要编辑入口。普通用户使用表单和可视化编辑，高级用户可以导入导出完整角色包。

### 5.2 皮肤

皮肤只决定“如何表现”，不决定角色为什么执行动作。同一语义动作可以由不同皮肤绑定不同素材。缺失素材时依次回退：

1. 当前皮肤的精确动作。
2. 当前皮肤的同类通用动作。
3. 默认皮肤的精确动作。
4. 默认待机动作。

切换皮肤不切换角色身份、记忆、关系和行为偏好。

### 5.3 状态

状态名称不写死在程序中。状态至少包含标识、名称、语义说明、类别、强度、建议持续时间、共存规则、进入与退出条件、允许或禁止的动作标签、Agent 是否可推断和离线回退条件。

角色可以同时拥有活动、情绪、环境和任务等不同类别的状态。拖拽中、动作播放中、退出中等少量运行状态由系统保留，其余表现状态允许扩展。

### 5.4 动作

动作由语义、表现和执行约束组成。动作可以是纯表现动作、用户交互动作或受控任务动作。约束包含持续时间、冷却、循环、可中断性、适用状态、禁止条件、关键帧和失败回退。

任务动作只能引用应用注册的受控能力，不能携带任意脚本、命令或权限声明。

## 6. 自主行为引擎

### 6.1 混合判断

采用已确认的混合方案：

- 本地状态引擎负责拖拽、移动、动作生命周期、闲置、全屏、勿扰、资源管理器目录与文件任务结果等明确事件。
- Agent 只在对话、任务转折、主动性触发或复杂语义无法由确定规则判断时输出高层结构化意图。
- 模型不可用时，本地状态与旧权重回退保证桌宠仍可活动。

Agent 意图仅包含状态意图、动作语义、紧急度和解释，不包含素材路径、系统命令或未经授权的文件操作。

### 6.2 决策顺序

候选动作依次经过：

1. 当前动作中断规则。
2. 状态和环境硬约束。
3. 素材与能力可用性。
4. 冷却时间。
5. 重复抑制。
6. Agent 语义匹配。
7. 角色性格与行为偏好。
8. 主动性和隐私设置。
9. 旧角色包权重。

### 6.3 调度和反馈

- 同一时间只有一个主动作控制角色身体。
- 表情、音频和气泡可以受控并行。
- 用户直接交互可以打断普通待机。
- 文件任务关键阶段不受随机动作干扰。
- 中断必须存在明确收尾或回退。
- 无可用动作时回退到默认待机。
- 第一版只使用行为反馈降低重复与打扰，不未经允许永久改写角色配置。

## 7. 文件实体交互

### 7.1 回收站搬运事务

删除请求采用以下事务阶段：

1. Agent 解析用户意图。
2. 文件工具解析、规范化并验证目标。
3. UI 展示目标和影响范围，请求确认。
4. 桌宠播放拾取和搬运动作。
5. 到达配置的提交关键帧时调用系统回收站能力。
6. 根据真实结果播放成功或失败分支。

确认前不得改变文件；真实操作失败时不得播放成功结果。Windows 端优先复用 Electron 主进程已有的系统回收站能力，不引入新的高权限常驻服务。

### 7.2 文件安全

- 只处理用户授权目录中的目标。
- 确认前与执行前分别验证路径和目标身份。
- 防止路径穿越、符号链接和目录联接绕过授权根。
- 批量、覆盖和移动操作单独展示影响并确认。
- 移入回收站与永久删除是不同能力。
- 第一阶段不开放永久删除。
- 审计只记录操作元数据，不记录文件内容。

角色包可以定义动画、关键帧、音效和结果表现，但不能配置命令、授权或伪造结果。

## 8. Explorer 动态窗口层级

2026-08-10 产品决策：目录藏身、目录授权、呼唤、召回、迷路恢复和目录角色表现全部退役。旧 `habitat.json` 不读取、不迁移，也不由本次变更主动删除。历史计划与人工记录只保留当时证据，不追认为已通过。

保留能力只负责 Windows Explorer 相邻 Z 序：

1. 固定 bridge/helper 识别准确的前台、非最小化 Explorer 实例，但不读取、采集或传输当前目录路径。
2. Main 内的严格协议只接收实例、外层 HWND、矩形、前台、最小化与单调序列事实；Renderer、preload、Agent、日志和 E2E 控制面均不接收私有 HWND 或路径。
3. 准确快照通过 Electron `moveAbove` 把桌宠放到对应 Explorer 上方；不恢复 User32 层级回退。
4. 非 Explorer、失焦、最小化、歧义、桥错误和层级错误均不调用显示、隐藏、聚焦、移动坐标或全局置顶。
5. 桌宠窗口始终保持 `alwaysOnTop: false`。普通应用获得前台时由 Windows 自然覆盖桌宠；切回 Explorer 后可由新鲜准确快照重新建立相邻层级。

设置页与托盘不再提供任何目录空间入口，角色行为契约也不再包含 `hide`、`emerge` 或 Habitat 专用语义。

## 9. 自由聊天与 Chat/Work 协作

Agent 将输入区分为陪伴聊天、信息协助和任务执行。用户无需频繁手动切换模式，但真实操作前必须显示当前状态并遵守权限与确认。

Chat 和 Work 共享同一角色人格、当前会话、授权记忆与情绪状态。普通聊天默认不加载文件或桌面工具；只有明确进入任务流程时，才按需加载当前任务所需能力。意图不确定时继续对话或询问，不擅自执行。

## 10. 本地长期记忆

### 10.1 记忆范围

采用“共享用户档案 + 角色独立关系记忆”：

- 用户明确允许共享的称呼、语言和通用偏好可以跨角色使用。
- 对话经历、关系变化、约定和情感记忆只属于当前角色。
- 文件内容、路径、截图、剪贴板和任务参数默认不进入长期记忆。
- 皮肤切换不切换记忆。
- 复制角色默认不复制关系记忆。
- 删除角色时单独询问是否删除其关系记忆。

### 10.2 记忆分层

逻辑上分为当前上下文、共享用户档案、角色关系记忆、重要情节记忆和行为偏好。每条长期记忆保存内容摘要、作用域、来源、时间、重要性、可信度、最近使用时间、用户是否明确要求记住及修正状态。

### 10.3 写入、冲突和遗忘

- 用户明确要求记住时形成待保存记忆。
- 自动发现的稳定偏好按隐私设置自动保存或先询问。
- 普通聊天不全部转成长久记忆。
- 写入前进行敏感性、作用域、去重和冲突检查。
- 用户明确纠正优先于模型推断。
- 低可信新信息不覆盖高可信记忆。
- 用户要求遗忘时立即从可检索记忆移除。

### 10.4 检索和本地边界

检索按相关性、重要性、时间、角色范围和可信度选择少量记忆，不把完整历史持续注入模型。长期记忆只保存在本机；若云端模型参与摘要，隐私页面必须明确提示相关数据会发送给当前模型提供商。

隐私页优先提供总开关、本地存储状态、共享档案、按角色查看、搜索、修改、遗忘、清空、导出、数据位置和空间占用。

## 11. 主动性

主动性提供关闭、轻度、标准、活跃和自定义等级，并允许分别控制主动发言、主动动作、提醒和系统状态感知。

主动性调度器只生成建议，最终动作仍由自主行为引擎决定。主动行为必须遵守安静时间、全屏、勿扰、冷却、每日上限和用户反馈。连续被关闭或忽略后降低频率。主动性不能替代文件与桌面操作权限，也不依赖持续截图。

## 12. 统一能力适配

能力描述包含标识、类型、状态、操作、权限、网络需求、敏感数据、提供商和降级方式。状态至少包括不可用、已禁用、准备中、可用、降级和错误。

Agent 只看到当前启用且与任务有关的能力，避免普通聊天长期携带所有工具描述。

## 13. 模型目录

采用已确认的三级机制：

1. 优先调用服务商正式接口发现用户账号实际可用模型。
2. 对无法可靠发现的服务商使用可独立更新且经过签名校验的模型目录。
3. 始终允许手动输入模型 ID。

内置目录只作离线保底。统一目录记录普通对话、推理、视觉、工具调用、结构化输出、长上下文和本地离线等能力，不仅通过名称猜测。未知模型默认采用保守能力，用户可以覆盖并在连接测试后保存。

远程目录只包含公开元数据，不包含密钥，也不得注入代码、提示词或工具定义；校验或更新失败时使用上一次有效目录。

## 14. 语音适配

语音流水线拆分为 VAD、ASR、Agent、文本分段、TTS、音频播放和角色表现同步。各环节可独立替换、关闭和降级。

- 用户讲话可以中断当前 TTS、未播放片段和说话动作。
- TTS 失败时保留文字回复。
- ASR 失败时仍可键盘输入。
- 当前皮肤没有口型时回退到普通说话动作。
- 麦克风与持续监听必须明确授权。
- 角色包只能声明音色和表现映射，不能运行语音脚本。

## 15. 未来桌面自动化

桌面能力按风险从低到高选择：

1. 当前结构化文件工具。
2. 应用正式 API 或浏览器接口。
3. Windows UI Automation、Win32 或 COM。
4. 局部截图与视觉定位。
5. 绑定目标窗口的鼠标键盘执行。

自动化采用“计划—授权门—最低风险执行器—单步执行—结果验证—审计”链路。执行器独立运行，Renderer 不获得系统控制权限，Agent Core 只发送结构化请求。默认不开放任意 Shell、不持续截图、不在支付、密码和系统安全界面自动操作。

## 16. MCP 策略

当前继续保持：

- 不删除 MCP 源码、IPC、preload、配置和存储结构。
- 不初始化或连接 MCP 服务。
- 不向 Agent 注册 MCP 工具。
- Renderer 不展示可启用入口。
- 角色包、模型响应和远程目录均不能启用 MCP。

未来恢复 MCP 必须另行设计服务器信任、权限映射、工具审核、会话隔离和用户交互，并重新获得批准。

## 17. 兼容与迁移

### 17.1 角色包 V1 到 V2

- V1 加载时先在内存中兼容转换。
- 原状态、动作、素材、FPS、锚点、循环和权重全部保留。
- 权重映射为动作偏好。
- 已知内置状态补充保守语义，未知自定义名称不自动改名。
- 用户明确保存或升级时才写入 V2。
- 写入前保留可恢复的原版本。
- 迁移失败继续加载 V1，不生成空白角色。

### 17.2 本地数据

角色、记忆、主动性和空间状态使用独立数据版本。迁移采用事务或新文件写完后的原子替换；失败时不得覆盖旧数据。无法识别的新版本进入只读保护，不静默清空。

## 18. 故障与降级

| 故障 | 回退 |
| --- | --- |
| 角色包损坏 | 隔离原文件并加载默认角色 |
| 动作素材丢失 | 回退同类动作或默认待机 |
| 自主决策失败 | 使用本地状态与旧权重 |
| 模型不可用 | 保留基础桌宠和本地行为 |
| 记忆写入失败 | 继续聊天并明确提示未保存 |
| 语音失败 | 退化为文字 |
| 文件操作失败 | 保留真实文件状态并播放失败反馈 |
| Explorer 检测失败 | 保持普通可见窗口，不调整相邻层级 |
| Explorer 层级调整失败 | 保持可见且非 topmost，等待新鲜快照恢复 |
| 自动化执行器崩溃 | 终止任务，不影响桌宠主程序 |
| 模型目录异常 | 使用上次有效目录或离线目录 |

## 19. 性能约束

- 本地状态引擎事件驱动，不高频轮询。
- Agent 不参与逐帧判断。
- Explorer 观察仅发布无路径窗口事实，错误时退化为普通窗口层级。
- 不持续截图或持续调用视觉模型。
- 记忆检索限制数量和注入长度。
- 模型目录缓存并条件更新。
- 语音和自动化组件延迟加载。
- 基础桌宠不依赖模型或网络维持流畅运行。

## 20. 测试重点

### 20.1 角色与行为

- V1/V2 解析和迁移。
- 自定义状态共存、进入和退出。
- 动作语义匹配、冷却、中断和重复抑制。
- 无效 Agent 意图的安全回退。
- 皮肤素材缺失回退。
- 固定随机种子下行为可重现。

### 20.2 文件安全

- 未授权路径、路径穿越、符号链接和目录联接。
- 确认后目标变化。
- 单文件、多文件、移动、覆盖和回收站操作。
- 动画中断不重复执行。
- 系统结果与角色反馈一致。
- 永久删除保持不可用。

### 20.3 目录与窗口

- 准确目录、上级目录、搜索结果和多个资源管理器窗口。
- 最小化、关闭、失焦、切换目录和目录失效。
- 重启后隐藏状态恢复与托盘召回。
- 四边四角、多显示器负坐标、DPI、任务栏方向与全屏。
- 临时置顶结束后恢复正常层级。

### 20.4 记忆与模型

- 共享档案与角色记忆隔离。
- 皮肤切换、角色复制和角色删除。
- 敏感文件信息默认不入长期记忆。
- 查看、修正、遗忘、清空和迁移失败保护。
- 服务商发现、签名失败、离线缓存和手动模型 ID。
- 未知模型采用保守能力。

## 21. 分阶段交付

### 阶段 0：当前分支基础收尾

- 完成 Renderer 中 MCP 入口隐藏。
- 修复左上角、边缘与多显示器拖拽。
- 回归角色工作室预览、状态动作增删和素材持久化。
- 更新明显滞后的内置模型目录。

### 阶段 1：角色包 V2 与行为契约

- 建立状态、动作、皮肤和能力契约。
- 完成 V1 只读兼容转换。
- 将旧权重降级为行为偏好。
- 暂不改变现有角色实际表现。

### 阶段 2：自主行为最小闭环

完成“本地事件—状态推断—Agent 语义—动作筛选—调度—反馈”的纵向闭环，首批覆盖待机、倾听、思考、移动、成功和错误，再开放任意新增状态与动作。

### 阶段 3：文件实体与 Explorer 动态层级

- 回收站搬运任务动作。
- 动画提交点与结果分支。
- 无路径 Explorer 窗口识别与动态相邻层级。
- 目录藏身、托盘呼唤和迷路恢复已于 2026-08-10 退役，不属于完成条件。

### 阶段 4：陪伴认知

- 自由聊天与任务意图分流。
- 共享用户档案和角色长期记忆。
- 记忆管理界面。
- 主动性等级、安静时间、冷却和打扰控制。

### 阶段 5：模型与语音

- 服务商模型发现、签名目录和手动模型 ID。
- 语音适配接口、ASR/TTS、打断和文字降级。
- 角色音色和说话动作映射。

### 阶段 6：桌面自动化

- 另行完成 Windows 结构化执行器的详细安全设计。
- 按 API、UIA、视觉顺序逐级接入。
- MCP 继续禁用，除非另行设计并批准。

## 22. 交付规则

每个阶段必须：

1. 先建立失败测试或可复现验证。
2. 以最小代码修改完成可见的纵向能力。
3. 执行相应单元、集成、构建和必要的 Windows 验收。
4. 不覆盖用户的无关改动。
5. 记录迁移影响和实际修改文件。
6. 使用独立提交，不混合多个阶段。
7. 用户验收后再推进下一阶段。
8. 单点超过约定时间仍无实质进展时，切换路线或降低非核心约束，但不能静默跳过。

## 23. 完成标准

当本文所述路线完成时，产品应达到以下结果：

- 用户能够自由创建角色、皮肤、状态和动作。
- 桌宠能够稳定、自主且可解释地选择状态与动作。
- 旧角色包无数据损失地继续运行。
- 桌宠可以通过动画完成受控文件任务并将删除目标移入回收站。
- 桌宠可在准确前台 Explorer 上方建立非 topmost 相邻层级，并在其他应用前台时自然被覆盖。
- 桌宠能够自由聊天，拥有本地、可管理、按角色隔离的长期记忆。
- 用户能够明确选择主动性，不受到不可控打扰或持续监视。
- 新模型可以通过服务商发现、目录更新或手动 ID 及时使用。
- 语音和未来桌面自动化作为可选能力接入，不破坏基础桌宠。
- MCP 在当前阶段保持禁用，现有安全边界不因扩展能力而后退。
