# 普通聊天真实流式修复

用户已要求仅检查并修复 DeepSeek、内置 Qwen 的流式输出，并要求气泡随增量自适应大小。本次以该明确要求为实施授权，不扩展桌宠功能。

本规格仅替代[Qwen 单次判别规格](2026-09-10-qwen-conversation-decision-design.md)中正式聊天固定 `stream:false` 的传输限制；有正文回调时使用 SSE，无回调及独立表现仍保持非流式。原单次判别、严格分支和全部任务边界不变。

## 现状与范围

- OpenAI 兼容 Provider 等待完整 JSON；本地 Qwen 固定关闭流式。
- 普通聊天适配器未转交已有 `onTextDelta`，协调器在完整响应后才发布缓存的增量。
- 气泡已有按正文排版、快照修订重测与 ResizeObserver，需用实际增量验证其尺寸变化。

## 实施契约

1. 复用已有正文增量回调与 start/delta/commit 事件，直接呈现网络 SSE 的正文片段，不做完整回复后的模拟打字。
2. DeepSeek 只呈现 content；工具参数与 reasoning 不进入正文。本地 Qwen 保留严格私有 chat/task JSON 判别，只增量解码 chat 的 text，完整返回仍执行原校验。
3. 不改变模型选择、提示词任务语义、授权判断、文件执行、表现决策、会话保存规则。完整成功正文才进入历史；取消、错误、旧会话迟到片段不能提交。
4. 原生工具响应可能先发正文再发工具片段；完整结果仍以原有工具判定为准。进入任务准备时复用 thinking 阶段撤销未提交草稿，不把它当作已执行结果或正式历史。
5. 气泡随每次正文增量更新排版与原生交互区域，长文本达到既有上限后滚动，完成后才开始三十秒倒计时。
6. 增量协议和展示归并与原聊天上限一致，按四千 Unicode 码点计数，避免合法 emoji 长回复在启用流式后被错误丢弃。

## 实施与验收顺序

- Provider 子任务：先受控 SSE 门控失败测试，再实现传输及 Qwen 正文安全解码。
- 主链：先证明完整响应仍被挂起时已能观察首段/后续段，再接通适配器与协调器。
- 气泡：验证逐段快照的重新测量；若既有机制已满足则不重复增加机制。
- 仅运行相关 Provider、聊天增量、气泡测试与桌面类型检查/构建，不执行角色、模型切换等无关回归，不调用真实模型或读取密钥。
- 记录实际验证结果。真实服务首 token 延迟和 Windows 用户桌面的视觉体验仍以实际使用为准。
