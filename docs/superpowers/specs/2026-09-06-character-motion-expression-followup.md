# 自定义状态的情境资格、有限表现与运动同步

2026-09-08 更新：活动优先、模型与宿主时间职责、无匹配处理及运动准备改按[单一入口与独立表现决策](2026-09-08-single-send-expression-isolation-design.md)实施。本文允许无动画时使用 idle 位移的降级规则已被用户明确否定；历史观察与未冲突边界保留。

日期：2026-09-06。状态：**用户已要求继续开发，并明确必须覆盖任意自定义状态和动作；按同步优先实施，实际结果另记验收记录**。

依据：[现行角色规格](2026-09-05-ai-pet-custom-state-autonomy-design.md)第 6、8 节；真实证据见[验收记录](../../operations/2026-09-06-custom-state-autonomy.md)。本补充覆盖所有作者状态／动作的候选资格和结束逻辑，替代先前 `whenMoving` 单一字段提案，不改变角色包契约。

## 已证实的问题

真实用户角色发布修复后，“播放运动状态”能播放跑步动画并约 3 秒回 idle；“向右走一点”也能实际完成 49 DIP 相对位移。但整段位移仍是 idle。“进入运动状态”的明确入口修复后仅播放动画，后续模型计划却继续选择跑步，观察期内未回 idle。当前 Main 在模型请求前启动短移动，模型选好动画时可能早已到达；表现计划也无法持续约束“仅在移动中适用”。

仅收到 `move-start` 或 `move-stop` 边沿不足以解决：它们只过滤已有候选；停止之后到达的计划仍可能重新播放跑步。不能给作者状态强加官方 `move` 语义，也不能根据名称本地猜选。

## 通用情境条件

1. 保持唯一表现计划。状态候选和动作候选各增加可选 `when`，仅允许 `moving`、`dragging`、`carrying`、`chatting`、`taskRunning`、`awaitingConfirmation` 六个布尔键；出现的条件必须全部满足。省略或空对象表示不限。它们是已有 Main 事实，不是官方状态类别或能力授权。新增事实须显式扩展类型及 Main 来源，不能接受自由脚本、路径或任意 JSON。
2. Main 用当前可信事实同时筛选状态和动作。事实变化立即复核当前动作；不再适用时越过普通两秒保持和作者中断偏好，切换为合格候选或 idle。动作冷却、资源、合法归属仍有效；不能通过失败回退、同状态续播或默认动作绕过条件。明确指定动画可以越过模型条件在原地播放，绝不反向授权位移。
3. 同一模型请求根据现有人设、状态与动作描述提出条件候选。既有 `runtime.moving` 保持真实值；若 Main 已解析尚未执行的移动，额外传递有界的待执行意图标记，不能伪称已经移动。
4. 仍使用 DeepSeek／Qwen、原 Provider 与原有无工具聊天请求，不增逐帧或高频模型调用，不建立第二套语义映射或缓存引擎。

内置 Qwen 使用的固定 llama.cpp 不支持 Schema 的 `if/then/else`。输出 Schema 约束字段、类型和枚举；`condition` 必须有真活动条件等关联规则由 Main Zod 强制校验，并在同一模型请求中明确解释。复用原分区失败处理，不以生成约束替代本地裁决。依据：[固定版本语法说明](https://github.com/ggml-org/llama.cpp/blob/b95502ba9aa0eb73a2f4fc8878d7fbe6a847a0b9/grammars/README.md#json-schemas--gbnf)。

模型生成契约要求状态显式填写 `when` 和 `lifetime`，无条件表现填 `{}` 与 `episode`；Main 仍接受旧计划省略字段。一次修复只接收本地生成的有界错误路径和原因，不回传坏输出全文。预算紧时保留完整用户正文，省去可选修复预留；实际请求和修复各自仍受原上限约束。这些结构约束不能保证模型总能正确理解作者描述，实际模型选择质量单独记录。

## 有限表现与持续活动

- 模型状态候选增加 `lifetime: "episode" | "condition"`，缺省 `episode`。普通情绪表现按作者状态建议时长播放，缺省 3 秒，最少 2 秒；按状态进入时刻计时，不能被动作轮换不断刷新。结束后该状态休息 10 秒，再按仍有效的心情、强度和条件考虑是否再次出现；也可以选另一合格状态。心情独立衰减，不因动画结束清空。
- `condition` 仅允许状态 `when` 至少包含一个值为 true 的可信活动条件，适用于真实活动持续期间的表达。它仍受条件、计划有效期、资源和心情资格限制；用于运动时停止就退出，不因短暂动作结束产生 idle 空档。只有 `moving:false` 等否定条件不能申请持续占用。
- 明确动作默认完整一遍，明确状态缺省 3 秒；同轮模型计划不能在结束后立即或迟到重新激活刚完成的明确状态。其余心情候选仍可用；后续新互动可以再次明确播放。保留原 token／上下文关联，不能靠名称屏蔽动作。
- idle 始终是可播放兜底，不受模型条件或上述情绪休息期阻挡。作者硬冷却保持有效，没有可播放动作时仍使用既有合法静止帧策略。

## 同步优先的执行时序

已有合格运动表现计划时立即移动；没有计划时先等待同轮模型，接纳条件候选后启动原位移，靠真实移动边沿切动画。匹配必须有明确的 `when.moving:true` 状态或动作依据，不能把任意无条件开心动作算作匹配。停止移动始终立即执行。

同步查询必须按当前的明确播放、保持时间、状态得分和实际动作候选作出保守判断；存在一个活动候选，不代表它会被选中。无法证明真实事实更新后的实际播放满足所需条件时继续等待或到原截止明确降级，不提高候选分数或绕过作者规则来制造匹配。

持续／间断运动三态设置继续独立工作，现有计划可在每次真实运动边沿重新适用；本轮不为它新增模型请求。首次尚无匹配计划时允许用 idle 降级，不能宣称已有对应动画。

同步优先需要复用 Director 现有唯一 pending 槽，保存 Main 已解析的精确请求、来源和轮次标记。相对方向与距离不再转换为区域目标；提交时先清槽，不能重复执行。新输入、停止、取消、拖拽、角色／Provider／配置变化、reset、close、转入文件任务或确认流程均清除待执行位移；迟到结果不恢复它。

无模型、无匹配或普通请求失败时保留 Main 已明确解析位移的降级能力，并发出已有表现不可用提示；取消与失效不触发降级。等待截止复用现有 Main 推进，上限 8 秒，到期仍未匹配则执行已授权位移，不创建额外后台循环。模型提出的一次运动仍只在该轮成功后提交，错误不能执行未经明确入口接纳的运动。聊天请求正在等待并不等于文件任务；真正进入任务／确认流程会撤销等待。

模型成功返回时，心情淡入可能尚未达到候选区间。因此“收到计划”不能替代“当前可播放”：明确位移仍在原来的八秒预算内等待真实资格，既有推进发现合格便执行；不重新计时，也不删除模型强度条件。模型失败可直接走原明确请求降级。这一时序同样适用于以后新增的条件表现。

Main 的自然到期与 Renderer 的终态回报可能交错。宿主只对自己确实发布、刚结束且动作和时间匹配的有界播放记录接纳无副作用的迟到终态；不推进第二次，不重新播放，不更新最近动作。陌生令牌、迟到 started、错动作和非法时间继续拒绝。角色切换、reset 与 close 清空这些记录。

## 修改与验收边界

实际窗口补充：`pendingMovement` 只表示 Main 已接纳位移请求，不能在模型提示里泛称动作“已处理完成”。请求应在候选旁明确本轮仍需按描述选择未来活动的表现，保留真实 `moving:false`。普通推断候选排除 `agentInferable=false` 对象，明确播放仍可查找它们。独立心情、情绪候选和空计划保持合法；不能因没有活动素材而强制伪造候选或抛弃合法情绪。以上仅澄清原职责与合法候选范围，不加入名称映射、模型分数修正或新的执行路径。

预计只改角色计划 Schema／引擎、Main Service／Director／聊天适配与相应定向测试。作者角色包、人设和素材不需要迁移；锚点区域不扩展，MCP 禁用、文件授权、官网链均不变。

先写最小失败用例：任意作者名称的状态与动作条件、同状态动作资格变化、迟到计划、有限情绪及持续活动、明确播放结束不复活、等待中的取消／停止／切换及三态运动。实现后验证真实 UI 的移动开始—动画切换—移动结束，以及明确播放自主结束。不能用模型口头承诺作为执行证据。

实施步骤见[情境执行计划](../plans/2026-09-06-character-context-execution.md)。所有新增数据只在有界会话中存在，不增加持久化、屏幕采集或 Provider 权限。旧无条件计划按有限表现兼容接纳，不维护平行旧引擎。
