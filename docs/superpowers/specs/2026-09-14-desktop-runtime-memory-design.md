# 桌宠运行内存优化规格

日期：2026-09-14。用户已批准开始优化，明确要求所有已完成交互效果与核心功能保持不变；本规格落实前一轮已讨论的窗口按需加载和界面拆包方案。

## 目标与现状

- 用户运行 `pnpm dev`，内置模型关闭；只读采样得到 Electron 进程组约 813 MiB 私有工作集，其中界面约 438 MiB、GPU 进程约 221 MiB、Main 约 143 MiB。单次采样不证明内存泄漏，也不能代替发行版基线。
- Main 启动即创建并加载设置、角色工作室；`App.tsx` 静态导入全部窗口视图。两者会使尚未使用的页面和模块提前常驻。
- 设置未提交字段、工作室选择与预览状态保存在组件中。关闭后销毁这些窗口会改变原有重开体验，因此本轮仅延迟首次创建，保持已经打开过的窗口隐藏语义。

## 实施方案

1. 复用 `createLoadBeforePublishWindow` 按需创建设置，工作室继续使用同一现有管理器；启动时只加载宠物、聊天和气泡。并发打开复用同一候选，加载失败销毁候选并允许重试；已销毁候选不得被迟到的加载结果发布。
2. 设置与工作室候选创建后立即登记启动失败清理；动态广播忽略不存在或已销毁的窗口。首次打开仍在加载完成后显示，禁止弹出新占位页面或改变现有关闭与保存握手。
3. Renderer 按当前 `view` 动态加载对应组件。保留所有窗口视图、组件 props、任务订阅与会话恢复时序意图；不改业务投影，不从静态 import 推断其他窗口保存完整聊天正文。气泡显式导入既有共享 CSS，入口仍按原顺序静态加载聊天、工作室、全局 CSS，以保留跨页样式及最终级联，只延迟视图 JavaScript。Main 在自有页面导航后等待 `#root` 首个元素提交，防止空白 Suspense 提前显示；固定脚本不读取正文或配置，无新增 IPC，10 秒未就绪按加载失败清理候选。
4. 无新增运行依赖。使用 React 原生按需加载及 Electron 既有窗口管理器，参考 [Electron 性能建议](https://www.electronjs.org/docs/latest/tutorial/performance)。Pixi 已动态加载，不重复建立另一套图形引擎。

## 不变项与非目标

- 保留模型调用、路由、流式正文、会话持久化、无痕、文件执行、授权裁决、角色状态和动作调度。
- 保留顶部三球动画、左展菜单、透明历史、按钮阴影、四行滚动气泡、窗口层级和鼠标穿透；不降低图片清晰度、分辨率或帧率。
- 保留聊天业务 owner 与气泡常驻生命周期，避免丢失流式事件或首条回复。
- 不启用/卸载本地模型，不改变模型身份或上下文，不用强制 GC/工作集裁剪伪造降幅。
- 本轮不改角色图集策略；只有测量证明必要且能保持切换连续性时才另行设计。
- 不修改官网、CloudBase、扫描器、共享业务契约；不增加产品遥测、权限或外部服务。

## 测量与验收

- 在生产实现变更前，以固定构建、固定测试角色、独立临时用户目录建立基线；只读取自有进程内存、页面类型、堆和节点计数，不读取真实用户正文或密钥。
- 用同一脚本、启动参数、稳定等待和采样规则进行前后对照，报告私有工作集及窗口数量；共享工作集不得直接相加宣称独占内存。测试配置与用户开发环境差异单独注明。
- 先 RED 后 GREEN：非当前视图不加载；冷启动不存在设置/工作室页；并发首次打开、失败重试、候选销毁、关闭后重开原状态均有定向证据。
- 检查首次打开耗时与白屏、关闭/重开、聊天流式及授权呈现；已有原生截图/首击环境限制如仍出现，记录未验证，不降低守卫。
- 定向测试、类型检查、构建和受影响桌面门禁；比较真实内存下降，不预设未经测量的 MB 承诺。新路径通过后删除原静态视图导入与启动预加载，不保留双入口。

本规格只替代启动时预加载非必要窗口与所有视图模块的资源策略，不替代既有聊天、角色工作室及本地模型的业务规格。
