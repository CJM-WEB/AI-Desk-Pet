# 官网文件预览与 PayPal 图片修复设计

## 目标

本次修复覆盖以下行为：

1. 捐款章节的 PayPal 付款方式使用 `apps/website/public/Paypal.png`，点击当前 PayPal 卡片后在付款码弹窗中显示该图片。
2. 下载章节外围的共享文件图标复用首页和捐款章节现有的悬浮预览效果。
3. 反馈章节外围的共享文件图标可以被鼠标命中，并显示该图标生成时随机绑定的一条反馈或建议。
4. 同一个反馈文件图标在存活期间保持预览内容稳定；文件图标消失并重新生成后重新随机选择内容。

## 现状与根因

PayPal 图片已经以 `Paypal.png` 存在，但付款方式配置和现有测试仍指向已删除的 `/Paypal.jpg`。因此需要把配置与测试统一更新为 `/Paypal.png`，不新增图片资源或建立第二份配置。

共享文件粒子已经统一由 `FileSwarm` 管理，并具备鼠标进入、鼠标离开、键盘聚焦和失焦状态。反馈章节也已经通过独立内容源，在文件粒子生成时绑定随机条目，并在粒子释放时删除绑定。

下载和反馈章节的活动章节容器会覆盖整个视口并接管指针命中。虽然文件图标本身允许接收指针事件，但它们位于章节内容层下方，因此鼠标无法命中。捐款章节已经通过章节级指针穿透和局部控件恢复命中的方式解决了相同问题。

## 方案

### 章节命中规则

下载、反馈和捐款章节统一采用同一命中规则：

- 全屏章节容器不接管指针事件，让外围共享文件图标可以被命中。
- 章节内部真正可交互的区域单独恢复指针事件。
- 下载章节保留侧边感应区、平台堆叠、下载按钮和已展开面板的交互。
- 反馈章节保留反馈滚筒、反馈卡片和根级弹窗的交互。
- 捐款章节保持现有支付滚筒和付款卡片交互不变。

不提高共享文件层的视觉层级，避免文件图标遮挡标题、卡片和主要操作区域。

### 文件预览复用

下载章节继续使用默认文件预览内容源，不新增章节专用悬浮组件。

反馈章节继续使用现有反馈预览内容源：

1. 文件粒子生成时调用绑定接口。
2. 从当前反馈和建议列表中随机选择一条。
3. 以粒子 ID 保存预览快照。
4. 悬浮或聚焦时读取该快照。
5. 粒子消失时释放快照；下一颗新粒子重新随机选择。

仓储为空或读取失败时继续使用现有兜底内容，不让预览交互中断。

### PayPal 图片

PayPal 付款方式保持配置驱动：

- 付款方式 ID：`paypal`
- 图片路径：`/Paypal.png`
- 图片替代文本：`PayPal付款码`

点击非活动 PayPal 卡片时先选中该付款方式；再次点击活动卡片时打开付款码弹窗。弹窗直接使用付款方式配置中的图片路径，不引入 PayPal 专用分支。

## 测试策略

先增加会失败的回归测试，再修改生产代码：

1. 验证下载和反馈活动章节采用允许外围文件命中的章节契约。
2. 验证章节中的核心按钮、滚筒和下载入口仍然可以接收指针事件。
3. 验证反馈预览内容在同一粒子生命周期内稳定，释放后重新生成会再次执行随机选择。
4. 验证 PayPal 付款方式打开弹窗后，图片地址为 `/Paypal.png`，替代文本为 `PayPal付款码`。

完成后运行网站单元测试、类型检查和生产构建。若本地浏览器环境可用，再补充桌面视口手动验证下载与反馈章节的文件图标悬浮预览，以及 PayPal 弹窗图片显示。

## 非目标

- 不调整文件粒子的生成频率、轨迹、数量或视觉资源。
- 不改变反馈和建议列表的排序、存储或点赞逻辑。
- 不重做下载、反馈或捐款章节布局。
- 不修改其他付款方式的图片资源。
