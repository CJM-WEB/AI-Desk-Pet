## 2. 已确认的交互

### 2.1 顶部聊天

1. 聊天输入默认隐藏在屏幕正上方。鼠标抵达顶部触发位置时先露出小三角；只有点击三角才展开输入界面。
2. 展开先出现三个小球，中间球横向展开为输入框，左球成为选项按钮，右球成为发送按钮。收起沿相反方向回到隐藏状态。
3. 选项球展开显示“新对话”“历史”“设置”。菜单采用可追加项目的数据结构，但本轮只提供这三个正式入口。
4. 点击“历史”后，输入框与左右按钮整体下移，上方带出可滚轮浏览的历史消息；再次点击恢复原位置。历史背景为透明模糊的玻璃效果，文字保持清晰。
5. 点击三横线、输入框或历史内容区域，只关闭菜单；点击底部三角或整个聊天区域以外的桌面，收起整个顶部聊天界面并关闭菜单。

### 2.2 普通回复

1. 普通回复在桌宠头顶以气泡显示，尺寸随正文适应。流式生成期间更新内容，完整回复显示后开始计时，30 秒后消失。
2. 新回复替换上一条普通回复气泡，并重新计时；超长回复达到屏幕容纳上限后，改为气泡内部滚动。
3. 鼠标悬浮时才显示左上角关闭按钮。关闭只隐藏这条气泡，不清除聊天记录、不取消任务。
4. 手动关闭的同一条流式回复不会因后续增量再次弹出；新的回复才重新显示。此规则落实“关闭这条气泡”的展示语义，不改消息合并。
5. 悬浮不暂停已开始的 30 秒计时。键盘聚焦气泡内控件时同样显示关闭入口，以便键盘操作。
6. 启动或窗口重建时恢复的历史正文不作为新回复弹出，也不恢复旧气泡计时、旧许可或旧点击。

### 2.3 授权与覆盖

1. 普通授权气泡默认正文为“待授权操作”，左侧“拒绝”、右侧“授权”。点击正文可展开原有授权详情。
2. 覆盖气泡正文为“明确文件编辑操作”，左侧“拒绝”、右侧“覆盖”；同样可展开原有详情。
3. 授权气泡沿用原有等待、处理、失效和清理规则，不适用普通回复的 30 秒计时，不通过隐藏界面自动作出任何决定。
4. 原有范围确认、具体许可、重复操作保护、历史披露保持各自回调和结果含义。统一的短文案不能改变原回调映射；展开详情、按钮悬浮说明与无障碍名称必须准确解释实际后果，尤其是重复操作的拒绝会结束当前任务，拒绝共享历史仍按原流程仅发送当前消息。
5. 展开详情保留原准确目录、模型、完整命令、目标文件和后果说明。按钮忙碌、重复点击防护、失败反馈和旧请求失效沿用原处理。

| 确认类型 | 左按钮的原操作 | 右按钮的原操作 | 详情与按钮说明必须写清的含义 |
| --- | --- | --- | --- |
| 任务范围授权 | `resolveCapabilityAuthorization(id, 'cancel')` | `resolveCapabilityAuthorization(id, 'confirm')` | 拒绝或进入本次本地任务 |
| 普通具体许可与覆盖 | `cancelAction(id)` | `confirmAction(id)` | 拒绝或批准本次准确操作，不撤销已经完成的操作 |
| 重复操作保护 | 原 `cancelAction(id)` 分支 | 原 `confirmAction(id)` 分支 | 左侧结束当前任务；右侧仅放行当前重复这一次，其他权限仍需满足 |
| 历史披露 | `resolveHistoryDisclosure(id, 'current_message_only')` | `resolveHistoryDisclosure(id, 'share_once')` | 左侧拒绝共享历史但仍发送当前消息；右侧仅本次共享历史 |

上述表格是原处理函数的核对依据，不在展示桥重新实现这些业务分支。

## 4. 方案比较与推荐

| 方案 | 代价与适用性 | 结论 |
| --- | --- | --- |
| 保留现有 chat 为唯一业务界面，另设头顶展示窗口 | 新增最小展示通信，顶部输入和回复可同时存在；保持原消息和授权所有者 | 推荐 |
| 一个透明大窗口同时覆盖顶部与宠物 | 共用 Renderer 容易，但透明空白跨度大，命中区域、跨屏、窗口层级与模糊裁剪更复杂 | 不采用 |
| 同一小窗口在顶部与头顶来回移动 | 窗口数量少，但显示回复会挤掉顶部输入，不能保持两处各自的显隐状态 | 不采用 |

推荐方案中，收到回复不主动关闭已展开的输入框。顶部输入与头顶气泡有各自的显示状态；收起顶部输入不撤销头顶待处理授权，普通回复仍按自身计时显示。

## 5. 视觉与动效提案

### 5.1 外观

采用浅色玻璃底、细高光边缘、柔和阴影与虹彩按钮。虹彩从青色过渡到蓝、紫和少量暖粉，主要用于两个圆形按钮的边缘与受光面；正文区域保持中性底色，避免彩色纹理压住文字。

| 元素 | 首版设计值 |
| --- | --- |
| 输入框 | 默认宽 360 DIP、高 48 DIP；圆角 24 DIP，长输入沿用多行编辑并限制可见高度 |
| 左右按钮 | 48×48 DIP 圆形，图标 20 DIP；与输入框间距 12 DIP |
| 顶部触发提示 | 约 56×18 DIP 的浅弧托底与向下三角；可点击区域至少 72×28 DIP |
| 收起提示 | 输入框底部居中的浅弧托底与向上三角 |
| 选项展开体 | 与左球连续连接的圆角面板；项目按“新对话／历史／设置”竖排，单项高度 40 DIP |
| 历史区域 | 与输入框同轴，上方展开；初始目标高度为工作区高度的 38%，上限 360 DIP，小屏自适应缩小 |
| 回复气泡 | 约 24 DIP 圆角、16 DIP 内边距；最大宽 440 DIP且不超过工作区可用宽度，最大高为工作区高度的 45% |
| 字体 | 复用系统中文字体栈，不下载外部字体；正文 14–15 DIP，行高约 1.6 |
| 色彩 | 深灰正文；青 `#59D9E8`、蓝 `#5E9BF4`、紫 `#9A7BE8`、暖粉 `#F0A1B5` 作为虹彩参考值 |

图标复用现有 `lucide-react`。消息正文沿用现有文字呈现，不额外引入 Markdown 渲染、代码执行、链接自动打开或内容处理。

### 5.2 动作顺序

- 顶部提示：约 160 毫秒向下露出；鼠标离开提示区域后留出短暂的移动容错，再回到隐藏状态。
- 展开：约 180 毫秒三球落位，随后约 300 毫秒中球横向展开；左右图标随各自球体定型显现。整段控制在约半秒。
- 选项：左球约 220 毫秒向下展开，保持球体与面板连续。
- 历史：约 300 毫秒带动整行输入下移，历史从上方揭开；滚动仅作用于历史内容。
- 整体关闭：先收菜单与历史，再将输入框缩回中球，三球返回顶边并隐藏。连续点击时反向衔接当前动画，不累加定时任务。
- 减少动态效果偏好下保留最终布局与所有功能，使用短淡入淡出代替形变和弹性位移。

动画优先使用现有浏览器的 CSS 与 Web Animations 能力，不为本轮动效引入新动画框架。

### 5.3 屏幕与内容适应

沿用桌宠所在显示器作为聊天显示上下文。顶部触发区位于该屏幕物理顶边的中央，宽度与展开后的输入组件组对应；不占据整条顶边。正文与按钮布局避让该屏幕工作区、任务栏和屏幕边界。

头顶气泡按现有角色视觉包围框的上缘居中定位，不新增角色素材锚点。空间不足时在工作区内调整气泡位置和尾部指向，不移动宠物、不缩放宠物、不改变行为状态。使用现有 DIP 坐标规则；显示器移除、缩放与分辨率变化后重新计算窗口位置。

实现采用 Main 提供的有界正文局部横坐标、尾部局部横坐标及朝向；上方放不下且下方空间更合适时改放下方，尾部向上。短正文可在固定透明画布内横移；CSS 按正文自身宽度约束偏移，确保换成长回复或视口变窄的首帧也能完整测量正文，不把旧偏移造成的裁切反复反馈为新宽度。

## 6. 窗口、通信与功能保留

### 6.1 唯一业务所有者

现有 chat Renderer 继续唯一接收完整任务事件、恢复会话、维护原展示仓库并调用原业务 API。新的头顶窗口仅展示 chat 提供的最小快照，回传预定义界面操作，不订阅完整 TaskEvent、不恢复聊天、不直接调用授权或模型 API。

数据流：

`原会话事件 → 原 chat 与原 TaskStore → 最小气泡展示快照 → Main 展示桥 → 气泡窗口`

`气泡按钮点击 → Main 展示桥 → 当前 chat 的原处理函数 → 原业务 API`

展示桥只接纳当前 chat 和当前气泡窗口各自允许的消息。快照携带展示修订、消息身份和当前许可身份；回传点击须匹配仍有效的快照，再由 chat 复核原会话修订和待处理请求。不能把过期点击转成新请求的批准。

展示数据仅包含当前气泡正文、原许可卡已有的公开决策详情、按钮展示状态和界面错误；不传完整会话、原始工具参数对象、密钥或私有元数据。pet、settings 仍不能接收聊天正文。

### 6.2 显隐与鼠标

Main 管理显示器、窗口矩形、置前、焦点、透明区穿透和顶边触发；Renderer 只管理菜单、历史、动效、展开详情和气泡计时等展示状态。

透明空白区不吞掉桌面点击，顶边提示不能抢走其他应用输入焦点。展开后输入框获得焦点；顶部输入与气泡内部切换焦点不能被误判为点击外部。

外部点击检测必须覆盖普通应用和桌面；不能仅把窗口失焦假装成完整的点击证据。实现前先验证 Electron 窗口事件能覆盖的范围；不足部分限定在 Windows 窗口表现适配器中，只识别鼠标点击与本应用可交互区域的关系，不读取按键文字、其他窗口正文或桌面截图。

### 6.3 原功能对应

| 原功能 | 新界面位置与约束 |
| --- | --- |
| 发送与 Enter、Shift+Enter、输入法组合输入 | 新胶囊输入框，复用原提交函数和键盘规则 |
| 执行中停止 | 右圆球按原可停止条件显示停止图标，仍调用原取消入口 |
| 新对话 | 左菜单，复用原新对话与清理逻辑，不因开关菜单触发 |
| 设置 | 左菜单，打开原设置窗口，不重做设置业务 |
| 当前会话正文 | 历史展开区，保持原顺序、身份与完整范围 |
| 普通回复 | 头顶气泡加原历史正文；气泡消失不删除正文 |
| 范围授权、具体许可、历史披露、重复保护 | 头顶授权展示，保留各自原处理、队列和忙碌规则 |
| 加载、保存、恢复、交互和模型故障提示 | 在输入区或展开历史的相应位置保持可发现，不能只藏在已自动消失的气泡中 |

存在待处理授权时，授权展示优先于普通回复；普通回复仍保存在原历史中，其显示期限独立计算。授权结束后，只在普通回复尚未过期且未手动关闭时恢复该气泡。详情展开后允许滚动，按钮保持可见。

## 7. 原生模糊、失败与兼容

透明模糊指窗口后方桌面内容的真实模糊，不能用普通 CSS 模糊当前页面冒充。Electron 官方文档明确说明透明窗口的 CSS 模糊不能处理其他应用内容；原生 `setBackgroundMaterial` 支持 Windows 11 22H2 及以上。

- [Electron 透明窗口限制](https://www.electronjs.org/docs/latest/tutorial/custom-window-styles#limitations)。
- [Electron 原生背景材质](https://www.electronjs.org/docs/latest/api/browser-window#winsetbackgroundmaterialmaterial-windows)。

先以当前固定 Electron 版本验证原生材质、透明形状、动态窗口尺寸和鼠标穿透的组合。Windows 10 兼容实现只允许进入独立窗口表现适配层，不改业务包；参考项目包括 [electron-acrylic-window](https://github.com/Seo-Rii/electron-acrylic-window) 和 [vibe](https://github.com/pykeio/vibe)，当前仅作调查来源，未采用其代码或依赖。采用外部代码前必须记录固定提交、源文件、许可证和本地修改。

首个实施检查点是原生表现验证：证明目标系统能正确显示玻璃形状、真实模糊、点击穿透及外部点击收起，再进行完整视觉接线。单项尝试达到 15 分钟仍无可判定结果时停止该尝试并记录证据，改用更小复现或替代方案；若需新增依赖、扩大原生能力或降低真实模糊要求，先提出具体影响供用户确认，不自行变更验收目标。

运行时材质不可用时保留可读的半透明底以维持基础聊天；该状态是兼容回退，不算真实模糊验收通过。不得通过截图桌面、持续截屏或发送桌面内容给模型来实现模糊。

实施验证确认：透明窗口的自定义形状不能裁剪整窗 DWM 材质。因此历史使用无 preload、无正文的独立系统材质背景，放在透明聊天内容窗口下方；历史圆角匹配 Windows 系统约 8 DIP，输入、圆球与头顶气泡仍使用原定圆角。该辅助层只承接窗口绘制，不新增消息或业务所有者。头顶窗口保持最多 464 DIP 的透明画布，实际气泡轮廓随正文适应，以免短回复缩小窗口后限制下一条长回复。

展示快照与点击同时绑定 Main 生成的 `epoch` 和单调修订。会话清理撤销整个展示代次；单独重建头顶窗口也撤销旧代次及普通回复，但原 chat 持有的当前待授权仍重新发布。该标记仅隔离展示生命周期，不承载或恢复业务许可。

气泡窗口故障不打断原聊天和任务。出现展示桥故障时，原 chat 显示可恢复的回复或确认界面，保持授权入口可达；不自动批准、不重放点击。应用退出、chat 重建和会话清理时撤销展示快照、计时器与旧窗口回调。

## 8. 修改与删除边界

拟修改范围限于以下职责；实施计划需进一步给出逐项文件和测试：

- `apps/desktop/src/renderer/src/chat/`：原聊天结构、新顶部展示、历史、气泡与授权视觉，保持原业务回调。
- `apps/desktop/src/renderer/src/styles.css`：移除被替代的聊天专属样式，公共及设置样式不随之删除。
- `apps/desktop/src/renderer/src/App.tsx`：新增纯展示视图分支，该分支不挂载原任务订阅。
- `apps/desktop/src/main/windows/`：顶部与头顶窗口配置、定位、显隐、穿透和展示协调。
- `apps/desktop/src/main/index.ts`：只增加窗口表现装配，替换原聊天相邻定位；保留原会话、Provider、授权和行为装配。
- `apps/desktop/src/shared/`、`apps/desktop/src/preload/` 及独立展示 IPC 注册文件：严格限制新增的展示快照与点击意图契约。
- `apps/desktop/resources/windows/`：仅在原生表现验证证明必要时，增加专属窗口表现适配资源；不混入 Explorer 或文件任务执行器。
- 对应桌面单元测试、边界测试、真实 Electron E2E，以及规格、计划和独立验收记录。

不修改 `packages/agent-core`、`packages/coding-task-core`、`packages/file-tools`、角色行为决策和当前会话保存实现。不改通用 TaskEvent 以承载视觉状态，不为新气泡增加第二套聊天或权限引擎。

替代路径通过定向验证后删除旧聊天头部、旧输入布局、旧相邻定位及只服务旧视觉的样式。安全、授权和行为测试继续验证原契约，不因旧外观被移除而整体删除。若清理涉及大量文件，先列精确清单并按仓库规则取得第二次批准。Git 保持只读。

## 9. 验证与完成条件

实施采用 SDD、子智能体分工和 RED → GREEN → REFACTOR。先为展示状态和窗口接口写可判定失败测试，再实现；涉及原生观感的部分另记实际观察，不以 jsdom 通过替代。

必须覆盖：

1. 顶边仅露提示、点击才展开、三球顺序、反向收起及动画被快速操作打断。
2. 菜单与历史独立开关、正确的外部点击优先级、完整历史滚动及输入不被遮挡。
3. 发送、停止、输入法、无痕、恢复、新对话、模型切换及原忙碌条件保持既有行为。
4. 流式提交后计时、30 秒边界、新回复替换、手动关闭后同消息不复活、长文本滚动。
5. 授权不受气泡计时影响，原详情完整、按钮映射正确、失败可重试、旧修订点击失效，拒绝不被误当批准。
6. 新气泡无业务 IPC 权限，pet/settings 不获得正文；展示故障不阻断原任务与确认。
7. Windows 实际顶边触发、其他应用与桌面点击、透明区穿透、焦点切换、跨屏/DPI、玻璃材质、气泡跟随与屏幕边缘位置。
8. 动画和气泡不得改变桌宠位置权威、拖拽、角色播放、状态决策或 Agent phase；无痕与持久化不增加任何视觉数据落盘。

最终验证按用户最后明确的视觉范围执行：桌面类型检查、构建、展示定向测试与正式聊天视觉 E2E。早先完整 `verify:desktop` 的既有失败保留真实记录；停止额外角色、拖拽及模型业务测试和问题修补，不再追加广泛回归。已经执行的相关安全与集成检查可以作为展示边界证据，不能据此宣称整套业务已全部通过。

交付检查包含中文编码、文档链接、修改范围和 `git diff --check`。原生观感、Windows 窗口层级、拖拽与不同系统兼容性没有实际观察证据时，写为“待用户人工确认”；未运行或失败的项目不得记为通过。

完成条件：确认的视觉流程全部有实现和证据，原业务契约未变，旧视觉路径按批准范围清理；自动化、实际窗口观察和待人工确认事项分别记录。
