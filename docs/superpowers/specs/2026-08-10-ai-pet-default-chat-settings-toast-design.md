# AI 桌宠默认聊天与设置 Toast 设计

> 文档状态：用户已确认，可进入实现
>
> 基准日期：2026-08-10
>
> 目标分支：`AgentCoreExtension`
>
> 开发方式：规格驱动开发；实施阶段采用 TDD 与子智能体驱动开发
>
> 范围：仅智能桌宠 Desktop，不包含网站

## 1. 文档目的

本文修复两个已确认的桌宠体验问题：普通聊天被严格 JSON 规划误判为固定澄清，以及设置操作提示长期占据页面布局。本文是本轮实施的唯一需求基准；长期记忆、截图、剪贴板和主动性另立规格，不在本轮伪接入。

## 2. 现状与根因

当前所有用户输入都由 `ConversationTurnAdapter` 请求模型同时完成路由与回复。模型必须返回严格的 `chat_reply`、`clarify` 或 `file_task` JSON；任何自然文本、Markdown、额外字段、非法情绪、空文本或工具请求都会被替换成同一句固定澄清。固定澄清随后作为正常助手消息写入历史，可能在后续回合形成重复强化。

DeepSeek 预置复用 OpenAI-compatible Provider，但当前请求没有结构化响应模式或专用采样参数。真正影响聊天质量的是把自由聊天压缩成严格规划协议，而不是文件工具、隐私门禁或历史上限本身。

设置窗口把 `notice` 直接渲染在标签页与正文之间，没有自动关闭、手动关闭或浮层定位，因此成功提示会持续占据页面布局。角色工作室已有可靠的 Toast 计时、暂停和可访问性实现，但当前组件和类型耦合工作室领域。

## 3. 已确认决策

1. 除非用户明确要求桌宠实际执行本地文件操作，否则输入一律按普通聊天处理。
2. 普通聊天直接使用自由文本模型响应，不再要求路由 JSON。
3. 明确文件操作继续复用现有文件 Agent、安全授权、隐私披露、确认和回收站事务。
4. 设置中的成功、信息、警告和错误 Toast 全部在累计可见 3,000ms 后自动关闭，并支持手动关闭。
5. 本轮不实现长期记忆、截图、剪贴板或主动性运行时；这些能力按独立规格顺序推进。

## 4. 稳定需求

### 4.1 范围与唯一入口

- `CHAT-DEFAULT-001`：Renderer 保留一个输入框，不增加聊天/文件手动模式开关。
- `CHAT-DEFAULT-002`：所有输入仍由 Electron Main 的可信会话模块决定去向，Renderer 不得提交路由类型。
- `CHAT-DEFAULT-003`：替换完成后必须删除旧三分支 JSON 规划入口、固定澄清降级和重复兼容路径。
- `CHAT-DEFAULT-004`：不得修改、测试、构建或运行网站。

### 4.2 明确文件操作

- `CHAT-INTENT-001`：只有同时存在明确文件对象、明确执行动作和要求桌宠实际执行的语气，才能形成文件任务。
- `CHAT-INTENT-002`：文件对象包括文件名、常见扩展名、相对路径、用户指示的当前文件/文件夹、当前目录或授权目录。
- `CHAT-INTENT-003`：执行动作包括读取、列出、创建、写入、修改、重命名、复制、移动、删除、搜索和整理文件实体；中英文常用表达必须有自动测试。
- `CHAT-INTENT-004`：只讨论文件知识、方法、安全性或可能性的消息属于普通聊天，例如“如何更安全地删除文件”。
- `CHAT-INTENT-005`：缺少文件对象、执行动作或实际执行请求中的任一项时默认普通聊天，不进入文件授权引导，也不显示语义澄清。
- `CHAT-INTENT-006`：明确文件操作一旦成立，后续仍必须经过现有授权、披露、确认、路径策略和回收站安全链；可信意图门不能绕过任何文件安全边界。

### 4.3 自由聊天

- `CHAT-REPLY-001`：普通聊天模型请求由稳定的自然对话系统提示、获准可见历史和当前用户消息组成，工具数组严格为空。
- `CHAT-REPLY-002`：系统提示要求模型以 AI 桌宠身份自然回答、优先使用用户语言、结合可见上下文，并禁止声称已执行未执行的文件操作；不得要求 JSON、路由字段或 Markdown 禁令。
- `CHAT-REPLY-003`：非空普通文本和 Markdown 文本均可作为聊天回复展示；回复上限保持 8,000 个 Unicode 字符。
- `CHAT-REPLY-004`：Provider 已规范化的合法情绪元数据继续进入现有角色表现事件，不恢复任意模型行为指令。
- `CHAT-REPLY-005`：空文本、超长文本、意外工具请求或 Provider 格式错误必须产生稳定公开错误，允许用户重试；不得显示固定语义澄清。
- `CHAT-REPLY-006`：聊天失败不得创建文件 Agent、读取授权根、创建 `PathPolicy` 或自动改走文件任务。
- `CHAT-REPLY-007`：只有成功展示给 Renderer 的用户—助手完整回合才能写入共享历史；失败、错误文本、工具请求和内部诊断不能进入历史。
- `CHAT-REPLY-008`：当前会话继续限制为最多 20 个完整回合和 16,000 个 Unicode 字符，只驻留 Main 内存；本轮不宣称跨应用重启记忆。

### 4.4 设置 Toast

- `SETTINGS-TOAST-001`：设置提示必须以固定浮层显示在设置窗口右上角、应用标题栏下方，不参与正文布局。
- `SETTINGS-TOAST-002`：成功、信息、警告和错误提示的累计可见时长统一为 3,000ms。
- `SETTINGS-TOAST-003`：每条提示提供原生关闭按钮，可立即手动关闭；按钮名称必须包含可理解的关闭语义。
- `SETTINGS-TOAST-004`：鼠标悬停或键盘焦点位于 Toast 内时暂停计时，离开后从剩余时间继续。
- `SETTINGS-TOAST-005`：新设置提示替换旧设置提示并清理旧计时器，不堆叠遮挡设置内容。
- `SETTINGS-TOAST-006`：Toast 出现时不抢焦点，关闭后不强制移动焦点；卸载设置窗口时必须清理计时器。
- `SETTINGS-TOAST-007`：成功与信息使用礼貌播报，警告与错误使用即时播报；提示不能只靠颜色表达语义。
- `SETTINGS-TOAST-008`：窄窗口下 Toast 宽度不得超出视口或产生横向滚动；若有过渡效果，必须遵守减少动态效果偏好。
- `SETTINGS-TOAST-009`：提取无工作室语义的通用 Toast 组件供设置与角色工作室复用，并删除被替换的工作室专用重复计时实现和设置页横幅样式。

## 5. 架构

### 5.1 会话分流

```text
Renderer 单一输入框
        │
        ▼
ConversationCoordinator
        │
        ▼
ExplicitFileIntentGate（可信 Main，正向举证）
        ├─ 普通或证据不足 ──► ConversationChatAdapter
        │                         ├─ 自然对话提示
        │                         ├─ 获准可见历史
        │                         └─ tools: []
        │
        └─ 明确文件操作 ─────► FileTaskAdapter
                                  └─ 既有 Agent 与文件安全链
```

建议接口：

```ts
export type ConversationRoute =
  | { kind: 'chat' }
  | { kind: 'file_task' };

export interface ExplicitFileIntentGate {
  classify(text: string): ConversationRoute;
}

export interface ConversationChatInput {
  history: readonly ModelMessage[];
  text: string;
  signal: AbortSignal;
}

export type ConversationChatReply = Readonly<{
  text: string;
  emotion?: CharacterEmotionLabel;
}>;

export class ConversationChatAdapter {
  constructor(provider: ModelProvider);
  respond(input: ConversationChatInput): Promise<ConversationChatReply>;
}
```

意图门只返回最小路由结果，不把匹配词、路径或用户正文写入日志或 Renderer 事件。证据不足的结果固定为 `chat`。文件任务仍使用原始用户文本进入既有 `FileTaskAdapter`，由其完成目标快照、第二次披露、授权预检和文件 Agent 生命周期。

### 5.2 聊天回复

`ConversationChatAdapter` 只接受 Provider 的文本响应。合法文本经过 Unicode 长度校验后返回；合法情绪元数据沿用现有白名单。工具请求、空文本和超长文本映射为稳定错误，不回显原始响应。Coordinator 只在确认请求仍属于当前 generation 后广播回复并写入完整回合。

### 5.3 通用 Toast

从现有工作室 Toast 提取通用 `TransientToastLayer` 和无领域偏向的提示类型。组件负责当前提示、3 秒计时、悬停/焦点暂停、手动关闭、可访问角色和卸载清理；提示的产生、替换与移除仍由各消费方状态所有者负责。

设置页只持有最新一条提示；新操作结果替换旧提示。角色工作室保留既有队列语义，但使用同一个通用展示组件。设置窗口当前结构不需要新增 Portal；固定定位相对视口即可满足不占布局的要求，避免增加无必要接缝。

## 6. 错误与安全

1. 聊天 Provider 的网络、认证、限流和服务错误继续使用现有公开错误映射。
2. 自由聊天中的异常工具请求属于模型响应错误，绝不执行工具或升级文件能力。
3. 明确文件操作缺少授权时继续返回现有稳定授权引导，不降级为聊天并假装完成。
4. 意图门不得记录用户正文、文件名、路径或匹配证据；现有日志与审计脱敏要求保持不变。
5. Toast 回调或计时清理失败不能改变已经完成的设置领域操作结果。
6. 所有运行时尚未接通的隐私选项继续禁用并显示“尚未接入运行时”，不得仅修改支持位伪装完成。

## 7. TDD 与验收矩阵

### 7.1 意图门

- “你好”“聊天呀”“我想和你聊天”“帮我整理一下”均为 `chat`。
- “如何更安全地删除文件”“解释一下文件夹整理方法”均为 `chat`。
- “读取 a.txt”“列出当前文件夹”“删除当前文件夹里的 a.txt”“rename notes.md to archive.md”均为 `file_task`。
- 否定执行、引用他人命令和讨论性表达不能形成文件任务。
- 任何文件任务路由都必须继续命中现有授权与文件安全测试。

### 7.2 聊天适配器与协调器

- DeepSeek 风格普通文本与 Markdown 文本直接展示。
- 请求工具列表严格为空，普通聊天不调用授权根、隐私文件数据或 `PathPolicy`。
- 合法情绪元数据正常广播；非法或任意行为指令不进入角色执行。
- 空文本、超长文本、工具请求和 Provider 错误产生稳定错误且不写历史。
- 连续三轮普通聊天携带完整可见上下文；新对话与旧 generation 隔离仍通过。
- 旧固定澄清文本和旧三分支 JSON 规划测试必须删除或替换，不能保留兼容壳。

### 7.3 Toast

- 四种 tone 在 2,999ms 时仍存在、累计 3,000ms 时关闭。
- 手动关闭立即生效；悬停和焦点分别暂停并从剩余时间恢复。
- 新提示替换旧提示且旧 timer 不会删除新提示；卸载后无迟到更新。
- 成功/信息与警告/错误具有正确 live-region 语义，关闭按钮可由辅助技术识别。
- 设置页不再渲染正文流横幅；工作室原有提示行为与队列不退化。
- Electron E2E 至少覆盖设置连接测试提示出现、手动关闭和自动消失。

### 7.4 完整门

按顺序运行 Desktop 类型检查、单元、安全、集成和 Electron E2E。网站目录差异必须为空，且不得运行网站测试、构建或开发服务。

## 8. 非目标与后续顺序

本轮不实现长期记忆、截图、剪贴板、主动性、语音、联网信息工具、桌面自动化或 MCP 恢复。

后续独立规格顺序固定为：

1. 本地长期记忆：版本化 Schema、显式记住/遗忘、检索注入、共享用户档案与角色关系记忆、管理界面和无痕门禁。
2. 截图与剪贴板：各自的采集器、任务级授权、披露清单、审计和生命周期。
3. 主动性：可信事件、安静时间、勿扰、冷却、每日上限和用户反馈。

截图、剪贴板、长期记忆和主动性在各自生产组合真正接通前继续保持禁用状态。现有 `LocalMemoryStore` 与 `ProactivityPolicy` 只能作为后续规格的安全原型，不等同于已上线功能。

## 9. 完成定义

- 普通聊天不再依赖严格 JSON 规划，截图中的固定澄清不能由普通问候触发。
- 只有明确文件操作能够创建文件任务，所有文件安全边界保持通过。
- DeepSeek 普通文本能够自然展示，失败不污染历史或升级能力。
- 设置提示以可关闭的 3 秒浮动 Toast 展示，不再推动页面布局。
- 工作室与设置复用一套通用 Toast 计时和无障碍实现，旧重复代码已删除。
- 所有聚焦和完整 Desktop 自动门通过，网站零修改且未运行网站验证。
- 长期记忆等后续能力仍准确显示为未接入，未虚构完成。
