# 当前对话持久化与模型切换确认

## 依据与范围

用户要求退出并重新进入后保留当前聊天，仅主动新对话或切换模型时开启空白对话；切换前必须提示并允许取消。用户另已确认保留无痕例外。本文落实本次请求，局部替代旧会话路由规格的“仅运行期、不写磁盘”以及所有配置修改一律清空历史的约定，不改文件执行、授权、角色行为和官网链路。

## 现状证据

- Chat 窗口关闭通常只是隐藏；应用退出或 Renderer 重建时，TaskStore 从空消息开始且没有恢复入口。
- Main 的 ConversationHistory 仅在内存保留最多 20 个完整回合、16,000 个 Unicode 字符，不能充当完整的可见聊天记录。
- 普通配置变更复用 resetConversation，甚至保存相同路由、修改非活动档案也会清空；本地模型切换在保存前就清空，同模型重新加载同样受影响。
- 无痕开关已有“关闭会话后不保留”承诺；原设置的“清除对话摘要”按钮没有相应清除实现。

## 设计与数据流

1. Main 独立保存一份当前会话：正式可见用户、助手、错误文字及现有有界模型上下文。完整聊天记录与有界模型上下文分开，不把 20 轮或 Renderer 原 100 条显示裁剪当作持久化范围。复用已有原子文件队列与 safeStorage 加密适配，不新增数据库或依赖。
2. 启动时先恢复记录，再开放聊天；只恢复文字与上下文，重新创建运行代次，不恢复任务、权限卡、披露许可、播放令牌、流式中间结果或行为状态。文件正文若本来就是最终可见回复，属于用户要求保留的聊天文字；原始工具数据不因此落盘。
3. 仅当前聊天窗口可通过严格空输入 IPC 请求恢复。快照和实时消息按同一 Main 投递顺序接纳，不能让迟到快照覆盖新消息或复活新对话之前的文字；pet/settings 不获得聊天正文。复用同一消息归并逻辑，避免 Main 与 Renderer 对流式提交产生两种结果。
4. 将配置失效与清空分开。目录、隐私和无实际模型变化的设置仍中止旧运行、撤销授权与迟到结果，但保留聊天。明确新对话才清文字，并等待清空写入完成。
5. Main 串行处理模型变更。比较实际聊天／任务模型身份，涵盖 Qwen 覆盖云路由、活动档案更改或删除及旧模型设置入口。确认文案说明“切换模型会开启新对话”，取消不写设置、不取消现有任务、不清聊天。同模型重载、同值保存、非活动档案及 Qwen 覆盖下的云配置修改不弹切换提示。
6. 确认后先终止旧运行再提交设置；只在模型身份实际提交变化后开启新对话。保存失败且旧身份不变时保留聊天。本地启动失败但路由已提交为本地时，保留现有本地故障态并开启新对话，不静默退回云模型。持久化记录绑定模型身份，崩溃恢复不能把旧模型上下文自动发给新模型。

## 无痕、安全与失败

普通聊天仅加密保存在本机，不上传或转成长期记忆。进入无痕后冻结此前普通会话的磁盘快照，本次后续内容仅在内存中；关闭无痕不补存这段内容，从下一次新对话开始恢复普通保存。新对话或明确清除数据时仍清除旧当前会话。设置中的清除对话入口与正式新对话清理共用实现，修正文案为实际清除对象。

加载失败或无法解密时保留原文件，不静默覆盖；可见提示只包含安全错误码和说明。写入失败不能伪装保存成功，退出等待已接纳写入完成；不用磁盘错误阻止基础聊天。所有晚到响应仍遵守现有代次和取消检查。

保存故障与恢复通过 chat 专属快照中的状态提示呈现，不作为任务失败事件，不清除正在等待的许可卡或流式回复。切换事务提交期间拒绝手动新对话与新消息；退出撤回尚未确认的对话框，等待已提交模型的身份收尾与新对话清空完成后，再关闭会话并冲刷保存队列。

## 验证与删除范围

先 RED 后 GREEN：实例重建、完整可见消息与有界上下文、无痕不补存、reset 写入顺序、加载失败不覆盖；快照与消息／reset 顺序、chat sender 边界；模型确认取消、同值重载、云／Qwen 切换、提交失败和真实提交后故障。隔离 Electron 验证重启恢复和无痕存储；原生确认的接纳、取消与退出信号由 Main 协调器和设置 UI 自动化测试验证，实际 Windows 对话框观感待用户人工确认。现有 E2E 仅提供 Renderer CDP，不为确认框新建 Main 调试或产品绕过入口。不请求用户真实模型、不读取真实聊天或凭据，沿用用户承担最终视觉验收的约定。

删除被新路径替代的无条件清历史调用及重复消息归并逻辑，保留无痕、披露与授权边界；不增加历史会话列表、搜索、导出、后台摘要或跨设备同步。完整门禁按实际结果单独记录，不将旧失败标为本次通过，不自动提交 Git。
