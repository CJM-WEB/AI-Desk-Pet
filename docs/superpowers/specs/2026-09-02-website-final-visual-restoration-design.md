# 官网最终视觉恢复与防回归设计

> 文档状态：用户已于 2026-09-02 批准“双重保障”恢复原则
> 目标分支：`WebsiteExtension`
> 最终视觉权威：`963df613e35f8cafc1a9ea076ab878f0bae782d6`
> 当前业务权威：实施开始时的 `WebsiteExtension` 当前提交
> 部署环境：上海 CloudBase 开发／测试环境；本规格不把它表述为正式生产

## 1. 问题与根因

上海测试站当前能够正常返回页面和 API，但五章节视觉已经偏离此前确认的最终版。逐章真实浏览器对照证明：

- 首页仍接近最终版；
- 介绍章在正常动态模式下只剩浅灰放射背景，核心内容不可见；
- 下载章丢失深色液态背景和主要玻璃信息层；
- 共享仓库章丢失深色液态标题、数字和玻璃构图；
- 支持章丢失左右两组反馈／支付景深按钮，只剩标题。

`2026-08-11-smooth-chapter-scroll-and-support-depth-design.md` 已明确规定：正常动态模式下，支持章可见玻璃和文字由 `LiquidGlassHome` 的 WebGL 着色器绘制，透明 DOM 只负责点击、键盘和无障碍语义。`963df61` 是完成该规格并取得真实浏览器视觉验收的最后提交。

后续以下三个提交改变了该事实：

1. `94785ee` 为减少动态效果建立无 GPU 路径；
2. `d103a83` 删除四条跨章节液态视觉事件；
3. `0664b49` 删除角落、介绍、下载、社区和支持纹理以及对应着色器分支，并把液态画布生命周期收窄到首页与介绍交接。

上述减法累计从核心视觉运行链删除约 1,335 行。自动化仍能验证 DOM、接口和交互语义，却没有稳定的最终画面基线；人工视觉项一直保持“待用户确认”。因此部署本身使用了当前分支的正确构建，但该构建在部署前已经发生视觉回归。

## 2. 目标

1. 恢复 `963df61` 已确认的五章节正常动态视觉和章节交接。
2. 完整保留 2026-08-12 之后的 CloudBase、共享资源、审核、管理员强制发布、下载计数、i18n、安全和错误处理行为。
3. 以“历史已删代码核对 + 当前逐章真实画面对照”形成双重恢复依据。
4. 建立能够阻止同类视觉职责被再次静默删除的自动化和人工双门。
5. 只修改网站视觉层及其直接交互投影，不修改桌宠业务，不修改数据库、云函数业务、Scanner 或远端数据。

## 3. 非目标

- 不整体回退分支或把任何当前业务文件直接替换成 `963df61` 版本。
- 不恢复已经退役的旧 Repository、旧 HTTP DTO、旧审核状态或旧本地持久化路径。
- 不改变章节顺序、业务文案含义、投稿／审核状态机、管理员权限或下载计数语义。
- 不引入新的动画框架、状态管理框架、第二套页面或兼容包装层。
- 不重做视觉风格，不把恢复任务扩大为新的 UI 设计。
- 不执行合并、变基或推送。
- 不触碰 `apps/desktop/**`、`packages/agent-core/**`、`packages/file-tools/**`、`packages/character-runtime/**` 或 `packages/character-assets/**`。

## 4. 双重事实来源

### 4.1 当前业务事实

当前 `WebsiteExtension` 是以下内容的唯一业务权威：

- CloudBase API 地址、运行时响应契约与 Repository；
- 共享包投稿、公开列表、点赞、下载和管理员风险标记；
- 反馈／建议投稿、审核和公开读取；
- 官方下载状态与管理员下载计数；
- 管理员认证、状态版本、幂等和错误处理；
- 当前中英文文案、移动端行为、静态回退和减少动态效果路径。

恢复过程中不得从旧提交覆盖这些实现。

### 4.2 最终视觉事实

以下内容共同构成视觉权威：

1. `963df61` 的正常动态运行代码；
2. `2026-08-11-smooth-chapter-scroll-and-support-depth-design.md`；
3. `963df61` 本地只读站在同一浏览器、同一视口下取得的五章节画面；
4. `94785ee`、`d103a83`、`0664b49` 的精确删除差异。

恢复不能只凭记忆重新绘制，也不能只把旧代码粘回；每项可见职责必须同时对应历史代码证据和真实画面对照。

## 5. 方案比较与裁决

### 5.1 整体回退到 `963df61`：拒绝

优点是画面可快速回到旧状态；缺点是会覆盖其后大量正确的 CloudBase、安全、审核和网站业务改动，风险不可接受。

### 5.2 只用 CSS 重新仿制旧画面：拒绝

当前透明 DOM 原本只是命中和无障碍层，最终版的玻璃、文字、按钮景深和章节构图主要由 WebGL 绘制。纯 CSS 重画会形成第二套近似视觉、重复业务文案和长期双轨，不能保证与最终版一致。

### 5.3 定向恢复历史视觉投影链：采用

以当前业务组件为 owner，按 `963df61` 恢复正常动态模式所必需的液态画布生命周期、纹理、着色器分支和最小视觉投影事件。旧代码只作为实现证据；每个恢复片段都必须重新适配当前类型、文案、业务状态和清理规则。

该方案能够恢复已确认画面，同时避免整体回滚和另造一套 CSS 页面。

## 6. 目标架构

### 6.1 业务 DOM 保持 owner

About、Download、Community、Support、LanguageMenu 继续拥有真实业务状态、点击、键盘、焦点、表单、Repository 和无障碍语义。`LiquidGlassHome` 只消费最小视觉快照，不发起 API、不写业务状态，也不决定业务操作结果。

### 6.2 `LiquidGlassHome` 恢复跨章节视觉职责

正常动态模式恢复以下职责：

- 首页 Logo、核心 Hero、流体背景、指针与点击波纹；
- 首页到介绍章的玻璃分裂与五块能力构图；
- 下载章的深色液态背景、玻璃信息层和平台视觉，与当前 3D 模型共同呈现；
- 共享仓库章的标题、页码／卡片数量和玻璃构图；
- 支持章的左右两组反馈／支付按钮、活动索引和 `0 / 2.5 / 5px` 景深；
- 五章节之间连续、原位的视觉交接。

液态画布正常动态生命周期恢复覆盖完整章节进度。`ChapterBackdrop` 继续服务减少动态效果、WebGL 失败和静态回退，不在正常动态模式覆盖最终液态画面。

### 6.3 最小视觉投影

只恢复最终画面确实需要的投影：

- 通用点击波纹；
- About 当前悬停／拖拽视觉；
- Community 当前卡片数量或页码视觉；
- Support 左右活动索引。

投影只携带有限、可校验、无敏感信息的数字或枚举快照，不携带 Repository、DTO、对象地址、状态令牌或用户正文。不得借恢复视觉建立新的全局业务总线。

恢复的事件契约限定为历史最终版中已经存在的 `LIQUID_GLASS_RIPPLE_EVENT`、`LIQUID_GLASS_INTERACTION_EVENT`、`LIQUID_GLASS_COMMUNITY_CARDS_EVENT` 和 `LIQUID_GLASS_SUPPORT_SELECTION_EVENT`。不得恢复没有有效消费者、会让整棵组件树随指针移动重复渲染的 `useWebsiteController.pointer` 状态。

### 6.4 减少动态效果与失败路径

`prefers-reduced-motion` 和 WebGL 初始化失败继续使用当前无 GPU DOM／CSS 路径：

- 不编译 shader、不创建纹理和 ticker；
- 所有章节文本、按钮和核心操作可见可用；
- 不把用户的减少动态效果偏好记录为初始化失败；
- 从正常模式运行时切换为 reduce 时完整释放 GPU 资源，切回时可重新建立；
- 页面隐藏、窗口失焦、卸载和章节暂停必须清理 RAF、ticker、监听器、纹理、buffer 和 program。

## 8. TDD 与双重验收门

### 8.1 自动化 RED

修复前必须建立能够稳定捕获本次回归的测试，至少证明：

- 替换现有错误契约：`exitProgress = 0 / 1 / 2 / 3 / 4` 时液态画布仍活动，到 `4.08` 才允许退出，不再保留“`1.08` 后释放”的旧断言；
- 介绍、下载、社区和支持所需纹理、uniform 与状态投影确实进入 WebGL Adapter；
- 支持页两个三项按钮组的活动索引和景深进入渲染链；
- 共享仓库桌面卡片的 CSS 网格中心与 WebGL 归一化中心使用同一组可计算数值，基础中心误差不超过 1 CSS px；窗口尺寸变化时重新计算，`900px` 及以下的可滚动 2／1 列布局不绘制无法同位的卡片玻璃；
- 减少动态效果和 WebGL 失败时不创建 GPU，DOM 操作仍可见；
- 当前共享资源、审核、下载计数、i18n 和管理员行为测试保持通过。

测试通过公开模块接口和可观察 WebGL／DOM 行为验证，不用只检查源码字符串来冒充画面正确。

另增加且只增加一个桌面正常动效 E2E：固定 Chromium、`1440×900`、DPR 1、中文、`prefers-reduced-motion: no-preference` 和确定性 seed，依次吸附五章并验证活动章、液态层活动状态、WebGL 初始化、Canvas 缓冲区／视口覆盖以及每章核心前景的非零可见边界。恢复后临时把生命周期阈值改回 `1.08`，确认上述门会 RED，再立即恢复 `4.08` 并确认 GREEN；该 mutation 只作敏感性验证，不进入提交。

### 8.2 真实视觉门

正常动态模式至少保存以下同视口、同章节稳定条件的验收图：

- `1440×900`：首页、介绍、下载、共享仓库、支持五章；
- `390×844`：减少动态效果下的支持章；
- `568×320`：减少动态效果下的整站边界。

每章先等待控制器精确吸附到整数进度，再按页面自身加载状态等待；下载模型必须等待成功或明确错误，不以固定短等待冒充完成。

WebGL 动态背景存在时间、GPU、ANGLE、字体光栅化和平台差异，因此不把正常动效整幅 WebGL 像素快照做成阻断性 `toHaveScreenshot`。自动化锁定职责和可见结构，人工截图与 `963df61` 逐章对照锁定最终观感；两者必须同时通过。视觉对照不能单独作为坐标正确证据：还要对比 donor 与候选的关键 shader／生命周期数值，并在真实浏览器中读取 DOM `getBoundingClientRect()`、Canvas CSS 尺寸、drawing buffer、DPR 和 WebGL 基础中心换算值；任何有意数值差异都要记录原因。五张正常动效和两张减少动态效果截图作为带元数据与 SHA-256 的人工视觉证据写入 `docs/operations/evidence/`，不只保存在被忽略的 Playwright 输出目录。

### 8.3 发布前强制检查

部署前必须由主智能体逐章打开本地发布候选，明确确认：

- 页面不是空白或只剩放射背景；
- 正常动态模式为最终深色液态视觉；
- 透明 DOM 与 WebGL 视觉命中位置一致；
- 下载 3D 模型、共享资源数据和支持页按钮都可见；
- 控制台无未处理错误；
- `prefers-reduced-motion` 仍可用。

没有这组新鲜证据时禁止重新覆盖上海 Hosting。
