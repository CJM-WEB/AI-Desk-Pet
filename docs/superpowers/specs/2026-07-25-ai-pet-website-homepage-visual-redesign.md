# AI Pet 官网首页视觉重做设计规格

## 1. 文档目的

本文定义 AI Pet 官网视觉重做的整体展示机制，以及第一模块（首页）的视觉、动效、交互、状态和验收规则。

本轮只重做 `apps/website` 的官网视觉层。现有 Agent、后端接口、数据协议、部署结构和其他应用不在修改范围内。后续官网模块仅预留接入边界，本规格不设计其具体内容。

## 2. 设计目标

官网不采用由滚轮直接推动页面上下位移的传统浏览方式。用户输入将驱动连续的场景进度：当前模块逐渐缩小并淡出，下一模块从场景深处显现，形成在网站内部穿梭的体验。

首页需要完成以下目标：

- 建立 AI Pet 的强品牌第一印象。
- 在黑屏中以书写方式展示 `AP` 标志。
- 通过弹性收束和背景变灰进入可交互状态。
- 使用鼠标光场、品牌朝向和漂浮文件建立空间感。
- 通过文件预览暗示 AI Pet 对不同文件类型的理解能力。
- 保持动效实现可配置、可替换，不把组件绑定到特定输入方式。

## 3. 已有素材

首页复用 `apps/website/public` 中现有的八张透明背景图片：

- `AP.png`：品牌标志。
- `TxtIcon.png`：文本文件。
- `PDFIcon.png`：PDF 文件。
- `PPTIcon.png`：演示文稿。
- `XLSIcon.png`：表格文件。
- `IMGIcon.png`：图片文件。
- `empty.png`：空文件夹。
- `Noempty.png`：非空文件夹。

不得为相同用途重复创建新的素材目录。Logo 书写动画可以增加一份仅用于动画遮罩的矢量路径，但最终静态画面必须使用原始 `AP.png`，避免矢量描摹改变品牌细节。

## 4. 技术方案

采用 GSAP、React DOM、CSS 3D 和 Canvas 的混合方案：

- GSAP 负责开场时间轴、章节进度、缩放、渐隐渐显和弹性动画。
- React DOM 负责 Logo、文字、文件图标及文件预览。
- CSS 3D 负责品牌组朝向鼠标的轻微倾斜。
- Canvas 负责鼠标影响区域和延迟消散轨迹。
- Logo 书写使用矢量路径遮罩，完成后无缝切换为 `AP.png`。

不采用自建完整动画引擎，也不把首页整体放入 Three.js。前者会增加长期维护成本，后者会让文本交互、无障碍和后续普通官网内容接入变得复杂。

## 5. 模块边界

### 5.1 ExperienceController

维护统一的归一化场景进度、当前章节和章节切换状态。首页与后续模块只消费进度，不直接监听滚轮。

### 5.2 InputAdapter

将滚轮、触控板、方向键、Page Up 和 Page Down 转换为统一进度变化。未来可以替换为按钮、触摸或传统滚动适配器，而不修改各场景动画。

### 5.3 IntroSequence

负责黑屏、Logo 书写、Logo 弹动、背景变灰和 “AI Pet” 字标显现。它只输出确定的阶段状态，不负责文件队列和鼠标效果。

### 5.4 BrandStage

负责品牌组布局、中央安全区和朝向鼠标的 CSS 3D 效果。

### 5.5 CursorField

使用单一 Canvas 绘制鼠标影响区域和延迟轨迹。Canvas 只提供装饰，不承载必须阅读的信息。

### 5.6 FileSwarm

管理文件图标队列、随机布局、进入、悬浮、退出、悬停冻结和预览内容。

### 5.7 PreviewContentPool

按文件类型维护结构化本地模拟内容。组件只读取配置，不在组件内部散落文案。

## 6. 场景进度与导航

页面使用连续进度配合章节边界轻吸附：

- 输入首先累积为平滑的归一化进度。
- 用户可以连续控制动画，不会被强制逐屏跳转。
- 接近章节边界且输入速度降低时，进度吸附到稳定状态。
- 首页退出时，品牌、文件和光场使用不同速率缩小并淡出。
- 后续模块接收同一进度系统，但本轮只实现接入边界或必要占位，不设计内容。

所有关键参数集中管理，包括输入灵敏度、阻尼、吸附阈值、缩放范围、持续时间和缓动曲线。

## 7. 首页时间轴

### 7.1 黑屏书写阶段

默认持续约 1.4 秒，实际值通过配置调整。

- 页面初始背景为纯黑。
- 文件图标、鼠标光场和交互预览均不出现。
- `AP` 标志以矢量描边遮罩逐笔显现。
- 标志在书写期间始终位于视口中央并保持较大尺寸。
- 描边结束后无缝切换到原始 `AP.png`。

### 7.2 品牌落定阶段

默认持续约 0.8 秒，实际值通过配置调整。

- Logo 先小幅放大，再通过弹性缓动缩至最终尺寸。
- 背景同时从黑色过渡至 `rgb(235, 235, 235)`。
- “AI Pet” 在 Logo 下方通过字距展开和淡入出现。
- Logo 与字标形成统一品牌组，位置保持居中。

开场默认自动播放，期间暂不接受普通章节导航。用户触发滚轮、点击或方向键时，立即结束开场并进入可交互首页的稳定状态，不播放压缩版动画，也不忽略输入。

### 7.3 可交互阶段

- 品牌组根据鼠标位置产生幅度受限的 CSS 3D 倾斜。
- 鼠标周围形成 `rgb(180, 180, 180)` 的柔和影响区域。
- 影响区域自然融合到 `rgb(235, 235, 235)` 的页面背景。
- 鼠标移动后保留延迟轨迹，并在配置时间内恢复为基础背景色。
- 文件图标在品牌落定后逐个进入，形成持续但克制的背景活动。

### 7.4 首页离场阶段

- 滚轮或键盘继续推动章节进度。
- 首页整体不是向上移动，而是向视觉深处缩小。
- 品牌、文件和光场分层缩小并渐隐，制造空间纵深。
- 进度接近边界时轻微吸附，再激活下一模块。

## 8. 文件队列与布局

- 同时最多存在 10 个文件图标。
- 图标从七种文件素材中随机选择，允许同类重复。
- 图标逐个出现、悬浮一段时间，再逐个消失。
- 进入和退出均结合透明度、缩放和弹性缓动。
- 存活阶段使用幅度较小、速度较慢的悬浮运动。
- 中央视口约 30% 的区域作为品牌安全区，文件不得进入。
- 布局生成时尽量避免文件之间重叠。
- 位置、尺寸和旋转必须设置合理边界，图标不得被视口裁切到无法识别。

每个图标生成时保存以下稳定数据：

- 唯一标识。
- 文件类型。
- 位置、缩放与旋转。
- 对应预览内容。
- 进入时间与剩余生命周期。
- 当前阶段和悬停或聚焦状态。

组件重新渲染不得改变仍在显示的图标内容或位置。

## 9. 文件预览

预览采用跟随鼠标的悬浮内容层：

- 预览层位于文件图标和普通背景内容之上。
- 预览与鼠标保持固定视觉偏移，并使用轻微阻尼跟随。
- 接近视口边缘时自动切换到鼠标另一侧，保证内容完整可见。
- 鼠标移开后快速淡出。
- 图标获得键盘焦点时显示相同预览，失去焦点时关闭。
- 图标到达预定消失时间但仍被悬停或聚焦时，冻结剩余生命周期。
- 鼠标移开或失去焦点后恢复倒计时，再执行退场。

预览内容在图标生成时从对应类型的本地内容池随机选择一次，在该图标整个生命周期内保持不变。

## 10. 本地内容池

运行时不调用 AI、Agent 或后端接口。各类型内容结构如下：

- TXT：短笔记、待办事项或对话摘录。
- PDF：文档标题与简短摘要。
- PPT：演示标题与两至三个要点。
- XLS：小型表格或数据概览。
- IMG：图片标题、描述和基础信息。
- 空文件夹：明确的空内容状态。
- 非空文件夹：简短文件清单。

内容池需要具有统一类型定义。以后可只替换配置数据，也可以在不改变预览组件的前提下接入真实数据源。

## 11. 状态管理

首页采用以下明确状态：

`loading → drawing → settling → interactive → exiting`

- 素材准备完成后从 `loading` 进入 `drawing`。
- 描边结束后进入 `settling`。
- 品牌落定后进入 `interactive`。
- 场景进度离开首页稳定区后进入 `exiting`。
- 跳过开场时，所有开场属性直接设置为 `interactive` 的稳定值。
- 浏览器标签进入后台或页面失去焦点时暂停动画计时，恢复后从原状态继续。

随机布局使用会话级随机种子。普通访问每次可获得不同组合，自动化测试可以传入固定种子获得稳定结果。

## 12. 降级与异常处理

- 单个文件素材加载失败时，从候选池中排除该类型，其他类型继续运行。
- Logo 描边资源失败时，直接对 `AP.png` 执行淡入和弹性落定。
- Canvas 不可用时取消鼠标光场和轨迹，不影响品牌与文件内容。
- JavaScript 尚未加载时，不得用默认样式永久隐藏可索引的基础品牌内容。
- 动画初始化失败时，页面应进入可见的静态首页，而不是停留在黑屏。

## 13. 性能约束

- 高频动画主要改变 `transform` 和 `opacity`。
- 鼠标事件只更新目标状态，Canvas 绘制统一由 `requestAnimationFrame` 驱动。
- Canvas 设备像素比设置上限，防止高分屏绘制面积无限增长。
- 文件图标数量严格限制为 10 个。
- 避免在动画循环中读取会强制布局的尺寸信息。
- 动态首页使用范围受控的客户端组件，其他官网内容继续保留静态渲染能力。
- 常见桌面设备和 1440p 视口下以接近 60 FPS 为目标。

## 14. 桌面端与无障碍边界

本轮以电脑端为设计和验收重点：

- 重点支持鼠标、滚轮、触控板和键盘。
- 不设计移动端布局、触摸手势和移动端特效。
- 窄屏只保证页面不崩溃、不锁死，移动端完整方案另行设计。
- 文件图标可以通过 Tab 聚焦，并显示清晰的焦点状态。
- 方向键、Page Up 和 Page Down 可以推动章节进度。
- 页面不得依赖可见的操作说明才能使用。

当系统启用 `prefers-reduced-motion` 时：

- 跳过 Logo 书写、弹性动作、3D 倾斜和鼠标轨迹。
- 使用短暂淡入淡出完成状态变化。
- 保留品牌、文件内容、键盘导航和章节访问能力。

## 15. 验收与测试

### 15.1 单元测试

- 输入到归一化进度的映射。
- 章节边界吸附。
- 文件队列数量上限。
- 品牌安全区与图标边界。
- 图标之间的基础避让。
- 悬停和聚焦时冻结生命周期。
- 文件类型到内容池的映射。
- 固定随机种子产生稳定结果。

### 15.2 交互测试

- 开场正常自动播放。
- 滚轮、点击或方向键可以跳过开场。
- 滚轮和触控板可以平滑推动首页离场。
- 键盘可以控制章节进度。
- 悬停和聚焦可以打开对应预览。
- 预览在视口边缘自动换位。
- 页面切到后台后动画暂停，恢复后不会一次性过期。
- 素材或 Canvas 失败时进入预期降级状态。

### 15.3 视觉与性能测试

Playwright 至少覆盖：

- `1440 × 900` 桌面视口。
- `1920 × 1080` 桌面视口。
- 系统减少动态效果模式。
- 一个窄屏防崩溃场景。

截图与运行检查需要确认：

- Logo 与字标始终处于正确视觉中心。
- 文件图标不遮挡中央品牌。
- 文本不会超出预览容器或视口。
- 动画过程中无明显布局跳动。
- Canvas 非空，光场会跟随鼠标且轨迹能正常消散。
- 首页退出具有分层缩小效果，不表现为普通纵向滚动。

## 16. 不在本轮范围内

- Agent 或后端功能修改。
- API 接口新增或调整。
- 运行时 AI 生成悬浮预览内容。
- 后续官网模块的具体内容和视觉设计。
- 移动端完整适配。
- 部署上线。
- Git 提交。
