## 目标、证据与范围

修复普通发送无法可靠进入任务、角色 JSON 故障阻断聊天，以及状态建议不能稳定落实为动作的问题。[本轮诊断](../../operations/2026-09-08-chat-task-expression-diagnosis.md)已复现 Qwen/DeepSeek 将读取要求返回为聊天，以及 DeepSeek 在“你表现得开心一点”连续两次返回空白。角色源码还存在无动画照常移动、活动与心情争抢、空候选终止旧播放的规则冲突。

保留 Electron 分层、DeepSeek、内置 Qwen、现有 Provider 传输和 Runtime、有限 OpenCode Core、任务范围及具体许可、现有角色包／工作室／Pixi 播放器。MCP 继续禁用；网站、CloudBase、扫描器、依赖解析、打包和推送不在范围内。锚点与区域保留现有入口，不扩展。

对比三种处理：继续调整联合 JSON 无法消除正文与表现的失败耦合；强制所有回复选择“终答／任务”工具已做过失败实验；本次采用原生正文／任务申请，随后独立进行精简表现决策。它增加模型调用，但能复用已有 Core、Provider 与角色引擎，不引入另一套文件执行或权限框架。

## 单一入口与原生任务申请

聊天界面只保留一个发送按钮及 Enter 行为。删除 `ChatSubmissionIntent` 的产品分支、明确任务按钮，以及普通输入按关键词／正则绕过模型进入任务的路径。用户当前原文和已有经披露批准的会话历史交给聊天模型，人设继续作为受宿主协议约束的系统消息。

主请求不携带 `response_format` 或角色状态／动作 Schema。它提供一个原生函数 `request_task_authorization`，参数严格为 `{}`，使用 `toolChoice:auto`。该函数没有文件／进程 handler，只表示请 Main 展示当前任务范围卡；目录、命令集合、模型、授权根、generation 和输入由 Main 绑定。合法申请可以没有正文；附带的叙述不作为已执行证据，也不阻断合法申请。未知函数、多调用、空调用 ID、非法或额外参数均不进入授权。

主提示明确三点：用户要求实际查阅、修改文件或执行命令时申请任务；讨论、引用、示例和否定本身不申请；尚未读过目录时不能声称知道内容。“目录是不是很乱”先表示未查看并征求同意；“可以，先看看”结合同一会话历史提出申请。模型判断不等于授权，所有文件副作用仍在范围确认之后。

Main 接纳申请后直接复用当前 `prepareCapabilityTask`、披露流程和 Core；不等待表现决策。任务完成、失败、取消或边界变化仍使许可失效。历史用于理解目标，不继承旧许可。可信工具结果继续是成功事实的唯一来源。

本项目借鉴 `D:/AgentLearning` 固定提交 `2a6be0a03b93a6734070e10a6c3b56863475f214` 的原生消息／工具／权限分离方式；没有复制新的执行框架或增加依赖。

## 两次请求与交付时序

普通用户轮次最多包含一个主请求和一个表现请求，按顺序执行，不让 Qwen 单 slot 同时承担两者。主请求先得到有效正文，表现请求随后只接收当前用户文字、角色公开描述、当前心情／状态、最近动作及 Main 布尔事实。不向表现请求额外传入任务工具输出、文件正文、目录快照、路径设置或任务历史正文。

主请求仍使用当前会话的 Provider、取消与披露边界。表现使用同一已选择 Provider，不能静默换模型；它无工具、无任务申请字段。普通聊天等表现结果后，在同一轮先交付表现再提交正文。表现最多等待 12 秒；超时、空响应或格式失败时取消该表现请求，正常提交已得到的正文，不把聊天变成格式错误。超时后不接纳迟到动作，也不重复请求碰运气。主请求失败则本轮不再发起表现请求。

暂停、重置、关闭、角色／Provider／配置变化会撤销本轮请求与尚未执行的行为。取消用户轮次不提交旧正文；仅可选表现失败则保留正文。后台自主请求继续受现有唯一预算持有者约束，用户交互先取消后台请求，不能排在它后面等待。

## 精简表现协议

模型只负责描述理解与选择，不再决定毫秒数、心情淡入、强度资格区间或运行事实。正式表现输出为严格对象：

- `moodUpdate`：`null` 或 `{summary,strength}`；描述自己的感受，强度为 0..1。
- `expressionPlan`：`null` 或 `{states:[{stateId,score,activity,actions:[{actionId,score}]}]}`。`activity` 为 `null` 或现有六个事实名之一：`moving/dragging/carrying/chatting/taskRunning/awaitingConfirmation`。状态最多 8 项、总动作最多 32 项；分数为 0..1、ID 唯一且属于本轮已发送的合法配对。
- `requestKind`：`ambient/state/action/movement`，区分日常表现与用户本轮直接要求。只解释真实当前用户文字，引用和角色描述不能制造明确请求。
- `explicitPlayback`：`null` 或 `{stateId,actionId?}`。`action` 要求精确动作 ID，`state` 允许在其下选择；`ambient` 不执行明确播放。
- `movementControl`：复用既有 `keep/set_mode/move_once` 及固定方向／距离、0/1/2 模式；明确本地指令已处理时不重复执行。自主／活动匹配请求不能返回明确播放或运动控制。

自然语言“表现开心一点”也可由模型识别为明确状态请求；不要求用户掌握一组固定句式。现有明确停止和精确名称处理可保留为宿主捷径，不能成为模型理解任意自定义动作的必要前提。普通请求不选择 `agentInferable=false`；明确请求可以选择当前角色真实存在的对应配对。

适配器把合法语义结果转换为现有 Engine 输入：情绪候选使用无事实条件的有限 episode，强度区间沿用本地心情存活阈值 0.02..1；活动候选使用对应事实为真的 condition、强度区间 0..1。心情衰减沿用本地半衰期默认值，聊天淡入为零；自主心情保持本地渐入。计划有效期、状态驻留、动作循环／冷却／防重复仍由宿主和作者配置决定。模型不能用短有效期加长淡入让候选永远不可播放。

## 一个引擎内的仲裁与生命周期

作者状态仍全部自定义，只有 idle 是必要兜底；`activity` 是当前候选的适用事实，不是官方状态类型或主／修饰分类。

已发生的活动优先于普通心情表现；其中实际移动只能选择明确适用于 moving 的候选。心情继续独立计时，活动结束后重新根据当前心情和有效候选选择，不直接恢复已经过期的旧状态。活动候选不依赖情绪强度，不能因新心情覆盖而丢失已匹配的行走能力；角色、皮肤或对应运行生命周期失效时清除缓存。普通新消息引起的请求修订只撤销在途推断，保留已接纳的活动候选与有限播放。已接纳的活动匹配作为当前角色能力缓存，不随情绪计划有效期消失；每次准备和播放仍校验实时事实、素材、冷却与失败记录，避免持续模式在默认计划到期后无故停下。

成功的日常 `expressionPlan:null`／空候选代表无新匹配，不是停止命令。它退役旧情绪候选的未来播放资格，保留当前播放 token 的原截止、循环和中断规则直到正常结束；不续命，不重新播放，也不把旧情绪候选绑定为新情绪。表现请求失败或宿主未提供计划不等于这个成功的无匹配结论。只有活动候选的非空计划仍保留独立心情候选，供活动结束后使用。明确停止、reset、资源失败和活动结束仍即时撤销不适用表现。明确动作默认一遍，明确状态沿用作者有界时长；结束后恢复正常择态。

已选状态下动作仍考虑模型分数、作者偏好、冷却及近期重复，避免反复播放同一动作；时间流逝不依赖下一条聊天。长期未互动的心情重评和无消息自主反应继续保留。

## 统一移动前置条件

一次移动、持续模式、间断模式和连续续行都经过同一检查：存在适合 moving 的合法候选、可解析素材且可开始播放，才能启动位移。移除八秒到期后使用 idle 位移的降级。

复用现有播放 token 和 `started/failed/interrupted` 回报建立准备步骤：Main 先准备对应活动表现，Renderer 回报相同 token 已开始后再启动位移。准备阶段保持真实 `moving=false`，只标记待移动，不伪造运行事实。已在播放的同一有效行走动作可以复用。最多等 1.5 秒首帧确认；失败、超时或失效时撤销准备并保持位置。后续播放失效时停止位移，不允许切到 idle 继续滑动。

持续／间断模式在首次需要移动却没有语义匹配时，复用无工具表现请求进行一次按描述的 moving 匹配；同一角色／Provider／模式生命周期内不因每次 tick 或拒绝结果反复请求。该请求属于模式执行的准备，只在空闲、无任务和无拖拽时运行，与后台心情重评共用在途槽；用户输入会取消它。没有候选则保持不动，等待用户配置或下一次明确请求。模式设置仍保留，不擅自改回 0。

明确请求确定无匹配时提示“请先配置对应状态和动作”；模型超时／协议失败只能说明本次动作未执行，不能把未确定原因说成素材缺失。日常聊天无匹配不打扰用户；模式自动尝试的相同缺失提示每个生命周期最多一次。

## 迁移与删除

新路径通过对应测试后，删除正式聊天的联合 JSON 生成／修复和 `capabilityPlan` 模型解析、任务提交意图分支、任务按钮及旧语义路由入口；宿主内部若复用已有结果类型，不保留第二条模型协议。旧 Engine 时间字段仅可作为 Main 内部输入，不再暴露给模型。删除专门固化旧降级行为的断言，保留未受影响的权限、取消和流式任务测试。

不删除用户角色、素材、人设或迁移数据，不批量清理文件。只有替代成功后的死路径才退役；不为缩短测试修改文件工具或放宽授权。

覆盖旧文档的范围：明确任务入口优先交付、两个未通过的联合输出实验作为正式入口候选的后续地位、角色联合 JSON 输出、活动受心情门槛限制、无匹配即时中断，以及允许 idle 位移。原历史失败和验收日期保留，不改写成成功。

## 验证与完成标准

先用最小失败测试覆盖四组已知因果：原生申请不依赖角色 JSON；表现坏／慢时正文仍可交付；移动优先及心情保留；没有对应播放就零位移。增加与改动直接相关的非法工具、范围前零副作用、reset／取消及迟到 token 检查。

有限真实验收使用同一个发送按钮：两模型分别验证日常问候、自然读取、讨论目录→同意→读取，以及明确开心／行走。每项记录是否申请、真实工具结果、表现是否发生；不以静态测试数量替代体验。真实 Windows 首帧、位移和停止后的状态必须区分程序观测与用户观察。Qwen 的历史格式错误尚未完整复现，不能在无证据时宣布全部偶发问题清零。

运行受影响包定向测试和类型检查，再运行桌面、行为／角色、安全、集成及必要 Electron 门禁；重复覆盖的底层测试仅执行一次并记录等价覆盖，不反复跑大矩阵。完成后仅本地 Git 提交，停在可供用户体验的开发版本。
