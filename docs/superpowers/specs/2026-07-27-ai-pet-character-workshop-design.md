# AI 桌宠角色工作室与序列帧角色系统设计

> 文档状态：已确认设计
> 产品代号：`Myself`
> 目标平台：Windows 10/11
> 基准日期：2026-07-27
> 上层约束：[AI 桌宠产品全局设计与演进计划](./2026-07-20-ai-desktop-pet-master-design.md)
> 关联设计：[多模型、Agent 与 MCP 系统设计](./2026-07-27-multi-provider-agent-mcp-design.md)；[文件夹空间与资源管理器图层设计](./2026-07-27-explorer-pet-space-design.md)

## 1. 文档目的

本文定义 `Myself` 的可自定义角色系统，包括角色工作室、序列帧素材导入、内部编译、状态与动作模型、交互锚点、运行时降级、角色包分享和资源安全边界。

该系统解决两个看似冲突的目标：

1. 所有角色共用一套稳定的行为、情绪和任务状态系统。
2. 用户不受统一骨骼、角色体型或画风限制，可以使用自行准备的图片创建任意 2D 角色。

最终方案不要求骨骼绑定，也不要求用户成为专业角色制作者。任何用户都能新建角色、导入一个待机动作并立即使用，之后再逐步补充其他动作。

## 2. 已确认的核心决策

1. 采用“统一行为协议 + 无骨骼序列帧角色包 + 交互锚点”架构。
2. 用户可以导入一张包含全部帧的精灵图，也可以导入多张独立单帧图片。
3. 应用不提供图片或动画生成能力，只负责导入、切帧、排序、编辑、校验、编译、预览和播放。
4. 角色不是一张基础立绘，而是状态、动作、序列帧和锚点组成的可编辑配置。
5. 用户创建角色后可以直接使用，不需要先导出角色包。
6. 导出角色包只用于分享、备份和跨设备迁移。
7. 不区分“普通用户”和“角色制作者”，所有用户使用同一套角色工作室。
8. 系统不检测不同动作是否属于同一个角色，素材一致性由用户负责。
9. 系统核心状态固定且不可删除，但用户可以新建扩展状态。
10. 缺少目标状态动画时继续播放当前角色的待机动画，不影响桌面位移和任务执行。
11. 首次启用动作不完整的角色时必须明确提示用户。
12. 完整角色编辑功能位于桌宠客户端内部的独立“角色工作室”大窗口，不放入聊天气泡。

## 3. 非目标

本设计不包含以下能力：

- 自动生成角色图片、序列帧或视频。
- 自动拆分身体部位或生成骨骼。
- Live2D、Spine 或其他统一骨骼格式。
- 自动判断不同状态是否为同一个角色。
- 自动修复画风、服装、面部或体型不一致。
- 允许角色资源执行脚本、插件代码或系统命令。
- 将导出角色包作为角色启用的前置步骤。
- 让角色动画结果决定真实文件任务是否成功。

## 4. 核心概念

### 4.1 角色

角色是一个持续可编辑的本地配置工作区，包含：

- 角色名称、封面和显示尺寸。
- 系统状态和用户扩展状态。
- 每个状态下的一个或多个动作。
- 每个动作的序列帧、时间参数和交互锚点。
- 编辑源文件和运行时编译产物。

角色可以不完整，但启用前至少需要一个可正常播放的待机动作。

### 4.2 状态

状态表示角色当前所处的语义阶段，例如待机、思考、移动或搬运。状态决定“现在应该表达什么”，但不直接包含具体画面。

状态分为两类：

- 系统核心状态：由桌宠行为系统和 Agent 任务流程触发，不可删除。
- 用户扩展状态：由用户创建并配置触发方式，可以编辑和删除。

### 4.3 动作

动作是某个状态下可播放的一段具体动画。例如“待机”状态可以包含呼吸、四处张望和打哈欠三个动作。

每个动作至少包含：

- 动作名称。
- 帧序列。
- 默认帧率。
- 是否循环。
- 播放权重。
- 播放完成后的处理方式。
- 方向或条件标签。
- 角色落脚点。
- 可选交互锚点。
- 可选点击区域和碰撞区域。

### 4.4 序列帧

序列帧是动作的视觉内容。导入源可以是：

- 一张规则排列的精灵图。
- 多张独立的 PNG 或 WebP 单帧图片。

首版不把 GIF、APNG、视频或任意动画工程格式作为编辑源，避免隐藏帧时间、颜色和透明度差异增加导入复杂度。后续可以在不改变角色协议的前提下增加解码适配器。

### 4.5 行为命令

行为命令由 Agent、任务状态机、桌面事件或用户交互产生，包含：

- 目标语义状态。
- 目标位置或移动路径。
- 方向和速度。
- 需要挂载的文件或物品。
- 状态持续时间。
- 完成、取消或失败后的后继状态。

行为命令不关心角色是人形、动物、物品还是抽象形象。

## 5. 系统架构

```text
Agent、任务状态机与桌面事件
              │
              ▼
         行为命令层
  状态、位置、方向、速度、目标
              │
              ▼
         角色状态控制器
  状态切换、动作筛选、权重选择、降级
              │
              ▼
         序列帧播放器
  帧时间、循环、方向、锚点、静态降级
              │
              ▼
         桌面呈现层
  角色位移、文件挂载、气泡、特效、点击区域
```

系统行为和角色表现必须分离：

- 系统决定角色何时移动、移动到哪里以及任务是否成功。
- 角色动作只决定移动或执行任务时看起来是什么样子。
- 文件操作结果以本地文件工具返回值为准，不以动画是否播完为准。

## 6. 状态模型

### 6.1 系统核心状态

第一版角色协议包含以下核心状态：

| 状态 | 用途 | 默认播放类型 |
|---|---|---|
| `idle` | 无任务时的基础状态 | 循环或随机短动作 |
| `listening` | 用户输入或桌宠正在接收指令 | 循环 |
| `thinking` | 等待模型或规划任务 | 循环 |
| `moving` | 在桌面上前往目标位置 | 循环 |
| `acting` | 执行一般本地工具或交互行为 | 循环或一次性 |
| `carrying` | 搬运文件、文件夹或其他桌面对象 | 循环 |
| `success` | 任务成功反馈 | 一次性 |
| `error` | 任务失败反馈 | 一次性 |

系统核心状态不可重命名或删除。用户可以为其增加、编辑和删除动作，但 `idle` 至少保留一个有效动作。

### 6.2 内置扩展状态模板

角色工作室可以提供以下可选模板，但它们不属于 Agent 的强制状态：

- 跑步。
- 吃东西。
- 睡觉。
- 坐下。
- 跳舞。
- 害羞。
- 生气。
- 玩耍。

模板只提供推荐名称、触发规则和锚点提示，不提供统一视觉素材。

### 6.3 用户扩展状态

用户可以创建任意名称的扩展状态，并配置一种或多种触发方式：

- 待机期间按概率随机触发。
- 单击或双击桌宠时触发。
- 从桌宠右键菜单手动触发。
- 用户输入命中特定关键词时触发。
- LLM 根据对话情绪选择。
- 指定系统事件发生时触发。

用户扩展状态不能替代、拦截或阻断核心任务状态。高优先级核心状态到来时，扩展状态应被中断；任务结束后回到 `idle`，而不是自动恢复被中断的娱乐动作。

### 6.4 动作池

同一状态可以包含多个动作。运行时先筛选满足方向、情境和资源条件的动作，再按权重随机选择。

为避免机械重复：

- 允许设置单个动作权重。
- 允许设置连续重复冷却次数。
- 允许设置最短待机间隔。
- 不要求所有动作具有相同帧数或帧率。

## 7. 素材导入与内部编译

### 7.1 精灵图导入

用户导入一张包含全部序列帧的图片后，编辑器要求设置：

- 行数和列数。
- 有效帧数量。
- 水平优先或垂直优先读取。
- 是否忽略空白格。
- 默认帧率。

编辑器显示可视化切帧网格，用户可以排除错误帧并调整播放顺序。

### 7.2 多图片导入

用户一次选择多张单帧图片后：

- 默认按文件名自然排序。
- 支持拖动重排。
- 支持删除、复制或追加帧。
- 支持统一设置默认帧率。
- 支持为个别帧覆盖持续时间。

### 7.3 编辑源与运行产物

系统同时保留两类数据：

1. 编辑源：用户原始图片、切帧配置、帧顺序和动作参数，用于后续继续编辑。
2. 运行产物：统一纹理图集、帧坐标、时间信息和锚点数据，用于快速播放。

保存动作时只增量编译受影响的动作，不重新处理整个角色。切换角色时释放旧角色的大尺寸纹理资源，只保留必要缩略图和当前角色资源。

### 7.4 编译原则

- 编译不能破坏用户原始素材。
- 编译失败时保留上一个可用版本。
- 编译产物使用格式版本号。
- 编译过程可以取消。
- 角色运行时不应依赖大量零散原图逐帧读取。

## 8. 角色工作室

### 8.1 入口

角色工作室位于桌宠客户端内部，使用正常尺寸的独立窗口。

入口包括：

- 桌宠右键菜单中的“角色工作室”。
- 托盘菜单中的“角色工作室”。
- 设置窗口中的“角色与动作”入口。

桌宠右键菜单同时提供已安装角色的快速切换，但不承担复杂编辑功能。聊天气泡不放置角色编辑器。

### 8.2 页面结构

角色工作室采用三栏工作区：

1. 左栏：角色列表、系统状态和扩展状态。
2. 中栏：动画预览、帧时间轴、播放控制和素材导入。
3. 右栏：动作属性、循环方式、权重、方向标签和锚点参数。

窗口还提供：

- 新建角色。
- 删除角色。
- 复制角色。
- 启用当前角色。
- 导入角色包。
- 导出角色包。
- 全状态巡览。
- 资源占用摘要。

删除多个角色或批量清理素材属于大量删除操作，执行前必须再次获得用户确认。

### 8.3 新建即用

新建角色后，用户可以立即进入待机状态并导入第一个动作。只要待机动作可以正常播放，就允许启用该角色。

其他状态可以边用边补充，不要求用户一次完成全部角色内容，也不设置专业模式或制作者模式。

### 8.4 实时预览

预览区支持：

- 播放、暂停和逐帧查看。
- 循环预览。
- 背景明暗切换。
- 模拟左右方向。
- 模拟移动速度。
- 显示或隐藏锚点。
- 模拟文件图标挂载。
- 全状态连续巡览。

预览只模拟视觉效果，不执行真实文件操作。

## 9. 交互锚点

### 9.1 基础锚点

| 锚点 | 用途 |
|---|---|
| `ground` | 角色与桌面、任务栏或窗口边缘的接触位置 |
| `focus` | 气泡、视线和状态特效的参考位置 |
| `carry` | 搬运文件或文件夹时的挂载位置 |
| `mouth` | 吃东西、吞入物品或吹气效果的位置 |
| `seat` | 坐在文件夹、任务栏或窗口边缘时的接触位置 |

### 9.2 区域

除点状锚点外，角色可以配置：

- 点击区域。
- 拖动区域。
- 桌面碰撞区域。

区域不要求贴合每个透明像素，但必须能避免明显的空白点击和错误碰撞。

### 9.3 锚点编辑

- 普通动作默认整段共用一组锚点。
- 搬运、吃东西等高交互动作可以启用逐帧锚点。
- 用户可以在预览区直接拖动锚点。
- 左右镜像播放时，锚点随画面一起镜像。
- 未设置可选锚点时，相关桌面物品使用角色边界框推导的保守默认位置。
- `ground` 为每个动作的必要锚点；首次导入时由系统自动放在画面底部中央，用户可以调整。

## 10. 动作缺失与降级

### 10.1 启用条件

角色满足以下条件时可以启用：

- 存在至少一个待机动作。
- 待机动作素材能够解码。
- 待机动作编译成功。
- 角色清单格式受当前版本支持。

### 10.2 状态缺失

目标状态没有有效动作时：

1. 保持真实行为命令继续执行。
2. 角色视觉暂时播放当前角色的待机动作。
3. 不借用其他自定义角色的动作。
4. 不因动画缺失阻断 Agent 或文件任务。

### 10.3 启用提示

首次启用动作不完整的角色时显示：

**标题：部分动作尚未配置**

**正文：**

> 该角色还有部分状态没有对应动画。继续使用时，缺少动画的状态将暂时播放“待机”动作，不会影响角色移动和任务执行。你可以随时回来补充。

操作按钮：

- “返回完善”
- “仍然使用”

该提示只在首次启用角色，或角色从完整状态变为不完整状态后再次启用时显示。角色列表长期显示“部分动作未配置”状态标记。

### 10.4 资源损坏

当前角色的待机动作损坏且没有可用编译版本时：

- 自动切换到官方默认角色。
- 保留损坏角色及其编辑源。
- 显示明确错误和“打开角色工作室”修复入口。
- 不自动删除用户素材。

## 11. 角色存储与分享

### 11.1 本地角色工作区

角色本地数据按以下概念结构保存：

```text
角色工作区/
├─ manifest.json
├─ source/
├─ actions/
├─ compiled/
├─ anchors/
└─ thumbnail.webp
```

- `manifest.json`：角色元数据、格式版本、状态和动作索引。
- `source/`：用户导入的原始素材。
- `actions/`：切帧、帧顺序、时间和动作参数。
- `compiled/`：运行时纹理图集和帧坐标。
- `anchors/`：锚点和区域数据。
- `thumbnail.webp`：角色选择页缩略图。

实际目录位置由 Electron 主进程管理，不向 Renderer 暴露任意文件写入能力。

### 11.2 即时保存

- 角色编辑采用自动保存草稿。
- 正在编辑的动作和当前可运行版本分离。
- 只有编译成功后才替换运行版本。
- 应用崩溃后优先恢复草稿，不覆盖上一个可用版本。

### 11.3 导出角色包

角色包是可选能力，用于：

- 分享给其他用户。
- 本地备份。
- 跨设备迁移。

导出包包含必要角色配置和资源，不包含应用设置、模型密钥、对话、授权目录或文件任务记录。

### 11.4 导入角色包

导入时：

- 先解压到隔离临时目录。
- 校验格式版本、文件类型、文件数量和总大小。
- 拒绝绝对路径、`..`、符号链接和压缩包路径穿越。
- 不执行角色包中的任何脚本。
- 与现有角色同名时创建副本，不静默覆盖。
- 校验完成后再原子移动到角色存储区。

## 12. 技术路线

### 12.1 桌面与编辑器

- Electron 主进程负责系统文件选择器、角色存储、导入导出和资源边界。
- React + TypeScript 实现角色工作室界面。
- Renderer 通过白名单 IPC 请求导入、保存、编译和切换角色。
- Renderer 不接收任意本地路径后自行读取整个文件系统。

### 12.2 图像处理

- 单张精灵图使用浏览器图像解码能力和 `createImageBitmap` 按矩形切帧。
- 多图导入先生成有序帧清单，再编译为统一纹理图集。
- 首版优先使用 Web 平台图像能力，避免仅为切帧引入大型原生依赖。
- 如果后续资源规模证明需要离线高性能压缩，再独立评估专用图像处理模块。

### 12.3 动画渲染

- 使用 PixiJS 的 Spritesheet 和 AnimatedSprite 作为首选序列帧渲染方案。
- 角色位移、方向和桌面交互由运行时控制，不烘焙进序列帧。
- 当前角色资源按需加载并缓存。
- 不活动的角色缩略图不加载完整纹理图集。

### 12.4 格式版本

角色清单必须包含：

- 格式版本。
- 角色唯一标识。
- 状态与动作索引。
- 资源文件校验信息。
- 编译器版本。

读取旧版本时通过迁移器转换；无法迁移时保持原文件不变并提示版本不兼容。

## 13. 性能要求

- 空闲状态不因角色工作室关闭而持续扫描素材目录。
- 空闲桌宠不持续进行网络请求。
- 当前角色只加载正在使用和即将切换的必要动作资源。
- 大型动作按需加载，不要求启动时载入全部角色。
- 纹理尺寸、单帧分辨率、帧数和角色包大小设置明确上限。
- 超过建议值时先提示资源占用，超过硬上限时拒绝编译。
- 角色切换后及时释放旧纹理和临时 `ImageBitmap`。
- 减少动态效果开启时使用动作代表帧，不持续播放序列帧。
- 窗口不可见或系统进入节能状态时降低或暂停非必要动画刷新。
- 编辑器编译不阻塞桌宠任务和文件操作主流程。

具体数值上限由实施计划通过目标设备测试确定，不写死在本设计中。

## 14. 错误处理

所有错误必须说明问题、影响和下一步操作。

| 错误 | 行为 |
|---|---|
| 图片无法解码 | 拒绝该素材，保留当前动作原状 |
| 精灵图网格无法整除 | 允许用户调整网格，不自动裁掉未知区域 |
| 帧尺寸不一致 | 允许导入并统一到逻辑画布，不强制拉伸原图 |
| 帧数或纹理超限 | 说明限制并提供减少帧数或尺寸的建议 |
| 编译失败 | 保留草稿和上一个可运行版本 |
| 角色包版本过新 | 拒绝安装，不修改现有角色 |
| 角色包资源缺失 | 拒绝安装并列出缺失资源 |
| 运行时纹理丢失 | 回退到官方默认角色并提供修复入口 |
| 扩展状态触发冲突 | 核心任务状态优先，扩展状态取消 |

## 15. 安全边界

- 用户图片和角色包均视为不可信输入。
- Renderer 不获得任意文件系统权限。
- 导入资源只允许白名单图片和结构化配置。
- 角色包不支持脚本、HTML、可执行文件或动态模块。
- 所有路径由主进程生成和校验。
- 导入导出操作不得访问用户未选择的目录。
- 压缩包导入必须防止路径穿越、符号链接逃逸和压缩炸弹。
- 删除角色只删除应用角色存储区内的数据，不删除用户原始素材位置的文件。
- 删除官方默认角色始终被拒绝。

## 16. 测试策略

### 16.1 单元测试

- 系统状态不能删除或重命名。
- 扩展状态可以创建、编辑和删除。
- 核心状态可中断扩展状态。
- 动作权重和冷却规则正确。
- 缺少目标状态时回退到当前角色待机动作。
- 锚点镜像和逐帧读取正确。
- 精灵图网格切分、文件自然排序和帧持续时间正确。
- 格式版本迁移不修改原始角色包。

### 16.2 集成测试

- 精灵图导入、编辑、编译和立即启用形成完整闭环。
- 多图导入、重排、编译和预览形成完整闭环。
- 编译失败时仍能运行旧版本。
- 重启应用后恢复角色、草稿和当前启用状态。
- 角色切换后旧纹理被释放。
- 文件搬运动画中的 `carry` 锚点与桌面物品同步。
- 角色工作室关闭后桌宠继续正常运行。

### 16.3 安全测试

- 恶意角色包路径穿越被拒绝。
- 符号链接和超大解压内容被拒绝。
- 未知文件类型和脚本被拒绝。
- 同名导入不覆盖现有角色。
- Renderer 不能通过角色 IPC 读取任意本地路径。

### 16.4 人工验收

1. 新建角色。
2. 导入一张待机精灵图。
3. 调整网格、帧率和 `ground` 锚点。
4. 启用角色并确认动作缺失提示。
5. 继续使用并验证所有缺失状态回退到待机动画。
6. 导入多张搬运序列帧并设置逐帧 `carry` 锚点。
7. 模拟文件搬运并验证挂载效果。
8. 创建一个扩展状态并配置点击触发。
9. 导出角色包，在另一份本地数据目录中重新导入。
10. 验证不导出角色包也能持续编辑和使用。

## 17. 验收标准

- [ ] 所有用户都能在客户端内打开角色工作室。
- [ ] 可以导入精灵图和多张独立单帧图片。
- [ ] 可以编辑帧顺序、帧率、循环、权重和锚点。
- [ ] 待机动作编译成功后角色可以立即启用。
- [ ] 动作不完整时显示已确认的提示文案。
- [ ] 缺少状态动画不会阻断桌面移动或 Agent 文件任务。
- [ ] 系统核心状态不可删除，用户可以创建扩展状态。
- [ ] 同一状态可以配置多个动作并按规则选择。
- [ ] 角色工作区自动保存，编译失败不破坏旧版本。
- [ ] 角色包可以导入和导出，但导出不是使用角色的前置条件。
- [ ] 角色包不能执行脚本或越过角色存储边界。
- [ ] 角色资源加载、释放和低动态模式满足常驻桌面的性能目标。

## 18. 与现有系统的关系

当前 `@myself/character-runtime` 只负责六个基础任务状态的映射。本设计将在后续实施阶段扩展该边界，但不把角色存储、图像编译和编辑器 UI 混入现有状态机文件。

建议保持以下模块边界：

- `character-runtime`：状态仲裁、动作选择、降级和播放契约。
- 角色资源模块：角色清单、格式迁移、导入导出和编译。
- Renderer 角色播放器：PixiJS 资源加载与画面呈现。
- 角色工作室：编辑器界面和预览控制。
- Electron Main：本地存储、系统文件选择器和安全 IPC。

该功能属于独立的大型子项目，应在现有第一阶段文件 Agent 闭环稳定后单独制定实施计划，不直接扩大当前 MVP 的验收范围。
