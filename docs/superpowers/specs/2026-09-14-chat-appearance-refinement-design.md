# 聊天视觉细调规格

依据：用户于 2026-09-14 明确要求执行四项视觉调整。沿用已批准的窗口定位、显隐、鼠标穿透与必要展示通信范围。

## 目标与替代范围

1. 选项菜单以右上方圆球为展开原点向左展开。画布增加透明留白，正常屏幕的输入框仍为 360px，圆球仍为 48px；窄屏收缩输入框，菜单不能越出窗口或遮挡输入。
2. 沿用现有配色，保留浏览器圆角抗锯齿，输入框、选项与发送键增加柔和底部阴影。原生裁区必须包含绘制余量，交互判断仍以原控件区域为准。
3. 历史外层完全透明；删除原生磨砂背板窗口、仅服务该背板的状态和协议。每条消息仍有自身背景并增加轻微阴影，滚轮浏览保持可用。
4. 普通回复气泡维持当前宽度约束，随流式内容增长到最多四行，超出部分在气泡内滚动查看，正文不截断。授权详情维持原有独立滚动区和按钮语义。

本规格仅替代 [原聊天视觉规格](2026-09-13-desktop-chat-visual-redesign-design.md) 中菜单展开方向、历史背板、紧贴控件的原生裁剪以及普通回复高度约束。

## 现状与边界

- 菜单当前 `left: 0`，会向输入框扩展；紧贴按钮圆角的整数扫描线 `setShape` 会裁掉外侧阴影及边缘半透明像素。
- 历史白底来自 CSS 与额外原生 acrylic 窗口，必须同时退役。
- 模型调用、流式解析、消息保存、文件任务、授权判定和桌宠状态决策均不修改。
- 不引入依赖；复用现有布局上报、鼠标观察器和窗口调度。低级鼠标钩子的消息泵性能修复保留。
- 原生绘制区域放宽后，使用原交互区域控制穿透，缓存穿透状态避免重复原生调用；拖动选择的按下/抬起必须成对处理。

## 验收

- 浏览器检查常规及窄屏菜单位置和点击命中、历史透明度与滚动、四行高度和完整末尾。
- 窗口端口检查绘制余量、原交互区域、穿透状态去重、销毁与失败处理。
- 桌面类型检查、构建及定向组件/原生 E2E；区分自动化与真实 Windows 观感。
- 失败沿用现有展示回退，不增加业务处理或新授权路径。
- 不迁移用户数据、不修改外部服务；旧背板实现与对应专用验证同步删除或改为透明窗口验证。
