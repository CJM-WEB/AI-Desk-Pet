# AI Pet 默认角色、持续状态与任务表现协同设计

后续模型选择与真实事件接线以[用途匹配规格](2026-09-12-behavior-event-bindings-design.md)为准；本文的默认资源、长期背景、单一引擎和安全边界继续有效。逐轮完整表现优先、任务终态再推理及仅移动启动匹配已在新规格范围内替代。

日期：2026-09-12。状态：用户已整体批准并已实施；批准包含第 4.3 节九个旧默认资源的备份与替换。实际结果及未覆盖项见[验收记录](../../operations/2026-09-12-character-behavior-continuity-acceptance.md)，本文件不作为功能完成证明。

## 1. 目标与已确认选择

本次逐项解决默认角色替换、动态长期状态、作者描述参与决策、任务与表现协同，以及自主判断的真实情境输入。

用户已确认：

- 以当前本机“全新优质角色”为新内置角色，显示名称精确为 `AI Pet默认角色`。素材、人设、动作、描述及播放设置保持不变。
- 本机原创作角色保留，另安装并启用新的默认角色。
- 当前角色已开启全部状态的智能体推断；以后新建状态也默认开启，保留作者手动关闭的能力，不批量改写其他已有角色。
- 模型根据作者描述判断哪些状态适合长期保持；程序维护持续时间和切换，不要求作者新增长期状态标记。
- 未陪伴情境只依据桌宠聊天、点击、拖拽及自身运行事实，不采集电脑键鼠闲置、屏幕、剪贴板或其他应用活动。

保持同一时刻只有一个活动状态。长期、短时与任务活动描述的是运行生命周期，不重新引入主状态和修饰状态，也不要求用户使用固定的状态名称。

## 3. 方案选择

采用“复用现有单状态引擎，增加持续生命周期和独立表现调度”。

- 仅延长动画时长、补提示词：改动较少，但仍受心情衰减、计划失效及任务分支跳过影响，不能满足本次需求。
- 扩展现有引擎与 Main 调度：复用播放器、候选目录、任务事实、播放 token 和取消机制，作为本次方案。
- 整体重写行为系统或引入新框架：会扩大范围，重复现有职责，本次不采用。

不引入新依赖、第二套行为引擎、固定休息/无聊名称映射或生理数值模拟。官网资源、CloudBase、文件执行核心及权限机制保留。

## 4. 默认角色替换

### 4.1 随包内容

以实施前核对的最新已发布角色为固定快照，包含发布清单、编译资源、草稿和源素材目录。保留图片字节及作者数据，仅调整顶层角色名称、内置稳定 ID 和安装版本标识。

内置 ID 继续使用 `builtin-default`，保持默认角色的删除保护和恢复引用；草稿、发布清单及 `source/catalog.json.characterId` 同步使用此 ID。显示名称使用 `AI Pet默认角色`，不修改人设中的称呼、背景或台词。

默认准备改为读取固定 V3 内容，复用 Schema、资源校验和 `CharacterStore` 事务。删除旧八状态生成逻辑。

### 4.2 已安装数据

将“安装或升级内置默认”和“激活默认”分开。启动能识别旧官方版本并进行一次事务升级；重复启动不反复重写。正常升级不能切走用户选择的其他角色。

本机此次交付明确安装并启用新默认，保留原“全新优质角色”供继续创作。应用仍运行时，先检查实际进程及未完成任务，使用正常退出和既有存储接口；操作前保存角色索引及将被替换的默认数据备份，禁止对活动数据目录并发写入。

若已有默认包含用户修改，先保存可恢复副本再升级，不能丢弃其未发布草稿。事务失败保留恢复材料和仍可用版本，不留下半安装清单。

现有草稿和发布事务彼此独立，并不包含源素材安装，不能声称已有整角色原子升级。安装流程复用既有原子写入和恢复方式，记录最小安装进度：完整校验随包内容及保存旧默认备份 → 安装并核对新源图及源目录 → 提交草稿 → 提交编译版本 → 最后确认内置修订。失败或重启先恢复未完成安装，必要时恢复旧默认；修订未最终确认不得当作升级完成。覆盖源图安装、草稿提交和发布提交之间的故障点，不能留下草稿引用不存在源图的可用角色。

### 4.3 旧内容退役范围

新默认校验通过后，从桌面正式资源目录 `apps/desktop/resources/characters/default/` 移除：

`acting.png`、`carrying.png`、`error.png`、`idle.png`、`listening.png`、`moving.png`、`success.png`、`thinking.png`、`sprite-metadata.json`。

旧资源在实施删除前另存恢复副本并复核绝对路径。本次规格的整体确认同时确认这九个明确旧文件的替换清单；不清理用户其他角色或官网图片。

依赖旧默认的测试改用独立合成素材，不保留旧正式角色作为隐蔽回退。官网只解除“官网示例图片必须等于桌面默认图片”的跨应用测试假设，官网业务与图片保持原样。

## 5. 动态长期状态

### 5.1 语义与生命周期

模型根据状态和动作描述区分短时表现、真实活动适用表现、可长期保持的日常表现。继续只返回合法 ID 和语义选择；Main 决定时间、事实、优先级与实际播放。

表现协议增加独立的长期选择，不把长期状态放进依赖心情强度的短时计划。没有新的长期选择表示保持现有选择；明确重新选择才替换。持续资格来自本轮模型语义判断，但仍须通过作者可推断开关、状态动作配对、当前皮肤和资源检查。

Main 保存当前长期选择、其动作候选和进入时间。持续状态不受短时表现的三秒建议时长、十秒状态冷却、心情归零或短时计划过期驱逐。动画结束只推进该状态内下一次合法播放，不插入待机帧；仍遵守作者动作冷却、中断和播放参数，暂时没有可播放动作时保留当前合法画面。

模型失败、超时或普通空候选不清除有效长期状态。不能以保留长期状态为由重放失效的任务活动或过期明确命令。

### 5.2 仲裁与恢复

复用现有明确请求和活动优先级，在没有适用临时表现时选择当前长期状态；没有有效长期选择才使用 `idleStateId`。此引用继续承担启动、无任何合法候选和资源故障的应急职责。

例如：休息持续 → 任务实际开始，播放工作 → 任务完成，短暂结果反应 → 恢复仍有效的休息。不会每个动画循环都先回待机。任务事实结束后，其活动候选失去该活动的播放资格，不能自动转成长期回退。

长期选择与活动候选分别拥有生命周期。同一作者状态可以适用于多个场景，只有独立验证通过的长期语义选择才能成为长期背景；活动缓存、任务准备 token 及短时计划不能冒充这一选择。程序不按“工作”等显示名称永久禁止状态，也不承诺用固定代码纠正所有模型语义误判。

用户明确要求进入某种长期状态时，由模型按描述同时选择新的长期状态；指定单个动作仍默认播放一遍。明确的新要求可以立即替换旧长期选择。状态退出条件、不可用素材、角色或皮肤变化、reset 和关闭使不适用选择失效；临时拖拽或任务结束只恢复仍可验证的选择。

普通推断与明确目标独立校验：非法可选计划不能让已单独验证的明确目标一起丢失；非法计划不被放宽或用于自主播放。未知 ID、错配动作及无真实明确请求的目标仍拒绝。能够验证请求类型的失败保留准确动作反馈，不把模型失败说成素材缺失。

## 6. 作者描述与新建状态

复用工作室已有状态和动作描述，不增加第二套 AI 专用文本框。描述帮助模型理解用途、适用情境、是否适合长期保持，以及同状态下动作的差别。

候选预算优先保护明确目标及其动作描述、当前长期状态和相关候选；先减少无关候选，再压缩描述。保留现有总输入上限，不通过无限扩大上下文解决问题。预算不足时只呈现实际送出的合法目录，不能接纳未展示 ID；无法容纳必要上下文时给出准确失败，保留现有合法表现。

人物人设、状态描述、动作描述均属于解释数据，不得制造用户命令、真实任务结果或文件权限。

新增状态默认 `agentInferable=true`，复用原开关并说明其作用：允许自主选择，关闭后仍可明确指定。已有角色中作者手动关闭的状态不自动开启。

## 7. 任务与表现调度

### 7.1 两条独立请求

同一次用户输入具有主聊天/任务请求和无工具表现请求。正式任务申请不再跳过表现。

支持并发的远程 Provider 同时启动两条请求；表现准备好即可交付，主回复和授权卡也可独立交付，不用等待另一分支完成。内置 Qwen 当前单推理槽采用表现先行，再发送主请求；动画播放继续与真实任务并行，不增加本地模型并发槽。

预先按描述匹配 `taskRunning`、等待确认等候选只表示可能适用，不能伪造任务已经执行。范围授权前仍无文件或命令副作用。

### 7.2 行为先行的有界准备

复用 Engine 的活动准备及 Renderer 同 token 的 `started` 回报。需要串行准备任务表现时，先请求并尝试开始对应动画，再启动已授权任务；准备期间真实 `taskRunning=false`，Core 开始后才变为 true。

建议沿用表现推理最多 12 秒和首帧确认最多 1.5 秒的上限。超时、无匹配或播放失败时提供准确轻提示，然后继续已授权任务；不能无限阻塞文件任务，也不能假报动画成功。此失败策略随本规格整体确认。

实际任务开始、等待、暂停和终态来自 Main/Core 事件。按这些事实切换已匹配的活动表现，成功和失败以工具结果为准。复用已接纳候选，不在每个工具进度事件调用模型。终态需要模型反应时使用独立、有限的任务事件表现请求；它不发起新文件任务。

终态反馈使用同源 Schema 的缩窄形式，只接纳无活动条件的短时反馈，长期选择固定为空，由 Main 恢复原有有效背景。这样不会把已经结束的任务反馈绑定到不存在的聊天活动，或把默认待机写成新的背景；传输名称继续复用既有自主表现契约。

### 7.3 生命周期与取消

表现分支具有本轮独立 owner、取消信号、会话 generation 和角色修订，允许同一轮从聊天跨入授权等待及执行阶段。不能因为主请求先结束就丢弃合法表现，也不能放开迟到结果校验。

新一轮替代、拒绝或取消授权、任务结束、reset、关闭、Provider/配置变化和角色变化撤销相应在途请求。任务终态反应绑定新的终态事件，不复用已撤销的运行中请求。单推理槽不插入会破坏 Core 在途请求的抢占逻辑，优先使用开始前匹配的活动候选。

主请求失败或非法输出、范围准备失败、授权过期、目标激活失败也必须终止尚未接纳的本轮表现并释放任务准备 token，不能依赖并不存在的 Core 终态事件清理。已经合法开始的独立明确动作按原生命周期处理，不因为主请求失败而伪报其播放失败。

## 8. 自主判断的真实情境

复用 Main 互动观察、任务事件和可注入时钟，提供以下有界运行期摘要：

- 距最近一次桌宠互动的时长及互动类型。
- 本次应用运行时长、本地时段、当前状态和长期状态已持续多久。
- 最近有限窗口内的桌宠互动次数、近期动作及各活动持续时间。
- 当前任务阶段，以及最近一次真实任务终态和距该事件的时长。

聊天表现可以接收用户本轮主动输入，其中可能包含用户自行写出的路径或命令；不从任务设置、文件、命令输出或历史任务正文额外补入这些内容。自主及任务事件摘要只包含阶段、结果和经过时间，不包含路径、正文或工具原始元数据。运行期摘要不新增持久化长期记忆。模型可以据此推测无聊或困乏，但这些是角色解释，不记录成系统观察到的生理事实。

保留首次未互动五分钟、后续十五分钟重评、每滚动小时最多四次的自主调用节制。到点可以保持当前长期状态，不要求每次调用都换动作。真实用户互动才刷新未陪伴计时，模型回应、动画循环及工具进度不算用户陪伴。

聊天、任务中的事件表现与空闲自主重评使用不同触发原因；不为了任务表现去取消所有后台节制。关闭自主判断后，明确命令、已授权任务反馈与基础播放仍正常。休眠恢复一次计算经过时间，不补跑旧调用。

## 9. 影响范围、验证与交付

主要影响 `packages/character-runtime` 的表现协议、Engine 和候选投影，以及桌面 Main 的默认角色安装、Adapter、Coordinator、Director、Service、自主运行器和工作室新状态默认值。Renderer 复用现有按 token 播放与反馈；必要类型通过既有契约传递，不开放新的系统能力。

按五项需求分别实施，先写最小失败测试，再实现最小改动：

1. 默认角色：首次安装、旧默认升级、重启幂等、原创作角色保留、新默认启用、源图/草稿/发布之间中断恢复，九状态资源与作者字段一致。
2. 持续状态：休息连续三十秒和十分钟不插入待机；临时工作后恢复；心情清除、空响应、超时不打断；退出条件、换角色及资源失败能退出；短时动作仍有界。
3. 描述和开关：名称无意义但描述可区分的状态动作正确进入上下文；大目录保护明确目标描述；新状态默认开启、已有关闭保持；合法明确目标不被非法计划连带丢弃。
4. 调度：远程并发及先完成先呈现，Qwen 表现先行，任务申请也有表现，授权前零副作用，首帧准备不伪造任务事实，失败不改任务结果；覆盖 Core 启动前失败、授权过期、取消与迟到响应失效。
5. 自主：五/二十/四十分钟的输入准确，计时和调用预算正确，任务事件不刷新陪伴时长，休眠/reset/关闭不补跑旧请求。

定向测试之后，运行受影响类型检查、桌面/行为/角色所需门禁及安全、集成、必要 Electron E2E。重叠命令执行一次并记录覆盖关系；区分已有失败与本次回归，不把未通过门禁记为成功。

真实验收使用新默认角色，覆盖持续休息、明确开心、描述驱动动作、文件任务开始与结束表现、闲置重评。程序观测到 Renderer 首帧和窗口状态，不能替代用户对视觉自然程度的确认。

实施计划另写 `docs/superpowers/plans/`；实际命令和运行结果另写 `docs/operations/`。本次不自动 Git 提交、推送、发布或制作安装包。
