# 内置 Qwen 单次会话判别与正文协议

日期：2026-09-10，批准日期：2026-09-11。状态：**已按用户批准完成 Qwen 专用适配；定向自动化与子目录有限实测通过，完整稳定性验收未通过。**实际结果及未通过项目见诊断记录，不以本规格代替验收。

适用范围仅为内置 Qwen 的正式 `conversation` 入口。沿用[单一发送与独立表现规格](2026-09-08-single-send-expression-isolation-design.md)、[编程助手规格](2026-09-05-ai-pet-coding-assistant-design.md)及[领域词汇](../../../CONTEXT.md)，只覆盖本文明确列出的局部契约。运行事实见[本轮诊断记录](../../operations/2026-09-10-qwen-subdirectory-diagnosis.md)，旧记录不能替代新方案验收。

## 1. 目标与非目标

目标是让 Qwen 在一次主请求中明确选择“申请实际任务”或“交付普通聊天正文”，减少强角色人设和多轮叙述挤掉任务申请的情况；合法任务决定继续进入现有 Main 范围确认和同一 Core。

保留一个发送入口、原始用户输入、现有会话历史、角色人设、独立表现请求及现有取消与配置失效边界。不增加单独的意图分类请求，不增加关键词路由、自动重试、第二套执行器或权限引擎。DeepSeek 的提示、请求体、返回解释和行为完全不变。其他 Provider、无工具对话、角色自主请求、任务 Core、文件工具、网站、依赖、打包与发布不在本稿改动范围。

本稿不承诺消除模型幻觉或保证所有自然语言意图正确；不把温度 0 当作确定性或语义安全保证。

## 2. 现状与有限证据

已定位的失败是：Qwen 在根目录读取后，对明确同意查看子目录或文件的跟进返回普通正文，缺少对应任务申请和工具结果。Core 已能读取相应子目录及空文件；不能把入口漏调用归因于空文件不存在。

温度调整、提示尾部提醒、精简原生提示、system 重排等候选均留下真实失败；同一失败 HTTP 请求仅更换工具描述也未解决。这里不再把原生 `auto` 提示微调作为已成功方案。

| 隔离证据 | 已观察事实 | 能证明的范围 |
| --- | --- | --- |
| `entry-structured.log` 与 `entry-structured-wire.json` | 单次 JSON 原型 8 条 `kind` 均符合预期；5 条任务中 2 条 `text` 非空 | 原型显示判别方向可行，但旧宽松 Schema 不满足任务空正文契约 |
| `entry-structured-strict.log` 与对应 wire | 严格联合 Schema 复测 8 条均有效：5 条任务正文为空，问候、讨论、拒绝共 3 条为聊天 | 只证明同一既有失败历史下这次固定样本的分类与形状；没有运行任务 Core 或窗口验收 |

这些文件位于会话私有目录 `.superpowers/sdd/2026-09-10-qwen-subdirectory/`。wire 核对到无工具、非流式、温度 0 及 `response_format`；正文和人设不复制到本规格。严格复测的讨论回复仍含没有读取证据的目录描述，说明聊天事实约束尚未解决，不能据 8/8 宣称完整修复。

## 3. 方案与接口

继续由 `ConversationChatAdapter` 生成正式主请求。仅当本地 Provider 接到 `purpose='conversation'`、原正式空参数 `request_task_authorization` 入口及准确宿主提示时，转换为 Qwen 私有会话判别请求；不能依靠用户文本、人设内容或部分字符串匹配触发转换。无工具、其他工具、非主会话及任意其他宿主 system 保持既有处理。

本地模型的一次 HTTP 请求使用 `tools:[]`、`tool_choice:'none'`、`stream:false`、`temperature:0`，通过锁定 llama.cpp 已使用的 `response_format:{type:'json_object',schema:...}` 发送严格联合 Schema。模型不能在该请求中返回原生工具调用。只替换准确宿主提示；人设与其他 system 的字节和相对顺序、用户原文和历史保持，沿用原 system 合并。转换后的完整提示和 Schema 必须先计入既有本地预算，再发送；不通过缩短用户原文或丢弃受保护工具链满足预算。

允许的完整输出只有以下两个分支，每个分支都禁止额外字段：

| 分支 | 严格字段 | 本地处理 |
| --- | --- | --- |
| 实际任务 | `{"kind":"task","text":""}` | 校验后映射固定任务申请，不交付模型正文 |
| 普通聊天 | `{"kind":"chat","text":"…"}` | `text` 必须含非空白内容，且 Unicode 码点数为 1～4000；原样交付正文 |

Schema 用互斥分支约束 `kind` 与 `text`，不能只给 `kind` 枚举而允许任意字符串。Main 内本地适配器仍独立严格解析与校验；聊天长度沿用 `Array.from(text).length`，空白检查不改变有效正文的空格、换行或其他字节。最多接纳 64 KiB 的原始 JSON 正文，完整解析，拒绝截断或包在 Markdown 围栏中的内容。

提示保持统一语义：实际查阅、修改、执行和对具体提议的明确同意选任务；“目录下有什么”等直接询问磁盘事实也选任务，由 Main 绑定目录并展示范围，不因尚未读取而改成聊天重复询问。仅讨论、建议、引用示例及明确拒绝操作选聊天。“不是根目录，请查看子目录”属于任务。角色仅影响聊天措辞；历史只帮助理解指代，不证明文件当前内容或继承许可。普通讨论尚未读取时说明未知并征求同意，不编造目录清单、文件正文或已执行状态。

复用现有本地请求策略、HTTP 传输和响应检查，在本地 Provider 内维护私有判别 Schema 与解码；不借用角色表现协议名称，不扩充跨应用公共 DTO，不恢复旧 `capabilityPlan` 联合 JSON 解析。

## 4. 映射、授权与隐私边界

本地适配器只在完整响应合法、请求未取消且连接 generation 仍有效后返回既有 `ModelResponse`：

- `task`：宿主生成一次新的非空请求 ID，返回固定工具名 `request_task_authorization` 和严格空参数 `{}`。ID 只用于该响应关联，不来自模型，不作为访问许可，不持久化复用。
- `chat`：返回 `{type:'text',text}`。只有解码后的正文进入聊天显示及原有历史；判别 JSON、`kind` 和生成的请求 ID 不作为聊天正文或新增公开字段保存。

既有 ChatAdapter 接纳固定申请后，由 Main 绑定当前原文、目录、模型、命令集合和 generation，展示原范围卡。确认前零 Core 执行；确认后使用同一任务服务、工具、权限和清理链。模型不能填写或改变路径、命令、授权范围、批准状态及执行结果。

任务分支不等待、不启动独立表现；聊天分支沿用原独立表现请求及其 12 秒可选失败边界。表现仍无文件工具且不接收新增任务内容。原始失败响应、API Key、凭据和私有元数据不进入 Renderer、错误或诊断日志；复用稳定错误分类及现有最小诊断字段。

## 5. 失败与生命周期

非法 JSON、未知分支、缺字段、额外字段、任务非空正文、聊天全空白或超长、原生 `tool_calls`、推理泄漏及 HTTP 错误均失败关闭。不得丢弃非法任务正文后接纳，不从坏 JSON 中抽取正文，不将其当普通聊天，也不退回原生 `auto` 或追加一次模型请求碰运气。

主请求失败时沿用现有稳定错误反馈，不显示原始响应，不发起表现、范围卡或成功事件。任务分支即使语法正确也只表示申请，不能当作已执行。普通聊天中无证据的文件描述仍属于语义失败，应在实际验收中记录；Schema 无法单独证明正文事实正确。

取消、reset、关闭、角色／Provider／配置或 generation 变化后，迟到响应不得生成有效申请或提交正文。继续复用现有信号、连接检查、Main 快照和失效处理，不引入可跨轮复用的判别结果或授权缓存。

## 6. 迁移、删除与旧规范覆盖

生产落点为 `apps/desktop/src/main/providers/local-model-provider.ts`；通过 `conversation-chat-adapter.ts` 导出原有宿主提示常量进行准确识别，提示正文对 DeepSeek 保持字节一致。没有新增通用协议框架、公共 DTO 或第二条执行路径。对应计划记录精确文件与 RED/GREEN 步骤，运行结果由验收记录维护。

新路径通过定向测试与必要真实验收后，删除仅服务旧 Qwen 主入口的原生 `auto` 提示候选、提示叠加／重排逻辑和失效断言；同一 Qwen 正式主入口只保留一种正式协议。保留非主会话工具传输、DeepSeek 原生入口及其测试，不删除用户数据或历史失败证据。临时原型不得成为生产旁路，不新增自动协议回退。

本稿获批后，仅对内置 Qwen 正式 `conversation` 局部覆盖 9 月 8 日规格中的三点：

1. “主请求不携带 `response_format`”改为本地严格 JSON 联合 Schema。
2. 模型线上原生 `request_task_authorization` 加 `toolChoice:auto` 改为无工具判别；Main 仍接收同一种经本地校验映射的空参数申请。
3. “删除正式聊天联合 JSON”只允许本稿的两个字段例外；不恢复正文与角色表现、文件能力参数混合的旧协议。

单一发送、原文与历史、独立表现、Main 授权、同一 Core、取消、普通聊天事实约束及其他 Provider 的原规范继续有效。[9 月 10 日原生入口修复计划](../plans/2026-09-10-qwen-task-entry-stability.md)中的 native 候选不能与本稿并列为两条正式 Qwen 路径。本稿不追认已有未验收改动，也不改写其失败结果。

## 7. 测试与人工验收

实施按 RED → GREEN → 最小整理执行，至少覆盖：

- **形状与映射**：两个合法分支；非法 JSON／额外字段／任务非空／聊天空白及码点边界／原生工具调用均拒绝；任务 ID 非空且独立，工具名与参数固定，原始响应不泄露。
- **请求与隔离**：正式本地入口只发一次无工具主请求，严格 Schema 到达实际 HTTP；单／多 system、原文、人设和历史保持；Schema 计入预算；无工具、其他工具、独立表现及 DeepSeek 请求不变。禁止通过修改云请求或放宽通用协议换取本地成功。
- **生命周期与完整链**：合法任务只展示原范围卡，拒绝时零 Core 执行，批准后才执行；取消／reset／配置失效阻断迟到结果。聊天仍最多追加一次原独立表现，表现失败不吞正文，主请求失败不触发表现。

真实 Qwen 验收先冻结最终源码、Schema、人设和输入，再分别检查实际人设与独立强合成人设：问候、根目录／子目录／空文件连续跟进、建议及明确拒绝。记录每轮分支、范围确认、实际工具路径和结果；目标空文件必须有本轮真实 `read` 成功与空内容，不能仅看总结。任何漏申请、负例申请、未确认执行、虚构文件事实或输出形状失败都如实记为失败，不用不同版本的成功片段拼成通过。

运行定向测试及桌面类型检查后，按仓库规则执行受影响桌面、安全、集成及必要 Electron 门禁。此前完整桌面门禁失败和未完成项目独立保留；定向测试或模型原型不能代替它们。

用户人工确认真实 Windows 单一发送、范围卡的确认／拒绝、聊天与独立表现交付、任务完成后再次跟进和取消体验。无观察证据的项写“待用户人工确认”；安装卸载、打包和生产部署不在本次范围。
