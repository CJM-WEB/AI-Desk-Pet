# 网站登录与投稿恢复规格

## 目标与证据

2026-09-09 用户授权修复管理员验证码和共享资源上传，沿用零额外费用、仅上海环境、禁止桌宠改动与 Git 合并的约束。根域管理员页发送验证码失败，认证允许域名仅含默认托管域名；默认托管管理员工作台仍可访问。匿名 prepare 实测返回 `503 / SHARED_PACKAGE_SUBMISSIONS_PAUSED`，远端开关为 false。

## 最小方案

1. 管理员页面增加一个构建配置 `NEXT_PUBLIC_ADMIN_ORIGIN`。部署值为 `https://ai-pet-scanner-dev-d0cpbc8094826-1391054083.tcloudbaseapp.com`。初始化认证前，非该来源的管理员页用 `location.replace` 跳到配置来源的 `/admin/`；不携带查询参数、fragment、邮箱或令牌。同来源不跳转；未配置时保留本地及现有测试行为。配置只能是无账号、无查询、无 fragment、根路径的 HTTPS origin；错误配置显示既有配置错误，不初始化认证。无需改变首页、样式和业务 API。
2. 不购买自定义认证域名权限，不新造邮件服务，不修改 OTP、唯一管理员校验或 `shouldCreateUser: false`。
3. 先解除 API 函数的响应日志投递，确认后将 `SHARED_PACKAGE_SUBMISSIONS_ENABLED` 改为 true，保留所有其他环境变量。上传沿用已有私有存储、一次性地址、尺寸校验和人工审核，不引入新接口。

## 安全、失败与验收

- 云端只操作 `ai-pet-scanner-dev-d0cpbc8094826`（上海），不启用按量付费、不变更套餐。
- 不输出密钥、验证码、状态令牌、完整签名 URL 或用户私人内容。保留数据库审计。
- 正式上传前日志门禁必须满足；失败则保持或恢复投稿暂停开关。
- TDD 验证跳转发生在认证初始化前、规范来源不循环、无配置兼容、非法配置失败关闭。执行网站质量门禁；远端浏览器检查根域入口、默认域验证码发送以及真实匿名上传全过程。
- 使用现有 68 字节 PNG 和 1376 字节合法 ZIP 作为唯一受控投稿，保持私有，验收后人工驳回并走现有隔离清理，不发布、不更改用户投稿。
- 仅部署已审阅的同分支网站产物，比较首页视觉相关产物，不能重新上线旧版。验收记录区分平台已接受发送与收件箱实际收到。

本规格仅替代旧验收记录中“管理员需手工选择默认域入口”和“共享包投稿保持关闭”的运行安排，其余审核与权限规格不变。
