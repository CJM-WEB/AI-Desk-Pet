# AI Pet 自定义状态、持续心情与自主表现设计

日期：2026-09-05；补充：2026-09-06。状态：**用户已确认文件能力验收并授权本阶段实施，开发中**。

本文将已确认的产品方向与推荐的工程取舍分开记录。源码调查基线为本仓库 `d7abbef`；没有把旧测试报告当成本轮效果证明。本规格依赖[编程助手规格第 9 节](2026-09-05-ai-pet-coding-assistant-design.md)定义的真实任务事实。

## 1. 决策摘要

### 1.1 用户已确认

- 用户可以导入素材、自定义人设、创建任意状态，一个状态下有多个动作。
- 取消主状态／修饰状态区分，**同一时刻只激活一个状态**，在该状态下选择和轮换动作。
- 唯一官方保留的状态含义是 `idle`；其他状态和动作不依附官方标准语义。
- 心情独立保留。开心事件可以产生持续的开心感，随后随时间回落，不能只等下一次聊天才改变。
- 长时间未互动时，可以逐渐表现出无聊、困乏或其他符合人设的反应。
- 首轮自主范围为心情、状态和动画，**暂不主动发消息**。
- 复用角色工作台已有描述与人设字段；当前版本不必使用全部高级能力，但需要保留继续扩展的结构。
- 2026-09-06 补充：工作台锚点与区域保留现有入口和数据，本轮不扩展编辑、锚点交互或区域功能；已有素材定位与基础拖拽继续复用。
- 2026-09-06 补充：角色人设编入当前桌宠的系统提示词；状态、动作描述是模型理解与匹配的重要输入，不能只按名称或旧标准语义触发。
- 2026-09-06 补充：保留 `0=静止 / 1=一直运动 / 2=间断运动` 的持久设置、聊天控制和自主桌面位移；停止运动不停止心情和原地动画。
- 用户要求以基本正常、安全边界与可扩展性为交付重点，使用有意义的定向验证，不反复运行完整验收矩阵；本轮不打包、不 push，MCP 保持禁用，官网链严格隔离。

### 1.2 推荐的实现取舍

采用**角色契约与决策层重构，素材及底层播放复用**。仅隐藏几个下拉框不能解除运行时对固定语义的依赖；整套播放器重写也没有必要。

| 项目 | 随本文审阅的推荐选择 |
| --- | --- |
| 新角色契约 | 显式 V3，按稳定状态／动作 ID 运行；保留 V1/V2 输入解析与迁移 |
| 心情表达 | 有界自由描述与连续强度，不再提供官方情绪枚举；第一版只保留一个当前心情摘要 |
| 时间演进 | Main 本地计算衰减；模型低频理解情境和选择候选，不参与逐帧播放 |
| 自主模型调用 | 使用已配置且满足披露条件的 Provider；默认启用，可关闭；至少间隔 5 分钟，每滚动小时最多 4 次请求 |
| 重启与休眠 | 心情首轮不跨应用重启保存；休眠时间计入一次衰减与未互动时长，不补跑旧动画或请求 |
| idle | 使用唯一 `idleStateId` 指向兜底状态；名称、描述和素材可编辑，发布时必须能播放 |
| 有歧义旧包 | 保留原包并生成迁移草稿；用户完成迁移前不启用该包的新运行路径，临时使用已可用角色或内置 idle |
| 初始感知范围 | 对话、真实任务结果、桌宠点击／拖拽及时间；不新增屏幕采集、剪贴板或其他应用监控 |

上述工程默认值随本阶段实施采用；它们是实现选择，不是模型效果或旧数据已迁移的证明。实现过程中发现无法无损解释的旧规则，按第 9 节交给作者处理，不静默丢弃。

## 2. 目标、非目标与现状

目标是让桌宠根据人设、交流与时间自然改变表现，并使作者只需维护一套角色定义。接受同样事件的不同角色可以选择不同状态，目录没有相应状态时也能稳定运行。

本次不包含主动聊天、长期人格记忆、任意脚本、角色取得文件权限、新增本地模型、复杂生理仿真、多人关系模型或全新动画渲染框架。

当前可复用与必须调整的证据：

| 来源 | 当前事实与影响 |
| --- | --- |
| [V2 Schema](../../../packages/character-runtime/src/character-v2-schema.ts) | 已有人设、描述、标签、动作与皮肤；同时固定主／修饰状态、八种标准语义及组合约束 |
| [公共契约](../../../packages/shared-types/src/contracts.ts) | 情绪仍是固定 `happy/sad/angry/surprised/calm`；只删除工作台语义栏会留下另一套官方分类 |
| [状态推断](../../../packages/character-runtime/src/behavior-state-inference.ts) | 可信事件先转标准语义，再选主状态与修饰状态 |
| [行为引擎](../../../packages/character-runtime/src/character-behavior-engine.ts) | 已有动作生命周期、冷却与反馈；推进时间尚不等于持续心情演进 |

| [旧运行投影](../../../packages/character-runtime/src/legacy-runtime-projection.ts) | 按语义合并或改写状态；播放器再跨状态找动作，无法忠实表达原始状态 ID |

## 3. 三种不同的数据

| 数据 | 含义 | 唯一事实来源 |
| --- | --- | --- |
| 情境事实 | 正在对话、文件操作实际成功或失败、被拖拽、多久未互动 | 所选执行后端的任务结果，以及 Main 的交互观察与事实投影 |
| 心情 | 此角色对此情境的持续感受摘要及强度 | 模型提出更新，Main 校验并按时间维护 |
| 表现 | 当前唯一状态、该状态中的动作、播放进度 | Main 仲裁与调度；Renderer 返回实际播放反馈 |

例如，任务仍在运行时角色可以心情愉快并播放作者定义的“认真工作”；动画结束不会结束心情或任务。心情归于平稳不要求存在名为“平静”的用户状态，最终可以回到 idle。

模型给出的分数表示偏好，不是真实校准的概率。最高分只是决策输入；冷却、连续播放、状态稳定性和当前可播放素材同样决定最终结果。

## 4. V3 角色契约与工作台

### 4.1 保留的作者数据

沿用 `identity → states[].actionIds → actions → skins[].presentations`。保留人物描述、背景、性格、语言风格、称呼、喜恶、行为倾向、互动边界、示例台词，以及状态／动作的名称、描述和标签。

保留素材、帧、精灵图、皮肤、FPS、倍速、镜像、锚点、区域、视觉几何、偏好、冷却、重复抑制、动作时长、循环、中断、朝向及失败回退。描述负责解释意图，播放参数负责可靠执行；不新增第二套“AI 专用人设编辑器”。

锚点与区域的现有编辑入口、字段及兼容解析保持可用，本轮不新增高级交互、逐帧能力或附着算法。V3 继续复用现有表现几何和资源契约作为扩展接口；新建表现沿用现有默认定位，不要求作者为了聊天与情绪动画先配置锚点。

### 4.2 单状态契约

- 顶层 `idleStateId` 引用唯一兜底状态；新角色默认 ID 为 `idle`。旧角色可保留原有稳定 ID，由引用赋予兜底职责，不按显示名称猜测。
- 启动时进入 idle；其名称、描述及素材可改，发布包必须保证每个可用皮肤能解析至少一个 idle 表现。不能删除唯一兜底而仍发布成功。idle 的兜底进入不受模型可推断开关或事件条件阻挡；没有合格动画时可静止呈现其有效帧，不借此绕过其他动作的硬冷却。
- 所有其他状态只有作者定义的 ID、名称、描述、标签、建议时长、表现强度、可推断开关、动作归属与受支持条件。
- 删除 `kind`、状态／动作 `semantic`、主／修饰组合和共存关系。某动作可由多个状态引用，但只能从当前唯一状态的动作集合中选择。
- `agentInferable=false` 表示模型不得自主选择该状态；用户在工作台预览或明确指定该状态仍可使用。
- 第一版条件只保留可直接核验的 Main 事件条件，具体执行语义见下文。删除标准语义条件和多状态同时成立条件；将来的时间、数值与转移条件通过显式 Schema 版本扩展，不塞入任意脚本或不解释的 JSON。

状态与动作数量沿用现有已发布角色资源预算；新版本不通过放宽数量掩盖目录选择问题。

第一版事件条件仅使用 `user-interaction`、`conversation-start`、`response-finished`、`task-start`、`task-waiting`、`task-paused`、`task-finished`、`drag-start`、`drag-end`、`move-start`、`move-stop`；任务终态附带共享事实中的实际结果。这些是机器事实，不是作者状态分类。

进入条件只过滤候选资格，不独立创建候选或调用模型；无条件表示不额外限制。边沿事件由 Main 分配 ID，有效期 2 分钟，一次进入消费一次，不能反复播放旧事件。退出条件只消费进入后新发生的匹配事件，使当前状态重新仲裁；没有候选时回到 idle。`agentInferable=false` 仍禁止模型自主候选；用户明确指定可越过可选进入条件，但不能越过资源校验。V2 条件无法对应这些含义时进入迁移问题。

### 4.3 工作台简化

状态编辑删除“状态类别、语义类型、标准语义、共存状态”；新建状态直接填写名称与可选描述。动作编辑删除“动作语义、允许／禁止主状态、要求／禁止修饰状态”，以所属状态的动作列表表达归属。

保留普通创作必需字段；播放冷却、中断、回退、方向和事件条件放在高级设置，不要求每个作者填写。既有草稿自动保存、撤销恢复、导入预览、编译、本地发布和资源预算继续复用。

### 4.4 按 ID 播放

Main 编译只读播放视图，保留原始 `stateId`、`actionId` 与皮肤关系。下发已校验的状态、动作和 `playbackToken`，Renderer 精确解析后复用现有 Pixi／帧播放器与缓存。

不再按语义重命名状态、不复制默认状态伪装成 idle，也不靠全局搜索同名动作补偿投影。表现资源复用与逻辑动作切换分开：资源复用不改变状态和动作身份；逻辑回退必须明确合法的目标状态／动作对，原子更新唯一活动状态，最终回到 idle。实际使用回退时反馈真实逻辑对象与素材来源，不能报告未播放的目标成功。

## 5. Main 心情状态与时间

### 5.1 最小运行期模型

Main 保存 `moodRevision`、有界 `summary`、目标强度、起始时间、渐入时长、衰减半衰期，并计算当前 `strength`；另存当前状态、进入时间、最近真实互动时间和表现计划有效期。

`summary` 最长 240 个字符；`strength` 在 0 到 1 之间。强度接近 0 时清除本次突出心情，回到“按既有人设、没有近期突出情绪”的基线。基线不是强制官方“calm”状态。第一版不模拟多个互相叠加的情绪向量，也不新增情绪标签枚举。

角色人设影响模型如何解释事件、更新摘要和选择状态；名称中有没有“开心”“困”不会触发固定代码映射。

### 5.2 连续衰减

对话引起的即时情感默认直接到达目标强度；自主产生的新感受默认在 60 秒内渐入，模型可建议 0 到 5 分钟的有界渐入时长。渐入期间按经过时间从 0 线性接近目标强度，随后按 `strength(t) = 目标强度 × 2^(-渐入结束后的时间 / 半衰期)` 衰减。这样无聊或困乏可以在本地逐渐出现，而不是等下一次模型请求才跳变。

推荐默认半衰期 5 分钟，模型可在 30 秒到 30 分钟内建议，Main 严格限制；渐入结束后强度小于 0.02 时清除突出心情。它是有限情感过程，不是无限累计的生理数值；后续未互动情境可产生新的感受。

计算使用可注入时钟，不依赖动画结束或下一次对话。正常运行使用单调时间；系统休眠恢复时，将非负且有界的休眠间隔一次计入，异常墙钟跳变不补跑回调。应用重启清除心情与候选计划，角色定义与用户设置照常保留。

最近互动只由真实用户聊天、点击、拖拽或明确操作更新。动画完成、模型自主重评、工具进度及桌宠自己产生的事件不能冒充用户互动。

### 5.3 更新而非无限刷新

对话中的新事件可以提出新的心情更新，Main 为事件分配标识并去重。重复到达的同一事件不能再次增加强度。自主重评可根据新经过的时间和情境变化提出新感受，但不能只因重看同一段开心对话不断重置旧开心事件。

每个推断绑定角色、Provider、会话 generation、情境修订和心情修订。新互动、换角色、重置或配置变化后，旧推断不得覆盖新状态；失效结果直接丢弃。

`moodRevision` 只在语义心情被更新或清除时递增，纯时间求值不递增，避免时钟每次推进都令慢请求失效。表现计划绑定同一修订；新心情到来立即失效旧计划，不能把开心动作区间用于新伤心摘要。新更新没有合法配套计划时，结束可中断表现并回到 idle；不继续旧心情的循环。

## 6. 模型建议与本地表现计划

### 6.1 结构化决策输入

当前角色的名称、描述、背景、性格、语言风格、称呼方式、喜恶、行为倾向、互动边界及示例台词共同生成明确的“角色人设”系统消息段，随角色发布和切换更新。角色段用于说话方式、情感理解和表现选择，宿主输出协议、工具授权及安全约束独立保留；作者文字不能改写 Main 权限或伪造真实任务结果。动作描述提供适用情境与动作含义，不执行其中的文字指令。

人设与候选目录分别分配上下文预算，避免旧版 2,400 字节目录裁剪同时吞掉人设。所有字段都纳入投影；大文本按当前模型可接纳上下文有界裁剪，优先保留当前用户输入、宿主约束、人设要点和相关候选。内置 Qwen 沿用真实本地输入上限，不把默认 64 KiB 宿主上限强加给小上下文模型；不通过扩大文件任务 Core 上下文解决陪伴聊天问题。

输入来自当前普通对话的必要片段、已有角色人设、Main 心情快照、最近互动间隔、当前状态／动作、有限近期播放记录和最小情境事实。任务正文与命令输出不进入自主心情上下文。

这对应用户图中的“临时结构化提示词”：它每次由真实状态和作者数据生成，不是让模型凭空填写宿主已经知道的事实。文件／命令结果使用所选执行后端的可信事件；Main 投影任务事实，并负责表现持续时长与播放次数。

人设投影按场景使用现有字段：聊天优先语言风格、称呼、互动边界和少量示例；心情与表现优先背景、性格、喜恶及行为倾向。不能把目前未投影的字段当成已经产生效果。

### 6.2 目录候选

名称和描述用于帮助模型理解，动作选择最终提交本次请求有效的状态／动作引用，不依赖模型编造 ID 或固定语义。

移除“默认顺序前若干项即整个可见目录”的选择方式。目录投影优先包含用户明确提到的精确目标、当前状态、idle 和近期候选；其余按本轮文本与既有描述检索，并保留轮换探索位置。继续复用轻量文本索引，不增加向量数据库。

投影仍有字节预算，并记录本次覆盖范围；未展示的候选不能被解释为整个角色都没有这种表达。首次实现最多投影 24 个状态、合计 32 个动作；数量上限针对本次动态候选，不是永久只允许目录前 24 项被选择。大量相近名称、中文自定义名称和描述中的同义表达进入真实模型验收。模型匹配失败时保持有效当前状态或 idle，不用固定相似度阈值猜出一个状态并当成事实。

角色决策输入使用独立的宿主预算，默认最多 64 KiB，系统提示与全部角色内容一同计入；按优先级缩减可选描述，不能截断后继续使用一个无效引用。该预算仅属于角色推断，不限制 OpenCode 编程会话。自主结构化输出最多 16 KiB、最多 8 个状态候选和合计 32 个动作候选；分数均为 0 到 1 的有限数，强度区间满足 `0 ≤ min ≤ max ≤ 1`。同一状态候选只出现一次，不同状态区间可重叠，由本地仲裁处理；动作引用必须属于对应状态。

### 6.3 决策输出

使用统一、严格校验的结构化信封，分别承载可见回复、心情更新、表现建议、独立运动建议和任务建议。表现建议至少包含：

- 心情更新：摘要、目标强度、建议渐入时长及半衰期；可省略，省略表示继续本地演进。
- 状态候选：本次有效状态引用、偏好分数及适用的心情强度区间。
- 动作候选：属于相应状态的动作引用、偏好分数；实际冷却、重复与资源资格由 Main 判断。
- 有效期：默认 20 分钟，Main 限制为最长 30 分钟，覆盖正常 15 分钟重评周期；建议不是永久命令，也不允许模型自行创建状态或资源。

同一次对话可以给出“强烈开心时手舞足蹈、开心变淡后微笑、最后 idle”的有限候选计划。Main 随强度变化使用计划，无需每秒再问模型。计划过期或没有适用候选时，短暂完成当前动作后回到 idle，并在预算允许时重评。

### 6.4 状态与动作选择

始终只有一个活动状态。状态在有效候选中选择；当前状态仍适用时保留小幅稳定优势，默认至少保持 2 秒，避免小分差每帧切换。用户明确指定、交互中断和资源失败可以越过该等待边界。

进入状态后在它的可播放动作中，按候选偏好、作者权重、冷却与近期重复情况选择。存在合格替代动作时避免连续选同一动作；接近的候选可加权选择，不能永远只播最高分的一个。随机源可注入以便测试。

状态建议时长影响下一次本地选态时点；动作时长和循环策略决定播放时点。建议时长届满会重新判断，不自动清除心情，也不要求立即调用模型。持续循环动作同样受状态有效期、强度变化和中断策略约束。

动作全部处于冷却时计算下一可选时间；不绕过硬冷却反复抽签。可暂时保留合法静止表现；资源不可用时选择有效回退或 idle，并更新唯一活动状态与实际播放记录。

## 7. 自主变化与调用预算

本地衰减、状态到期和动作轮换不消耗模型调用。无新交流时，推荐在距真实互动 5 分钟后允许首次自主重评，此后至少间隔 15 分钟检查长期未互动情境；预算不足时只保留本地演进。

自主重评使用独立的无工具请求，`tools: []`，信封只接受心情与表现字段，不接受回复、运动、任务或工具建议；不向聊天插入消息、不创建文件任务、不发通知。模型看到互动间隔和人设，可以提出“有点无聊”或“想休息”等自由心情与已有状态候选；这些词不是系统内置状态名称。

只有满足现有 Provider 配置及披露条件时才可调用。推荐设置中提供一个“自主心情”开关及调用频率说明，默认启用；关闭后停止自主模型请求，聊天引起的心情仍本地衰减、动作仍可轮换。

所有自主请求，包括重评与格式修复，按应用本次运行统一计入每滚动小时最多 4 次的上限；角色和 Provider 切换不清零，发起即计数，失败、取消不返还次数。任意两次相隔至少 5 分钟，每次请求最长 60 秒。已有用户请求时自主重评让路，应用最多一个自主请求在途。格式失败不立即违反间隔补打一轮，而在允许的下一时点再尝试。

没有模型、拒绝披露、离线、错误、超时或预算耗尽时，只执行已有有效计划、本地衰减和 idle 回退。不能把这种降级标成“已理解角色并自主产生新心情”。

第一版不跨重启保存心情，也不保存全部对话来支持自主重评。系统唤醒仅检查当前情境一次，不补发休眠期间欠下的模型请求。

## 8. 感知、运动、任务与结构化失败

### 8.1 有来源的感知

文件／命令的执行结果按[编程助手规格](2026-09-05-ai-pet-coding-assistant-design.md)投影；普通聊天完成不等于文件成功。点击、拖拽、窗口运动和播放反馈继续从现有可信 Main 链收集，不新增读取其他应用内容的能力。

拖拽的命中、位置、捕获和松手流程先完成自身确定性行为，再更新情境供表现解释。模型失败不能阻止用户拖动桌宠；“被拖拽”也不是用户必须创建的官方状态。

### 8.2 真实运动独立

只有现有 `MovementControlPlan` 和 Main 的运动策略能改变窗口位置。选中作者命名为“奔跑”“搬东西”的动作不自动授权或启动运动；真实移动也不要求目录存在官方 `move` 状态。

现有移动档位继续只控制真实位移。档位 0 不再关闭原地心情、状态或动画；停止运动、关闭自主心情和暂停动画是不同操作，不复用一个开关隐式全部禁用。

### 8.3 失败隔离

可见文本与各结构化建议分段校验，依赖同一引用的字段作为一个整体校验。无效表现建议不得执行，也不能吞掉合法聊天或重放已经发生的文件操作。普通对话至多进行一次无工具格式修复，已有效的字段不得重复应用；自主请求遵守第 7 节的独立预算。

失败回退不能越出当前角色包或取得系统能力。播放令牌用于完成、失败和中断反馈；迟到令牌、旧 generation、角色切换、关闭窗口及应用退出后的结果均失效。

## 9. V1/V2 迁移与失败保护

### 9.1 版本策略

增加显式 V3，不能原地把 V2 的字段改成另一种意思。正式编辑、保存、发布和运行仅有一条 V3 路径；V1/V2 解析器只用于输入转换及保留原始数据，不维持第二套长期正式调度器。

复用现有导入、发布、原子提交、索引更新、恢复和草稿保存事务。必须修正[迁移入口](../../../apps/desktop/src/main/characters/character-migrations.ts)及[角色存储](../../../apps/desktop/src/main/characters/character-store.ts)中“当前 V2、备份 V1”等版本特判，避免 V3 将仍需保留的源备份当成普通旧备份清除。

### 9.2 确定转换与人工解释

素材、全部皮肤、帧、几何、名称、描述、标签、已有 ID、播放参数及人设原样保留。存在唯一明确 idle 来源时设为 `idleStateId`；缺失或多义时列出问题，由用户指定，不能仅按名字或默认状态自动猜测。

单纯动作归属和可精确计算的单状态允许／禁止规则，可展开为新的 `state.actionIds`。原修饰状态可以保留为独立状态草稿，但旧的叠加含义不能宣称等价保留。

以下内容必须逐项产生迁移问题：要求／禁止修饰状态、共存关系、多状态条件、官方语义条件，以及无法确定动作资格的组合。迁移界面显示原规则、受影响状态／动作、推荐替换与效果预览。用户明确处理后才发布，不静默去掉约束，也不简单把 `requiredModifierStateIds` 改名成 `requiredStateIds`。

皮肤 `semanticFallbacks` 不能直接丢弃。优先将旧解析得到的表现资源展开到原逻辑动作的该皮肤表现中，保留素材引用及原状态归属，不把资源复用变成跨状态选动作。若必须切换逻辑动作，需指定合法目标状态／动作对并显示迁移问题；不能自动向当前状态添加其他动作来掩盖变化。无法展开、循环或超预算时同样阻止发布。所有皮肤都参与核验，不只转换默认皮肤。

### 9.3 原包保留与暂存运行

迁移先产生独立草稿和报告，原包字节与素材保留。确定转换的包可在迁移预览确认后提交；存在问题的包不能替换正式数据或活动指针。

推荐当当前旧角色尚未迁移时，在新版本中临时显示此前已可用的 V3 角色，否则显示内置 idle，并清楚标出“原角色待迁移”。原角色仍可在工作台检查、修正和导出；不以沿用旧语义运行来掩盖迁移未完成。

拒绝、失败、磁盘中断和重启后都能找到原包与迁移草稿。备份清理不包含在这次自动迁移内；不得因清理旧代码删除用户素材。此暂存体验需要随本文获得批准。

## 10. 模块边界与扩展方式

| 模块 | 本轮职责 |
| --- | --- |
| `packages/character-runtime` | V3 契约、输入迁移、单状态仲裁、可注入时钟的心情与动作调度、按 ID 的播放视图 |

## 12. 分段实现与验收

推荐在编程任务事实契约稳定后，先交付 V3 创作、迁移和按 ID 播放，再接持续心情与低频自主决策。每段有自己的 RED/GREEN 用例与运行门禁，不用同一批大改同时验证全部行为。精确文件和执行顺序在本文批准后的实施计划中展开。

### 12.1 自动化场景

1. 导入素材，创建无官方语义的状态和三个动作，保存、发布、启用、重启、导出回导；ID、描述、皮肤与播放参数一致。
2. 任何时刻只有一个活动状态；多个可用动作轮换，冷却／重复规则生效，全部冷却时无忙循环。
3. 一次开心事件后，动画结束心情仍存在；虚拟时间推进使强度回落，状态／动作按有效计划变化，无下一次聊天也成立。
4. idle 可自定义表现，其他状态不用标准标签；`agentInferable=false` 不被自主选择，明确指定仍可使用。
5. 长时间未互动触发受预算约束的无工具请求，不生成聊天消息、文件任务或 PowerShell 请求。
6. 相同旧事件、过期响应、角色切换、Provider 切换、reset、休眠恢复不会重复增益、补跑回调或复活旧播放。
7. “奔跑”动画不改变窗口；没有官方 move 状态仍可按获准策略移动；移动档位 0 仍能原地改变表现。
8. 普通聊天结束、任务部分成功、任务取消、模型总结失败、动画失败各自保留正确事实。
9. 含修饰约束、共存条件、多个皮肤回退的 V2 包生成可审迁移问题；拒绝、失败、磁盘中断不损坏原包、素材、索引和活动指针。
10. 无模型、坏格式、目录超出投影预算、资源失败和清理路径均能降级，普通聊天和基础桌宠继续可用。

### 12.2 真实效果与人工观察

固定角色素材、人设、Provider 与输入，分别观察“分享好消息”“普通日常”“任务失败”“长时间不互动”。至少使用两套人设和作者自定义名称，检查反应是否符合描述、强弱是否有变化、是否反复重复一个动作。

脚本模型和虚拟时钟证明结构与时序，不能代替真实模型的情境理解。Windows 拖拽、窗口运动、实际皮肤播放连续性及迁移体验由人工观察记录；未观察时标记“待用户人工确认”。

最低自动化门禁为定向 package 测试及类型检查，随后按影响范围运行 `pnpm.cmd verify:desktop`、`pnpm.cmd verify:behavior`、`pnpm.cmd verify:characters`。可按依赖拆段执行并记录实际命令，不重复运行已通过的相同检查来充数。

2026-09-06 验证范围补充：遵照用户减少验收投入的要求，上述聚合命令按重叠依赖去重拆段；优先覆盖角色保存与播放、时间衰减、三态运动不互相干扰、无工具自主请求、失效结果与旧包保护。已有原生拖拽问题不作为本轮反复诊断的入口，未观察到的效果留给用户实际体验反馈。新的失败只有影响本轮功能或已确认边界时才扩展检查。

完成条件是创作与运行链贯通、时间演进可复现、角色表现不会扩大文件任务权限、迁移不丢数据、旧正式路径清理，以及自动化与人工证据分别记录。本稿只描述待实现的验收标准。
