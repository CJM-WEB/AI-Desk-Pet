# 暂停匿名投稿 CAPTCHA 设计

## 目标

从网站的匿名资源包投稿与反馈／建议投稿链路中完整移除腾讯云 CAPTCHA。管理员邮箱 OTP 登录保持不变，REST 接口路径、投稿数据结构中的业务字段、限流、内容审核、管理员人工审核和状态查询保持不变。

## 删除边界

- 前端不再加载腾讯 CAPTCHA 脚本，不再创建验证码客户端，也不再向投稿仓库传递 `ticket` 与 `randstr`。
- 资源包投稿与反馈投稿的仓库接口删除 CAPTCHA 参数，请求正文不再包含 `captcha` 字段。
- 后端两个匿名投稿入口不再校验 `captcha` 字段。
- 投稿服务不再依赖或调用 `CaptchaVerifier`。
- CloudBase API 运行时不再创建腾讯 CAPTCHA 客户端，运行配置不再要求 `CAPTCHA_APP_ID` 与 `CAPTCHA_SECRET_KEY`。
- 删除仅由上述链路使用的前端 CAPTCHA 模块、后端腾讯 CAPTCHA 适配器及其专用测试。
- 更新部署文档和隐私说明，避免继续声明当前会处理 CAPTCHA 数据。

数据库中既有的 `captcha_replays` 表和迁移历史不回滚、不删除。迁移记录属于已执行的生产历史，强行回滚会增加数据风险；该表停用后不再产生新记录。

## 保留的安全边界

- 匿名投稿继续按来源 IP 使用现有 `submission_prepare` 限流。
- 资源包继续执行文件类型、大小、上传完整性、内容审核、技术扫描和管理员审批。
- 反馈与建议继续执行字段校验、内容审核和管理员审批。
- 管理员接口继续要求 CloudBase Bearer 会话、管理员邮箱白名单和管理员角色。
- 管理员邮箱 OTP 属于独立认证链路，不做任何改动。

## 数据流

资源包投稿：前端校验文件与表单 → `POST /api/v1/submissions/prepare` → IP 限流 → 创建待审核记录与签名上传地址 → 上传 → finalize → 管理员审核。

反馈投稿：前端校验文本 → `POST /api/v1/feedback` → IP 限流 → 创建待审核记录 → 管理员审核。

两个请求均不再生成、携带或验证 CAPTCHA 票据。

## 错误处理

- 删除 `CAPTCHA_CONFIG_REQUIRED`、`CAPTCHA_LOAD_FAILED`、`CAPTCHA_CANCELLED`、`CAPTCHA_INVALID`、`CAPTCHA_REPLAYED` 和 `CAPTCHA_UNAVAILABLE` 在匿名投稿链路中的触发路径。
- 其他表单校验、限流、上传、数据库、审核和网络错误保持原有错误码及界面提示。

## 测试与验收

1. 先修改测试，使无 `captcha` 的资源包 prepare 和反馈请求能够进入对应服务；确认测试在生产代码修改前失败。
2. 前端测试证明点击提交不会创建或调用 CAPTCHA，并且请求正文没有 `captcha`。
3. 后端测试证明无 CAPTCHA 字段仍执行 IP 限流和投稿服务。
4. 管理员 OTP、公开列表、点赞、下载和管理员审核测试保持通过。
5. TypeScript、前后端测试和生产构建通过。
6. 部署后实际提交一个最小合法反馈，确认无需验证码即可进入待审核状态；不自动批准或公开测试内容。

## 非目标

- 不移除或削弱 IP 限流、内容审核、资源包扫描和管理员人工审核。
- 不修改数据库历史迁移。
- 不修改管理员邮箱 OTP。
- 不顺带处理扫描服务、定时清理、HTTPS 或安全响应头等其他部署问题。
