# 网站共享资源最小开放规格

> 同日后续视觉修订：用户明确移除公开风险提示，按[显示精简规格](2026-09-11-shared-package-display-design.md)执行；本文件的三处提示展示要求被替代，其余上传、审核、下载和数据边界不变。早前验收中的提示观察仍是当时的真实结果。

日期：2026-09-11（北京时间）。状态：用户已明确确认本节范围；实际云端配置、上传与下载结果见[本轮验收记录](../../operations/2026-09-11-shared-resources-opening-acceptance.md)，规格确认本身不作为通过证据。

## 1. 用户确认与替代范围

用户明确要求：跳过扫描器，继续现有人工直接审核；沿用已有 CloudBase 环境，用户表示已经购买个人版；不新建生产环境，核心目标仅为用户上传共享资源并供其他人下载。

本规格在本次共享资源开放范围内作以下覆盖：

- 替代[本轮分析](../../research/2026-09-11-shared-resources-opening-analysis.md)中“先修复 Scanner 的 V1/V2/V3 兼容及容量差异”和“另建生产环境”的建议。分析中的历史观察保留，不作为本轮未决要求。
- 替代[零费用人工审核规格](2026-09-01-website-stage-2c-zero-cost-manual-review-design.md)与[内容审核手册](../../operations/content-moderation.md)中本次发布必须先运行本地 Docker Scanner 的步骤。本次由管理员直接人工查看并裁决，不运行扫描器，不生成或宣称技术扫描通过。
- 对[部署手册](../../operations/cloudbase-deployment.md)中的开发与生产隔离要求作本次明确例外：继续使用上海现有环境 `ai-pet-scanner-dev-d0cpbc8094826` 开放共享资源，不另建环境。该例外不推导为其他生产部署、付费资源或迁移授权。
- 替代此前本环境“零额外费用、共享包投稿保持暂停”的运行安排：核对用户已购个人版与准确安全来源后，在受控验收窗口开启投稿。不得代购、重复购买或另开按量付费。

保留[管理员强制发布规格](2026-08-31-admin-override-publication-design.md)中的独立风险确认、`force_publish`、`admin_override`、真实扫描历史、状态版本、幂等和审计边界。

## 2. 目标、非目标与现状证据

目标链路为：官网匿名投稿 → 私有文件直传 → 人工队列 → 管理员直接审核并强制发布 → 其他匿名用户下载。下载必须取得原始完整 ZIP，不能仅以按钮可点击或 HTTP 200 作为成功依据。

本次不修改桌宠、工作室、扫描器或业务 API，不新增账号体系、上传代理、数据库、云服务或第二条发布路径；不部署自动审核，不清理旧代码，不进行 Git 写操作，不更改官方安装包链。界面错误提示等体验补强不纳入本次最小开放。

已有事实来源：

- [2026-09-09 验收](../../operations/website-login-upload-repair-2026-09-09.md)证明根域存储 PUT 预检失败、默认托管域预检可通过，随后投稿开关恢复为 false；这是历史网络证据。
- 本轮分析记录过个人版升级前的只读控制台状态；用户已购个人版是后续输入，当前套餐和功能权限须重新读取确认。
- [网站仓库](../../../apps/website/components/website-experience/community/cloud-shared-pet-repository.ts)已实现 `prepare → 封面 PUT → ZIP PUT → finalize`。
- [投稿服务](../../../apps/cloudbase-api/src/services/submission-service.ts)已有开关、固定对象键、ZIP 100 MiB／封面 5 MiB、实际大小与 MIME 核对，以及完成后进入 `manual_review_pending` 的逻辑。
- [审核服务](../../../apps/cloudbase-api/src/services/admin-service.ts)与[公开服务](../../../apps/cloudbase-api/src/services/public-content-service.ts)已有强制发布、审计协作和 300 秒下载签名能力。本规格不把已有代码或旧验收当作本轮远端成功证据。

## 3. 最小配置与数据流

1. 只读核对现有环境 ID、上海地域、个人版生效状态、API 与 cleanup 正常，以及当前开关值；不修改其他环境。
2. 在当前环境的 Web 安全域名／HTTP 网关跨域配置中加入官网精确来源 `https://cjmwebsite.cn`；若平台输入要求域名，填写 `cjmwebsite.cn`。保留已有默认托管域与平台来源，不使用通配符，不改变网站或管理员入口。
3. 核对 API 函数 `ClsLogsetId`、`ClsTopicId` 仍为空，响应日志不保存状态令牌、上传／下载签名或私人内容。更新配置必须保留全部其他环境变量，不让 SDK 自动重新注入日志绑定。
4. 在受控验收窗口将 `SHARED_PACKAGE_SUBMISSIONS_ENABLED` 设为 true；从实际官网浏览器完成 prepare、两次 PUT 与 finalize，核对对象及人工队列。
5. 管理员人工核对标题、说明、封面、ZIP 内容与权利／隐私问题，并在现有两步确认中提交审核理由与 `ADMIN_OVERRIDE_ACCEPTED`。通过 `force_publish` 后应为 `published + admin_override`，公开保留“管理员人工放行，未通过系统安全验证”。
6. 另一匿名浏览器下载同一已审核 ZIP，核对大小与 SHA-256。本轮可复用现有不含个人资料的最小 V1 夹具，只证明该样本的上传、审核和完整下载；不据此声称 V2/V3 或全部新旧角色包兼容。

桌面回导仅是今后需要时的非阻断补充，不属于本次开放门禁，不为此追加桌面或 Scanner 任务。本轮不宣布角色包已在桌面启用或所有投稿均安全。

上传及状态查询继续匿名；管理员操作继续通过既有网关和应用层授权。私有 Bucket 保持 `public=false`，签名地址短期有效；保留现有限流、固定对象键、文件不覆盖、状态版本、幂等和审计。不得用“跳过扫描器”扩展成公开读写 Bucket、普通批准绕过或去掉风险提示。

## 4. 失败与回滚

- 套餐未生效、来源添加失败、API 日志门未满足或实际浏览器上传／发布／下载链失败时，不宣布开放成功；已开启的投稿开关恢复 false，保留其他配置与审计。
- 只把已观察到的失败阶段和稳定错误码写入验收，不记录令牌、签名 URL、管理员凭据、私有对象地址或真实用户正文。
- 不删除或改写用户投稿。受控测试内容由管理员按本次实际结果处理；如需下架，沿用现有隔离与到期清理，不永久删除、不批量清理。
- 若现有代码出现阻断，不在配置任务中顺带改实现；先记录最小复现和必要文件，再按已确认需求形成针对性 RED/GREEN 修复。不得通过放宽权限或伪造扫描事实绕过。
