# 反馈存储与文件粒子渲染优化设计

## 目标

仅解决以下两个遗留问题：

1. 浏览器本地存储不可用时，投稿不得显示为保存成功。
2. 文件粒子运行期间不得因剩余生命周期变化而每帧触发 React 列表重渲染。

## 反馈存储失败行为

- 官方示例和现有内存数据仍可读取，反馈章节不能因此失效。
- `Storage` 对象不存在时，投稿和点赞等写操作必须抛出 `FeedbackStorageError`。
- 投稿失败后编辑器保持打开并保留原草稿，显示“浏览器本地存储不可用，投稿无法保存。”
- 已存在的实际写入异常继续使用通用“投稿暂时无法保存，请稍后重试。”提示。
- 不引入云端接口、临时投稿成功状态或新的持久化依赖。

## 文件粒子渲染行为

- RAF 继续负责粒子生命周期计时、暂停恢复、离场阈值和过期移除。
- 每帧计算结果写入 `particlesRef`，不因单纯的 `remainingMs` 变化提交 React state。
- 仅当粒子阶段变化、粒子被移除或其他已有交互状态发生变化时提交 React state。
- 粒子生成、悬浮保持、随机反馈绑定与释放、减少动态效果和退出清理行为保持不变。

## 测试要求

- 仓储测试证明 `storage: null` 的写操作失败且内存文档未被伪装成持久化成功。
- 反馈章节测试证明存储不可用时保留草稿并显示专用提示。
- FileSwarm 组件测试证明普通 RAF 帧不会重新渲染图标，跨越离场阈值和过期移除时才更新。
- 最终运行网站类型检查、全部单元测试、生产构建和完整 E2E。

## 非目标

- 不处理平板章节导航、移动端图标避让、投稿编辑器尺寸或图片资源压缩。
- 不改变视觉设计、粒子数量、生命周期参数或反馈随机规则。
