# AI 桌宠多模型、Agent 与 MCP 系统设计

> 文档状态：已确认设计  
> 产品名称：`AI Pet`
> 目标平台：Windows 10/11  
> 基准日期：2026-07-27  
> 上层约束：[AI 桌宠产品全局设计与演进计划](./2026-07-20-ai-desktop-pet-master-design.md)

## 1. 目标

建立与角色表现解耦的智能核心，使普通用户只需选择提供商、选择模型并填写 API Key，即可使用聊天和 Agent；高级用户仍可配置自定义兼容服务。系统必须兼容国际与中国主流大模型，并通过统一工具注册中心安全接入本地工具和 MCP。

## 2. 已确认决策

1. 普通配置只显示“提供商、模型、API Key”。
2. 预置 OpenAI、Anthropic、Gemini、DeepSeek、Kimi、通义千问、智谱、豆包、腾讯混元、MiniMax 等提供商。
3. 保留折叠的高级自定义提供商，可设置 Base URL、模型 ID、协议类型和额外请求参数。
4. 模型目录采用“应用内置目录 + 可签名更新目录 + 提供商接口发现”三层来源。
5. 默认使用单一主模型；高级模式可分别指定对话、Agent、视觉和备用模型。
6. 未经用户授权，不得将上下文切换发送到另一家提供商。
7. MCP 同时支持内置服务和用户手动添加服务，首期支持本地 `stdio` 与远程 HTTP。
8. MCP 服务、工具、资源和提示词均可独立启停和授权。
9. Agent 主动性分为被动、辅助和自主三级，默认辅助模式。
10. 对话、长期记忆、操作记录和授权信息本地优先保存；文件、截图、剪贴板和记忆按需发送。

## 3. 系统边界

```text
聊天界面
  │
  ▼
Agent Orchestrator
  ├─ Model Router
  │   ├─ Provider Registry
  │   ├─ OpenAI Compatible Adapter
  │   ├─ Anthropic Adapter
  │   └─ Gemini Adapter
  ├─ Tool Registry
  │   ├─ 内置文件工具
  │   └─ MCP Client
  ├─ Permission Policy
  ├─ Context Disclosure
  └─ Audit / Cancellation
  │
  ├──────────► 桌宠状态桥：聆听、思考、执行、成功、失败
  ▼
Electron Main 中的受控执行器
```

Renderer 只提交用户意图并展示结果，不持有模型密钥、不启动 MCP 进程、不执行工具。模型只能提出结构化调用，所有调用必须在 Main 中完成 Schema 校验、权限判断、超时控制和审计。

## 4. Provider 体系

### 4.1 提供商目录

每个目录项至少包含：

- 稳定的 `providerId`、显示名称和协议类型。
- 官方 Base URL 模板，不在普通界面暴露。
- 可选的模型发现端点。
- 内置模型清单及能力标签。
- API Key 获取帮助链接。
- 请求限制、已知兼容差异和目录版本。

模型能力标签包括 `chat`、`tools`、`vision`、`streaming` 和 `longContext`。Agent 路由前必须检查能力，不能把工具任务发送给不支持工具调用的模型。

DeepSeek、Kimi、通义千问等采用其官方支持的协议适配方式。若接口兼容 OpenAI 协议，复用兼容适配器并通过目录配置差异；不得为每个品牌复制一套相同客户端。

### 4.2 配置模式

普通模式：

- 选择提供商。
- 从兼容模型列表选择模型。
- 填写 API Key。
- 测试连接后保存。

高级模式：

- 选择 `OpenAI Compatible`、`Anthropic` 或 `Gemini` 协议。
- 配置 Base URL、模型 ID 和白名单额外参数。
- 禁止用户通过额外参数覆盖 Authorization、安全 Header、超时和工具 Schema。

### 4.3 密钥和故障转移

- 每个提供商配置档案使用独立密钥槽，并通过 Electron `safeStorage` 加密。
- 日志、错误消息、导出配置和角色包不得包含密钥。
- 路由可配置主模型、对话模型、Agent 模型、视觉模型和备用模型。
- 自动故障转移只在用户预先允许的档案间发生，并在发送前显示目标提供商。
- 工具写操作已经完成但模型总结失败时，不得重复执行工具。

## 5. Agent 与权限

### 5.1 工具注册

工具名称不能继续使用仅包含内置文件工具的固定枚举。统一工具标识采用命名空间，例如：

- `builtin.files.read_text`
- `builtin.files.move`
- `mcp.<serverId>.<toolName>`

工具注册项包含输入 Schema、来源、风险等级、所需数据范围、超时和执行器。模型收到的工具列表只能包含当前会话已启用且已授权的工具。

### 5.2 风险等级

| 等级 | 示例 | 默认策略 |
|---|---|---|
| 只读 | 列目录、搜索、读取已授权文本 | 可配置自动执行 |
| 可恢复 | 新建、复制、移动、重命名、放入回收站 | 执行前确认 |
| 高风险 | 永久删除、覆盖、运行程序、访问敏感目录 | 逐次确认，部分默认禁用 |

风险由本地策略根据实际工具和参数计算。模型或 MCP 声明的风险只作为参考，不能降低本地判定。

### 5.3 主动性

- 被动模式：只响应明确指令。
- 辅助模式：可根据获准事件提出建议，但不自行修改文件。
- 自主模式：只执行用户预先建立规则中的低风险操作；可恢复和高风险操作仍需遵守确认策略。

后台不得持续全盘扫描。事件订阅必须限定在用户授权目录和明确开启的数据源中。

## 6. MCP

使用官方 MCP SDK，不自行实现协议。MCP 管理器负责：

- 本地 `stdio` 服务的命令、参数、工作目录和环境变量白名单。
- 远程 HTTP 服务的 URL、认证、连接测试和 TLS 要求。
- 初始化、能力发现、工具/资源/提示词清单和版本兼容。
- 每个服务及每项能力的启停。
- 调用超时、取消、并发上限、进程退出和崩溃隔离。
- 对输入输出执行大小限制、Schema 校验、脱敏和审计。

本地 MCP 进程以最小环境启动，不继承完整父进程环境。用户添加可执行命令时必须看到实际程序路径和参数并确认。MCP 返回的文本一律视为不可信内容，不能把其中的指令提升为系统权限。

## 7. 隐私与上下文披露

- 对话记录、记忆和审计默认只保存在本地。
- 长期记忆默认关闭，可查看、修改、删除并按会话禁用。
- 文件内容、截图、窗口标题、剪贴板和长期记忆分别授权。
- 每次模型请求生成数据披露清单，记录发送了哪些类别以及目标提供商，不记录完整敏感正文。
- 无痕会话关闭后不保留对话和记忆。
- MCP 只能访问工具调用明确传入且权限层允许的数据。

## 8. 与角色系统的关系

Agent 只发布语义事件，不引用具体序列帧：

```text
listening → thinking → awaiting_confirmation → acting → success/error
```

角色运行时自行把事件映射为当前角色动作。角色缺少对应动画时回退到该角色待机动画，不影响 Agent、Provider 或 MCP 执行结果。

## 9. 验收标准

1. 普通用户可通过“提供商 + 模型 + API Key”完成连接。
2. DeepSeek、Kimi及至少一个其他中国模型提供商通过真实或契约测试。
3. OpenAI、Anthropic、Gemini 三类协议响应均归一化为统一模型事件。
4. 不支持工具调用的模型不会被用于 Agent 工具任务。
5. 故障转移不会跨越未经授权的提供商。
6. MCP `stdio` 和 HTTP 测试服务均可发现并调用工具。
7. 禁用的 MCP 工具不会进入模型上下文，也无法从 IPC 绕过执行。
8. 三类风险权限和三级主动性均有自动化测试。
9. API Key、完整文件内容和敏感路径不会写入日志。
10. 角色状态能跟随 Agent 生命周期变化，但角色动画失败不会改变工具结果。
