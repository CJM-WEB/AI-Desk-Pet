# AI Pet 基于 OpenCode 的文件操作与任务执行重构

日期：2026-09-05。状态：**用户已要求首轮实现 DeepSeek 与内置免费 Qwen；采用任务范围授权，接入验证进行中**。

本稿明确文件任务子系统的复用范围：以 OpenCode 的成熟工具与执行链为主要来源，接入 AI Pet 现有内置模型和 Provider，适配本产品的边界与安全策略。AI Pet 调查基线为 `d7abbef`；OpenCode 固定为 `2a6be0a03b93a6734070e10a6c3b56863475f214`。

## 1. 已确认方向

用户要求**主要复用 OpenCode 的整套文件操作与任务执行能力，继续使用 AI Pet 现有内置模型和已有 Provider 模型**。编程助手范围包括自主规划、读取、修改、构建、测试和修正；普通聊天与文件任务不能混淆。

复用边界为：

1. 文件工具、任务循环、工具结果回注、任务上下文、错误恢复、取消与权限机制，以成熟上游实现为主要来源；保留必要依赖和来源记录，不重新发明另一套执行框架。
2. 模型来源、模型选择、Provider 配置和凭据管理继续属于 AI Pet。无需选择 OpenCode 示例中的模型、注册其账户或改用其他模型。
3. 桌宠聊天、角色人设、心情、状态动画、工作台及其他产品功能继续使用自己的体系；仅修改与新任务核心对接所需的接口。
4. 原文件任务实现及安全实现可以大幅替换。保留现有模型不等于冻结当前 Provider 的单工具协议、消息格式或上下文处理代码。
5. 权限与安全机制参考并复用 OpenCode，具体默认策略适配 Windows 桌宠；既不自动继承上游全部默认值，也不预先锁定全部旧规则。

此前“默认保留旧执行框架”和“优先整体内置 OpenCode 后端及其模型体系”两项推荐均不再适用。模块嵌入、源码移植或独立进程是实现方式，须服从上述产品边界。目标是文件工具与执行闭环达到相近完整度；不同模型的复杂规划成功率分别验收，不承诺所有模型表现相同。

### 1.1 首轮实施范围与授权决定

用户随后明确首轮先实现 **DeepSeek Provider 与内置免费 Qwen**。其他 Provider 的模型设置与普通聊天保留，其他 Provider 的新任务能力不记为本轮真实验收通过。角色自主状态不在本轮实现范围。

实施期间用户补充授权：每个已完成并验证的小任务可进行 Git 提交，暂不 push。早期阶段的只读 Git 记录仍按当时事实保留；未完成的工作不混入已验收阶段提交。

用户选择的授权体验是：**按任务授权明确范围，范围内连续执行；超出范围或高风险操作再确认。** 任务授权绑定当前任务、真实授权目录、模型配置与会话 generation；取消、任务结束或上述边界变化后失效，不转换成全局永久许可。范围内常规读写和明确批准的构建、测试命令可以连续执行。外部目录、删除、目标覆盖冲突以及未纳入授权的命令另行请求批准；普通聊天及角色自主事件不能创建或续用该授权。命令会执行项目代码，这种授权与路径检查不构成 OS 沙箱。

首轮先验证有限 OpenCode Core 原代码组装：保留原 runner、原消息／工具结果、原文件工具与原权限服务；模型接口直接接入现有配置。不得经过旧单工具 `ModelResponse` 再驱动原 runner。只加载文件与任务所需工具，禁用默认插件、外部配置发现和无关模型管理。Windows 命令、取消与真实结果回传是正式替换门禁；未通过时继续定位具体适配问题，不能以增加旧循环轮数代替重构。

**调查基线尚未复现并定位用户反馈的故障，不能据旧测试宣称读取能力可靠。** 现有测试通过不推翻用户反馈；读取失败本身也不能证明具体是哪一层导致。以下表格描述改动前证据；实施期间发现的问题、修复与真实模型结果统一记录在[本轮验收记录](../../operations/2026-09-05-deepseek-qwen-coding-tasks.md)。

## 3. 重构范围

采用上游为主的完整链路，范围包括：

- 现有内置模型与 Provider 到执行核心的配置映射、请求与响应转换、流式消息及多工具调用；不替换用户的模型来源与设置体系。
- 原生会话历史、调用／结果关联、连续执行、上下文管理、失败反馈、用户补充和取消。
- 文件读取、目录与内容搜索、写入、编辑、补丁，以及命令运行和构建／测试闭环。
- OpenCode 的权限匹配、询问、批准、拒绝和作用域机制。
- 工具结果、权限等待、任务完成／失败的桌面呈现。
- Windows 运行、生命周期、打包、数据目录与必要的桌宠事件接入。

复制、重命名等能力先核查上游工具和命令链能否完成，再决定是否需要专用工具。**不再为了保持当前工具清单而优先新增一批自研文件工具。**

本次不将角色自主行为接入有工具的编程会话；官网、资源投稿和角色素材制作不随文件后端一起重写。MCP、任意外部插件、部署发布和额外 Agent 不是本轮验收必需能力，不因默认服务装配而自动纳入。

## 4. 核心复用方式与模型适配

| 方式 | 复用程度与职责 | 当前定位 |

### 4.1 已证实的接入条件

- [官方 CLI 的运行入口](D:/AgentLearning/packages/opencode/src/cli/cmd/run.ts)本身通过 SDK 提交任务、消费事件和回复许可，提供了通过原生接口对接执行链的样例。SDK 的 `/v2` 导出名称不能直接等同较新的 Core V2；应以请求路由与处理器为准。
- [sdk-next](D:/AgentLearning/packages/sdk-next/README.md)提供进程内入口，调用原 Server 组装；不是只有复制算法一种复用方式。
- [原 runner 组装测试](D:/AgentLearning/packages/core/test/session-runner-recorded.test.ts)替换模型、传输、配置、上下文及快照后，仍使用原 runner、协调器、事件、数据库与工具注册表。

- [数据库](D:/AgentLearning/packages/core/src/database/database.ts)支持指定路径与内存 SQLite；无需为运行期上下文重新设计一套执行记录框架。
- [Core 包](D:/AgentLearning/packages/core/package.json)有 Node 条件导入，同时是 private 的源码 workspace 包，不能声称 npm 即装即用，也不能声称它只能运行在 Bun 中。

### 4.2 必须实测或明确配置的差异

该版本同时存在 V1 产品链和较新的 V2 Core。V2 部分公开入口尚未实现，工具及集成也不完全等同 V1；不能把“来自 OpenCode”当成二者能力相同的证明。

默认启动还可能读取项目配置、AGENTS 指令、加载插件、创建数据目录、保存工具输出或快照。[Global](D:/AgentLearning/packages/core/src/global.ts)存在导入阶段目录创建，[外部插件加载器](D:/AgentLearning/packages/core/src/config/plugin/external.ts)可能扫描并安装／执行插件。工具权限配置不自动覆盖所有这些启动行为。

这些是需要选择和适配的具体事项，不是继续自研循环的理由。接入评估应记录必要改动清单、实际包体和行为；不预先虚构成本或复用百分比。

生产 V1 的服务与 SDK 是完整运行链的参考样例；Core 的组装接口是可嵌入性的证据。在本稿最初的只读调查时，二者均未在 AI Pet 中跑通。后续接入进展按第 1.1 节范围实施，运行证据单独记录；不能据此宣称只需更换接口就已具备完整能力，也不能把整套服务及其默认行为作为产品要求。

### 4.3 保留现有模型，适配任务协议

现有代码已包含内置模型链路：[LocalModelProvider](../../../apps/desktop/src/main/providers/local-model-provider.ts)通过 `OpenAICompatibleProvider` 调用应用管理的本地连接；[发行身份](../../../apps/desktop/src/main/local-model/local-model-release-identity.mjs)声明内置模型为 Qwen3.5-4B 的量化版本。发行声明不等于已验证用户当前运行实例。[ProviderRegistry](../../../apps/desktop/src/main/providers/provider-registry.ts)继续承接已有 Provider 配置和凭据。

上游 [模型解析接口](D:/AgentLearning/packages/core/src/session/runner/model.ts)允许注入模型解析器，[LLM 协议层](D:/AgentLearning/packages/llm/README.md)提供统一消息、工具调用和结果事件。因此可以将自己的模型接入上游执行链；不需要绑定某个模型名称。具体采用上游协议适配器还是桥接已有适配器，由完整工具往返测试决定，避免同一请求经过两套互相裁剪的协议层。

需要处理的接口差异包括：

- 当前 [ModelMessage／ModelResponse](../../../packages/agent-core/src/types.ts)围绕单个工具请求设计。新核心保留完整调用标识和调用／结果关联；支持批量调用的模型不得被旧接口压成一个调用，不支持并行调用的模型可以串行执行同一工具集。
- 现有本地适配包含输入预算和读取结果裁剪。应按当前模型的真实上下文限制接入上游的分段读取、输出截断和压缩机制，明确保留后续读取方式，避免裁掉本轮关键结果或断开工具消息关系。这是适配事项，尚不是用户读取故障的已证实根因。
- 工具协议、流式结束、取消、超时及 Provider 特有的必要元数据必须完整传递；聊天和角色表现的结构化输出不能覆盖任务工具协议。
- 内置模型与各已有 Provider 使用同一执行核心和工具集合，允许按协议与上下文能力配置调用方式。不得用静默切换模型或云端回退掩盖本地模型链路失败。

完整工具体系解决宿主能够做什么、执行是否可靠以及结果是否回传；模型能力还影响如何规划和修正。读取不返回内容时先定位任务入口、工具请求、实际执行、结果回注和界面终态，不能未经诊断统一归因于模型规模。

## 5. 产品与执行核心的职责

推荐外部关系为：

```text
桌宠的聊天／任务入口
        ↓
任务接入与界面事件适配
        ↓
复用 OpenCode 的任务循环、工具、上下文与权限机制
        ↔ 模型适配接口 ↔ AI Pet 现有内置模型／已有 Provider
        ↓
真实文件与命令结果
        ↓
任务界面，以及最小桌宠感知事件
```

任务接入适配只处理产品差异：已有模型配置与会话身份、输入归属、权限请求的展示与回复、事件投影、取消及执行核心生命周期。模型设置和凭据仍由应用管理。**不再在原 runner 外套当前 AgentLoop，也不额外构建另一个规划器、语义完成裁判或并行执行记录系统。**

权限由一个统一的执行模块按 AI Pet 策略裁决，优先复用上游规则机制；不能让旧 PermissionPolicy 和上游权限各自作一次互相冲突的判断。Main 管理应用输入、模型选择与执行生命周期；文件和命令的可信执行职责根据最终封装方式分配，不预设必须保留旧 FileToolService。

Renderer 继续通过应用接口呈现内容和提交操作，不直接持有模型密钥或任意进程能力。普通聊天与角色自主表现没有编程会话权限；这是用户要求的产品分工，不是保留旧文件安全框架的理由。

## 6. 先做端到端接入验证，再决定正式替换

本阶段交付首先是一条能验证的完整路径，不是批量迁移或大面积改写代码。

### 6.1 使用现有模型验收

必测对象为 AI Pet 当前内置模型，以及已有且具备可用配置的 Provider 模型；分别记录具体模型、协议、上下文限制和结果。尚无可运行配置的项目标为待验证。最终产品必须在自己的正式入口、现有模型配置下通过验收，不能以改用 OpenCode 示例模型作为通过条件。

必要时，在相同模型、测试文件和自然请求下对照旧链路、原生 OpenCode 与接入链路，以定位宿主差异。这只是诊断手段，不要求用户选用与 OpenCode 相同的模型；无法对齐的参数明确记录。不得悄悄换更强模型证明接入成功。

读取测试使用允许读取的非敏感文本，包含本次随机生成、模型事先不知道的内容。保留自然表达，不补“立即调用 read 工具”之类内部指令；不以换一种恰好命中正则的说法替代失败场景。

用户已补充的“持续说正在读取却无内容”记为明确失败类型。准确原句、文件类型、Provider 和当时会话条件仍需在复现时记录；缺失时只能称代表性场景，不能称已复现原故障。

### 6.2 第一条必须贯通的路径

`正式聊天入口 → 任务进入 → 真实模型 → 实际读取正确文件 → 工具结果回注 → 最终内容展示`。

通过必须同时满足：

1. 读取的是用户要求的正确文件，操作结果有后端真实证据。
2. 对应调用的结果实际送回模型，不能丢失或只留在内部日志。
3. 小文本“显示内容”请求最终显示正确内容；内容问答能回答文件中的指定信息。
4. 界面结束运行态，不残留无对应实际请求的“正在读取”。
5. 发生权限拒绝、超时或失败时，给出准确终态；不能无限等待或用模型口头成功收口。

读取失败时按边界记录任务是否进入、Provider 是否返回调用、实际工具结果、结果回注和界面终态。诊断记录只留定位所需的脱敏信息，不默认抓取用户全部文件或密钥。

### 6.3 随后验证编程闭环

在同一个上游会话内验证“搜索 → 读取 → 修改 → 运行测试 → 分析失败 → 修正 → 再测试”。同时检查用户补充、权限等待与回复、取消，以及恢复后没有重复执行已完成的操作。

先以桌面测试入口贯通小场景，再扩到多文件项目。测试夹具用于可重复地检查协议、拒绝和取消；真实模型用于证明自然输入能完成任务，二者分开报告。

### 6.4 路线选择依据

比较现有模型端到端通过情况、原链路保留程度、必要上游差异、权限一致性、Windows 打包、启动与退出清理。不得只比代码行数，也不得因为当前单元测试更多就优先保留当前实现。

候选接入方式验证失败时先记录具体障碍和最小适配实验；不能直接转回旧自研框架，也不能扩大到替换整个产品和模型体系。若本轮无法完成实验，状态是未验证，正式方案仍不能宣称定稿。

## 7. 完成与真实结果

尽量消费上游原生消息、工具结果、权限事件和会话状态。桌宠适配层只作必要的事实展示校验：

- 文本中的“正在读”不能创建一个没有活动请求的永久运行态。
- 没有实际读取结果时，不显示“读取成功”；模型声称完成不能替代工具证据。
- 已经发生的写入和失败检查分别显示，后续模型总结失败不抹掉实际修改。
- 上游会话完成、命令退出与用户目标是否满足分开呈现；自然语言需求仍可能需要用户检查。
- 修复后重新运行的测试使用新结果，不用此前失败或修改前的检查宣称通过。

撤回上一稿预先规定的 16 次响应、32 次工具、8 MiB 自研执行记录、64 KiB 字符投影和自制文件版本清单方案。运行限额、压缩和存储优先采用所选上游现有机制；具体产品限额根据接入测量再定，不换个数字继续限制原循环。

## 8. 边界、安全与默认规则重新设计

### 8.1 权限机制的基线

以所选版本 OpenCode 的权限规则、资源匹配和 `allow / ask / deny` 为机制基线，适配 AI Pet 的授权入口、Windows 路径、会话作用域和取消要求。旧“每次写入与命令都确认”“只接受授权根标识＋相对路径”“一律走现有 PathPolicy”等规则可以重设计；上游 `* = allow` 等默认值也不会因复用机制而自动启用。

已核查的 V1 [默认 Agent 配置](D:/AgentLearning/packages/opencode/src/agent/agent.ts)以 `* = allow` 为基础，普通读取允许，部分环境文件和外目录默认询问；有特定内部目录例外。这里的 `ask` 是规则判定结果，不是每次调用必弹窗。用户配置、Agent 配置和已批准规则会影响最终行为。

[权限实现](D:/AgentLearning/packages/opencode/src/permission/index.ts)包含一次批准、持续规则批准和拒绝。V1 与 V2 的批准保存范围不同，规格必须以最终选定的链路为准，不能混写为一套保证。

### 8.2 需要随正式方案审定的默认行为

以下是重构会涉及的真实产品变化；本稿列出事实和推荐方向，不把概括性的“包括安全”当作这些设置已逐项启用：

| 项目 | 上游事实／差异 | 本轮推荐方向 |
| --- | --- | --- |
| 工作项目内操作 | V1 build 的基础规则允许工具执行，不强制每写一次就询问 | 通过明确任务授权支持范围内连续执行；不默认全局放行，也不预设每次操作弹窗 |
| 项目外路径 | 上游存在绝对路径、外目录请求和例外规则 | 复用资源与权限模型，明确 Windows 路径解析、外部范围批准及保存作用域，不照搬内部目录例外 |
| 编辑与覆盖 | 上游 write 可覆盖；V1 edit 有多种纠正匹配，V2 更偏精确匹配 | 复用编辑能力并验收冲突和歧义处理；覆盖目标与已有改动的保护策略单独确定 |
| 删除与恢复 | 上游文件删除并非统一进入 Windows 回收站；快照也不是通用文件撤销 | 根据桌宠与 Windows 使用方式确定删除及恢复策略；不因复用源码自动放开永久或批量删除 |
| 命令执行 | 命令权限不等于 OS 沙箱；上游可有项目外副作用 | 使用所选上游进程与权限链，明确命令权限，不叠加第二套未验证的 Shell 解析器 |
| 会话、输出与快照 | 上游可以保存原生会话与工具输出；内存数据库并不能自动关闭全部落盘 | 按本产品会话与隐私要求选择原存储配置，明确保存范围、目录和清理；不新造执行记录系统 |
| 配置、指令与插件 | 部分默认加载发生在工具权限询问之外 | 明确启用集合；文件任务所需配置／指令与任意插件执行分别列出，不无意加载额外能力 |
| 后端连接与生命周期 | 独立服务需要连接与认证，嵌入式则需要作用域销毁 | 使用应用管理的私有连接与数据配置，验证退出、断线和待批准请求清理 |

只有最终选择独立服务时，才需要私有服务连接方案：固定本机回环地址、设置启动认证凭据、不向 Renderer 暴露凭据，且不因继承配置或 mDNS 改为对外监听。上游 [Basic Auth 配置](D:/AgentLearning/packages/opencode/src/server/auth.ts)未设密码时默认无认证，SDK 组合启动器也不会自动补认证请求头，必须实际验证；这些服务细节不构成必须引入完整后端的理由。

第一轮接入实验使用隔离测试目录及测试数据，避免尚未审定的默认覆盖／删除行为作用于用户真实项目。确认产品默认规则后再扩大验收范围。

### 8.3 保留的是产品责任，不是旧类名

聊天与任务不串线，凭据不进入普通公开日志，用户能理解正在授权什么，取消与失败如实呈现，仍然需要有证据。实现这些责任可以使用上游机制，也可以在必要接缝处适配；不能借此恢复一整套旧执行器或权限框架。

## 9. 与桌宠感知的共享事实

本节继续作为[角色自主表现规格](2026-09-05-ai-pet-custom-state-autonomy-design.md)引用的任务事实来源。

由所选执行后端提供真实会话、工具和权限事件，应用投影为最小情境事实：应答开始／结束、任务运行／等待／暂停／结束，以及已经发生的本地操作结果。

普通聊天的应答结束不能产生文件成功事实。任务结果区分完成、部分执行、失败、取消与未验证；动画、心情或模型口头总结不能修改本地结果。

角色感知不需要文件正文、完整路径、命令输出或权限凭据。它消费事件摘要，不进入上游有工具的编程会话；自主表现仍不主动发消息。

## 10. 替换范围与代码规范

以下现有模块均可替换，不再默认保留：

- `AgentLoop` 及其四轮上限、单工具响应与单操作完成票据。
- 以固定句式和工具名主导执行的 Router、任务摘要及事务续接实现。
- 与上游消息协议不兼容的 Provider 内部工具适配和消息契约；保留用户已有模型、Provider 配置、凭据来源与模型选择。
- 文件工具的读取、搜索、编辑、补丁及结果处理主体。
- 当前权限、确认、路径和 Shell 控制实现中被上游取代的部分。

保留桌宠 UI、现有内置模型运行与分发、Provider 设置、人设与角色系统及无关功能；任务入口、模型协议和事件适配按需要修改。新链路通过真实端到端验收后，删除已替代的旧入口、旧协议与只服务旧行为的测试，产品只运行一条正式任务链。对照实验不作为永久双框架架构。

代码复用记录固定仓库、提交、文件、MIT 许可证和本地差异。优先保留上游原代码组织与测试，让必要改动集中在少量清晰接缝；不把所有上游代码改写成当前类结构来追求表面统一。产品新增文档和结构性注释使用中文，第三方许可证及来源声明完整保留。

## 12. 进入实施与交付证据

接入验证已拆入[首轮实施计划](../plans/2026-09-05-deepseek-qwen-coding-tasks.md)，其中明确上游入口、测试环境、复现请求与可判定结果。实施顺序为原核心读取、文件工具与 Windows 命令、现有模型与正式入口、真实验收和旧路径退役；未经对应验证的步骤不能标成完成。

实际实现采用规格与测试驱动，优先复用上游测试，并补产品接入链的回归。最低证据包括：

1. 原始读取故障能复现并通过修复后的同一场景；尚无完整原始条件时单列未验证。
2. 内置模型与已有 Provider 分别验证自然表达读取：小文件正文正确出现在正式界面，而非只有“正在读取”或成功标识。
3. 单任务完成改测修正闭环、权限等待／回复、取消与失败收口；按实际模型分别报告表现，不用更强模型的结果替代。
4. 聊天与角色自主表现没有继承编程任务权限。
5. Windows 启动、打包、退出和清理有实际验证；上游测试通过不代替桌面集成。
6. 原生 OpenCode 与接入版本的差异有记录，必要安全与生命周期测试通过，旧正式链完成清理。

第 2 节与第 4 节的调查结论保留其原始证据范围。后续实现与运行结果记录在[首轮验收记录](../../operations/2026-09-05-deepseek-qwen-coding-tasks.md)，不得把原先“仅只读调查”的状态或实施计划当作当前验收结果。用户具体读取故障仍缺少完整原始条件，代表性读取场景通过也不等于已复现并定位原故障。
