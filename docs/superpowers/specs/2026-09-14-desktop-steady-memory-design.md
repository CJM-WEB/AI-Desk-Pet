# 桌宠日常使用内存优化规格

日期：2026-09-14。用户已要求继续优化：API 模式日常使用后空闲总占用尽可能降低，全部现有功能和效果不变。用户最新明确“也不用严格低于500MB，尽可能就行”，500 MB 仅作参考，不作为硬性验收阈值。用户也取消本轮内置模型优化，内置 Qwen 的实现、配置与测量均不在本轮范围。

## 现状和范围

- 前轮[启动优化](2026-09-14-desktop-runtime-memory-design.md)只减少首次使用前的窗口和视图代码常驻；其隔离软件栅格化数据不能代表真实开发版及打开过工作室的状态。
- 用户截图为重启后打开过设置或工作室，任务管理器显示 Electron 进程组 694.2 MB。调查时没有存活的用户 Electron 进程，不能凭截图给各匿名子进程指定角色。
- 本轮采用临时用户目录、真实开发版与实际硬件 GPU 配置，分别测冷启动、设置打开、工作室打开及两者原生隐藏后。Electron 与 Vite/Node 分开统计，不读取真实配置、密钥或聊天内容。
- 500 MB 是 API 模式的日常空闲参考；不为压到某个数字牺牲功能或效果，不据此推算内置模型开启后的内存，不修改或测量本地模型策略。

## 优化边界

1. 保持模型身份、上下文能力、输出流、会话、权限、文件执行、角色状态决策、素材、像素、帧率、窗口交互和编辑状态。不能通过降低质量或删除功能达到目标。
2. 优先释放已经不再使用的临时资源；其次检查可重建渲染缓存与重复加载。对未保存字段、编辑选择、预览当前帧、播放进度、导入/编译和隐藏后重开效果必须给出保留证据。
3. 不使用强制 GC、工作集裁剪或把内存迁往显存后不报告总变化。模型休眠、上下文缩减和缓存精度变化不作为默认实现；涉及响应延迟或能力权衡时单独说明并确认。
4. 本轮仅扩展资源生命周期范围，不替代角色、本地模型或授权业务规格。无 Git 写操作、无新依赖，不修改网站内容链。

## 已确认的最小资源清理方案

`pixi-character-player.ts#extractAlphaMask` 创建临时 2D Canvas，复制 Alpha 后不再使用其 RGBA 画布。通过 `finally` 将该临时画布宽高清零，在成功、无 context 和读取异常三条路径都明确释放 backing store；保留原图片、纹理和逐像素 Alpha 数值，不触碰正式显示画布。复用已有 Pixi 测试中的实际 Alpha 提取链路，先验证临时画布未释放的 RED，再验证清理及原命中结果不变。实际收益以真实开发版前后对照为准，不按图集理论容量直接宣称降幅。

### 草稿预览不生成未使用的 Alpha 掩码

- 现状：`DraftCharacterPreview` 仅消费共享场景的当前帧、布局和播放接口，从不消费 `getHitSnapshot()`；但 `loadAssets()` 仍为每张预览素材创建 Alpha 采样画布，并保留每像素一字节的掩码。正式桌宠的透明像素命中依赖该掩码，必须继续保留。
- 最小方案：在现有 `createBrowserPixiCharacterScene(container, loadPixi, options)` 工厂第三参数增加桌面模块内部的可选 `captureAlphaMask`，缺省为 `true`。只由草稿预览显式传入 `false`；`BrowserPixiCharacterScene.loadAssets()` 根据该选项跳过 `extractAlphaMask()`，纹理加载、帧矩形、方向、缩放、播放速度、帧率及清理链路原样复用。
- 此选项不进入 IPC、共享角色 Schema、用户设置或发布数据。它不改变窗口生命周期，不卸载组件、Store 或精灵，不暂停导入、编译、保存或巡播。隐藏回收、原生显隐 IPC 和恢复事务不在本候选范围。
- 默认场景仍采样并提供相同的 Alpha 命中快照；关闭采样的预览仍完成图片解码、纹理创建和正式场景渲染，其 `getHitSnapshot()` 返回空。加载异常与资源销毁沿用原错误和清理行为，不新增降质或替代渲染路径。
- 验收：用安装版本的真实 Pixi 纹理、精灵和布局，替换图形设备与图片解码边界，证明关闭采样时不请求 2D context、不读取像素，当前帧、画面边界及纹理源尺寸保持；默认场景继续采样并返回原 Alpha 字节。组件测试确认草稿预览显式关闭采样且仍进入就绪、可切换方向和帧。
- 生产代码须在真实开发版基线结束后修改，先观察上述最小失败测试再实现。实际节省以相同开发版、硬件 GPU 和角色的前后样本为准，不把理论像素容量记为实测收益。

### 正式桌宠 Alpha 掩码使用无损游程存储

- 只读测量已对正式默认角色9张图集的64,940,276个Alpha逐字节核验；完整8位逐行等值游程使用统一Uint32结束位置与行索引时，数据区为2,425,530 bytes，较原始64,940,276 bytes少约59.62 MiB。这是存储容量证据，不是进程工作集降幅；203帧左右镜像及多阈值1,624,000次比较一致。
- 仅改变桌面播放器的Alpha存储表示：直接从现有Canvas RGBA扫描生成游程，保留每个原始0–255值；使用统一读取入口，原裁切、方向翻转、缩放、半开边界和任意有限阈值的 `alpha > threshold` 关系保持。PNG、GPU纹理、分辨率、帧率、状态、预览选项和IPC均不变。
- 游程不节省空间时保留原始Uint8表示；两种表示二选一，不额外保留完整RGBA或raw Alpha，不在每次命中时解压整图。行索引支持只二分当前行的游程，内部索引由构造入口建立，异常尺寸、源长度、坐标和快照继续穿透，读点不做全图校验。
- 复用当前Alpha提取函数的Canvas `finally` 释放和草稿预览 `captureAlphaMask:false`。无新依赖，不引入新图像解码器或第二个掩码缓存。角色切换、过期加载和销毁仍只使用现有场景Map及生命周期。
- 验收先执行RED：完整256种Alpha与全部整数阈值、分数及范围外有限阈值；多行游程边界、裁切多帧与左右镜像；不划算时raw回退；异常输入与超界；实际存储字节减少。接入后保留现有真实采样、默认命中、预览跳过、Canvas释放及过期加载测试，整合后测实际GPU/开发版内存。

其他隐藏工作室资源回收先完成测量与独立审计，再将具体方案和验证条件补充到此规格；不可根据内存截图直接改动其生命周期。

## 验收

- 最小清理变更先执行对应 Pixi/Alpha 测试、桌面 typecheck 和构建，再按角色影响范围执行定向行为与交互回归。
- 内存基线在实现前取样；前后使用同一角色、GPU、启动模式和操作顺序，报告多个样本，不以首次峰值与后续低值作不等条件比较。
- Windows 可见性以自有窗口原生句柄事实为准，不单独依赖 CDP 下的 document.visibilityState。
- 本轮不执行本地模型优化及其专门测量。
- 保留前轮全量门禁已有失败的记录；不得把本轮定向通过写成所有功能已人工验收。
