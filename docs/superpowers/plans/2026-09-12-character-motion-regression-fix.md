# 三档运动与表现连续性回归修复

日期：2026-09-12。状态：实现与自动化验收完成；真实 Windows 观感待确认。

依据：用户本轮报告 Qwen 状态切换不稳定、三档运动失效及跑步与位移脱节；沿用已批准的[持续状态设计](../specs/2026-09-12-character-behavior-continuity-design.md)和[运动同步设计](../specs/2026-09-08-single-send-expression-isolation-design.md)。本次恢复既有契约，不改变作者素材、播放参数、三档含义或文件授权。

## 现状与范围

- 实际新默认的跑步动作为 `presentation`，约 1.1 秒一轮。真实 Service、Engine、Director、Motion、Scheduler 组合复现：每轮新播放令牌触发 Director 停止位移；持续模式重新选目标，间歇模式提前结束。
- 表现请求中的 `movementControl.mode` 只有数字枚举，未解释 `0=静止、1=持续、2=间歇`。自然说法需要模型判断时缺少必要协议语义。
- Adapter 接纳 `requestKind=movement` 搭配无条件短时或长期背景，允许移动动画脱离真实移动。不得根据状态名称硬编码修正，更不能把无条件动画当成位移授权。
- 三档只控制桌面位移。用户明确要求原地播放某状态或动作仍然有效；持续背景、任务并行与模型失败保护沿用原规格。

## 实施与验收

1. 运行链：在 `apps/desktop/tests/` 增加使用真实新默认及五层对象的集成测试，先证明有限动画每轮错误停止，再在 Director/Service/Engine 的必要边界实现合法续播交接。保留真实目标及首次首帧门槛，失败、条件失效、取消仍停止；不以延长动画或放开所有令牌检查代替修复。
2. 模型协议：在 `character-expression-adapter.test.ts` 先覆盖模式语义及矛盾输出。只在模型声明移动请求时限制冲突候选，保留明确原地播放；在原提示和接纳路径最小修复，不增加模型调用循环或公共协议。
3. 实际验证：用固定九状态目录对真实 Qwen 进行有限的修复前后对照，并记录原始结构化选择与接纳结果的公开字段。增加真实 Electron 三档运动用例，观察窗口位移和动画，覆盖至少两轮跑步、停止及间歇等待。
4. 整合：定向测试、类型检查、桌面/行为门禁和差异检查；已有失败与本次回归分开记录。真实 Windows 手感仍标为待用户确认，不把模型抽样等同于全部自然语言稳定性。

## 安全与清理

验证使用隔离用户数据；真实设置、角色创作原件和凭据只读，模型请求仅含公开目录与合成情境。继续保留 Main 文件能力边界，不改变 Provider 文件任务，不采集用户活动。无新依赖、无 Git 写操作、无批量删除。

运行结果另写验收记录；本计划中的预期通过不构成完成证据。最终结果见[验收记录](../../operations/2026-09-12-character-behavior-continuity-acceptance.md)的“本轮运动与 Qwen 回归收口”一节。
