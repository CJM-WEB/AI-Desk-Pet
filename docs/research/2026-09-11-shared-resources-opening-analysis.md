## 1. 结论

现有网站已经实现匿名投稿、私有直传、人工审核、公开列表和限时下载。当前不能上传首先受投稿开关与 CloudBase Web 安全域名限制；开放前还必须处理审核扫描器与当前 V3 角色包的格式不一致。仅购买套餐或打开开关均不足以完成用户所需的“上传后供其他人下载使用”。

如果要在 `https://cjmwebsite.cn` 内提供持续可用的共享资源服务，建议采用个人版作为最低付费候选，并保留现有人工审核流程。当前控制台的跨域功能升级弹层推荐个人版，单买一个月报价为 19.90 元、包含 40,000 资源点。暂没有需要直接购买 199 元/月标准版的用量证据。

正式环境的选择需在实施规格中确认：当前唯一环境仍是开发环境。既有规则要求开发与生产隔离，因此默认建议保留开发环境，另建生产环境；若希望直接把当前环境转为正式环境，须明确批准对现有隔离规则的调整，不能把套餐升级自动等同于生产上线。

## 3. 已有证据与新发现

### 3.1 已定位的上传阻断

[2026-09-09 验收记录](../operations/website-login-upload-repair-2026-09-09.md)记录过同一签名目标的对照预检：根域 Origin 返回 403，默认托管域返回 204；签名生成正常，文件对象未创建。为避免不断留下空投稿，开关被恢复为 false。本次控制台的开关、套餐与来源列表仍与该结论一致，但本次没有重新签发地址或上传测试文件，不能把历史网络响应记为今日重测。

浏览器流程在 [cloud-shared-pet-repository.ts](../../apps/website/components/website-experience/community/cloud-shared-pet-repository.ts) 中为 `prepare → 封面 PUT → ZIP PUT → finalize`。根域的同源 API 并不能替代文件目标的跨域来源校验；仅更换 API 地址不能修复实际页面 Origin。

[submission-service.ts](../../apps/cloudbase-api/src/services/submission-service.ts) 在创建记录前检查开关；正式契约限 ZIP 100 MiB、封面 5 MiB。上传后核实对象存在、实际大小和 MIME，再进入 `manual_review_pending`。

### 3.2 当前角色包与扫描器格式不同

- [桌面导出服务](../../apps/desktop/src/main/characters/character-package-service.ts)的 `exportCharacter` 直接打包当前草稿和发布清单；当前存储契约使用 V3。
- [V3 Schema](../../packages/character-runtime/src/character-v3-schema.ts)要求 `version: 3`。
- [扫描器](../../apps/package-scanner/src/scan-package.ts)第 459 行附近仍调用 `characterDraftV1Schema` 与 `characterManifestV1Schema`。
- [V1 Schema](../../packages/character-runtime/src/character-schema.ts)明确要求 `version: 1`，并非兼容多版本的别名。

因此，ZIP 的网络传输本身可以完成，但当前 V2/V3 包会被现有本地审核扫描路径拒绝；这与 CloudBase 套餐无关。以上为源码静态确认，本次未新增失败测试或运行 Docker 扫描。实施时应使用当前工作室导出的合法包建立回归测试，优先按版本调用 `character-runtime` 的既有严格 Schema，继续复用 `character-assets` 的资源完整性校验并保持原 ZIP 字节，禁止仅修改版本号或关闭结构检查。旧包迁移及有歧义内容的处理仍由桌面端承担，不能把可解析直接解释为可启用。

另有[两侧容量限制](../../packages/character-assets/src/package-policy.ts)差异：桌面为 2000 项、解压总量 256 MiB、单资源 32 MiB；网站扫描为 500 项、解压总量 300 MiB、单资源 10 MiB。因此两侧合法包不能直接视为等价。建议规格限定共享包同时满足网站与当前桌面导入预算，保留更严格的共享项数与单资源限制，并收紧会超出桌面能力的解压总量；是否采用此规则须先确认，不能直接放宽校验。

### 3.3 审核与下载已有正式路径

现行 [人工审核规格](../superpowers/specs/2026-09-01-website-stage-2c-zero-cost-manual-review-design.md)已经退役云托管扫描器、TMS、IMS 和自动审核 worker。新共享包通过管理员本地 Docker 辅助检查、人工查看和两步 `force_publish` 发布，公开保留 `admin_override` 风险提示。普通上传者无需登录；管理员认证与匿名投稿分开。

[公开内容服务](../../apps/cloudbase-api/src/services/public-content-service.ts)只对满足发布与结构条件的资源签发 300 秒下载地址。未审核包继续私有；正式安装包与用户共享包继续隔离。

## 4. 可选方向与费用判断

| 方向 | 适用情况 | 判断 |
| --- | --- | --- |
| 个人版＋官网原域上传 | 正式面向其他用户共享下载 | 推荐；先确定生产环境，再配置域名与验证完整链。新建环境价格以其购买页为准 |
| 免费版＋默认托管域投稿 | 暂时验证流程、坚持不新增费用 | 可研究最小入口跳转；必须让投稿页面本身运行在允许的域名下。默认域仅宜测试，不能承诺长期公开稳定可用 |
| 标准版 | 实测资源点、容量或特定能力超过个人版 | 目前没有直接需要此档位的证据；按真实负载再评估 |

官方现价：个人版 19.9 元/月（限时优惠）、40,000 点/月；标准版 199 元/月、330,000 点/月。套餐点数由数据库、托管、认证、存储和下载等共同消耗，不是无限流量。[官方资源点价格](https://cloud.tencent.com/document/product/876/127357)

下载流量按假设举例：平均每包 20 MB，1000 次完整下载约 20 GB；仅按上海云存储 CDN 下行 210 点/GB 计算，约消耗 4200 点。回源、存储、数据库和官网流量另计，签名下载的实际账单分类需在验收后观察。该数字不是当前业务预测或月账单承诺。

更完整的计费来源、计算假设和套餐边界见 [CloudBase 成本调研](2026-09-11-cloudbase-shared-resources-cost.md)。HTTP 自定义域名额度与 Web 安全来源是不同配置，不能用价格表中的域名数量直接推导 CORS 配额。

## 5. 建议实施顺序

1. **形成并确认规格**：确定面向公众还是临时试用、生产环境安排、月度预算及仍沿用人工审核。明确替代旧“零额外费用、投稿暂停”的哪些运行约束；先不改变桌面业务。
2. **TDD 修复包格式兼容**：以当前导出 ZIP 为最小失败样本，验证新版与旧版受支持包、草稿与清单版本一致及共同容量预算；保留非法 JSON、越界路径、资源摘要错误和恶意包的拒绝行为。复用现有解析与资源校验，避免另造打包系统。
3. **准备云端运行面**：按批准的生产或试用安排复用已有数据库迁移、API、cleanup、私有 Bucket 和管理员认证；付费方案核对实际金额后再购买，配置精确的官网安全来源，保留限流。API 响应日志不得重新泄露状态令牌或签名地址。
4. **受控验证上传与审核**：在受控验收窗口开启投稿，验证实际官网浏览器的 prepare、两次 PUT、finalize、状态查询、待审私有性及管理员审核；失败恢复暂停。
5. **验证下载可用后开放**：另一个匿名浏览器下载同一已审核包，核对 SHA-256，再导入当前桌宠并启用。仅下载 HTTP 200 不足以证明桌宠包可用；完整链及第 6 步运维准备均通过后再宣布可供用户使用。
6. **完善提示与运维**：最小修改区分“投稿暂停”和“传输失败”；保留人工风险标记，确认清理、用量告警、备份、下架与回滚方式。
